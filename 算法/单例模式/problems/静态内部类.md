# 静态内部类（Holder / Bill Pugh）

## 核心思想
利用 JVM {{c1::类加载时机}}和{{c2::类加载的线程安全性}}：静态内部类 SingletonHolder 只在第一次被引用（`getInstance()`）时才加载，天然延迟初始化 + 线程安全。

## 标准实现（推荐，最简单）
```java
public class Singleton {
    private Singleton() {}

    // 静态内部类：只有在 getInstance() 被调用时才加载
    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE; // 触发 SingletonHolder 类加载
    }
}
```

## 工作原理
1. `Singleton` 类加载时 {{c1::SingletonHolder 不会被加载}}（内部类独立加载）
2. 首次调用 `getInstance()` → 访问 `SingletonHolder.INSTANCE` → {{c2::触发 SingletonHolder 类加载}}
3. JVM 保证类加载过程 {{c3::线程安全}}，INSTANCE 只创建一次
4. static final 保证 {{c4::发布安全}}——INSTANCE 对所有线程可见

## 与饿汉式对比
| | 饿汉式 | 静态内部类 |
|------|------|------|
| 加载时机 | 外部类加载时 | 首次getInstance() |
| 延迟加载 | ❌ | ✅ |
| 线程安全 | ✅ | ✅ |
| 代码量 | 少 | 略多 |

## 优缺点
- 优点：{{c1::延迟加载 + 线程安全 + 无锁 + 代码简洁}}
- 缺点：{{c2::无法传入参数（类加载时自动初始化）}}

## 适用场景
{{c1::不需要传参的单例首选方案}}。比 DCL 更简洁，比饿汉式更节省内存。
