# 破坏单例的方式与防护

## 反射破坏
```java
// 通过反射强行调用私有构造器
Constructor<Singleton> c = Singleton.class.getDeclaredConstructor();
c.setAccessible(true);
Singleton instance2 = c.newInstance(); // 破坏了单例！
```

### 防护方式
```java
public class Singleton {
    private static boolean created = false;

    private Singleton() {
        synchronized (Singleton.class) {
            if (created) {
                throw new RuntimeException("单例已创建，禁止反射破坏");
            }
            created = true;
        }
    }

    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

注意：{{c1::created 变量也可能被反射修改}}，只能增加破解成本，无法完全防御。完全防反射应使用 {{c2::枚举单例}}。

## 序列化破坏
```java
// 序列化后再反序列化 → 产生新对象！
ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("singleton"));
oos.writeObject(Singleton.getInstance());

ObjectInputStream ois = new ObjectInputStream(new FileInputStream("singleton"));
Singleton instance2 = (Singleton) ois.readObject(); // 不同实例！
```

### 防护方式：readResolve()
```java
public class Singleton implements Serializable {
    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {}

    public static Singleton getInstance() { return INSTANCE; }

    // JVM 在反序列化时自动调用此方法，返回的对象替换反序列化出的对象
    private Object readResolve() {
        return INSTANCE;
    }
}
```

工作原理：{{c3::ObjectInputStream 在 readObject() 完成后，通过反射检查类是否有 readResolve()，若有则用其返回值替换反序列化出的对象}}。

## 各实现防破坏能力
| 实现 | 防反射 | 防序列化 |
|------|:--:|:--:|
| 饿汉式 | ❌ 需加标志位 | ❌ 需加 readResolve |
| DCL | ❌ 同上 | ❌ 同上 |
| 静态内部类 | ❌ 同上 | ❌ 同上 |
| 枚举 | ✅ JVM 内部保护 | ✅ 默认已保护 |

## 总结
- 日常开发 → {{c1::静态内部类（除非要防反射/序列化破坏）}}
- 需要防破坏 → {{c2::枚举（最安全）}}
- 需要传参 → {{c3::DCL + 防反射标志位 + readResolve}}
