# 双重检查锁定（DCL — Double-Checked Locking）

## 核心思想
{{c1::两次检查}} + {{c2::synchronized 只锁创建代码块}} + {{c3::volatile 防止指令重排}}

## 标准实现（必须会写）
```java
public class Singleton {
    // volatile 防止指令重排！
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {                    // ① 第一次检查（无锁，快）
            synchronized (Singleton.class) {        // ② 加锁
                if (instance == null) {             // ③ 第二次检查（锁内，确认）
                    instance = new Singleton();     // ④ 创建实例
                }
            }
        }
        return instance;
    }
}
```

## volatile 为什么必须
`instance = new Singleton()` 不是原子操作，分三步：
1. {{c1::分配内存空间}}
2. {{c2::初始化对象}}
3. {{c3::instance 指向内存地址}}

JVM 可能将 2 和 3 重排 → instance 非 null 但对象未初始化 → 其他线程拿到半成品对象。{{c4::volatile 禁止指令重排}}。

## 为什么两次检查
- 第一次 if（锁外）：{{c1::性能优化——实例已存在时直接返回，不用加锁}}
- 第二次 if（锁内）：{{c2::防止多个线程同时通过第一次检查后重复创建}}

## 优缺点
- 优点：{{c1::延迟加载 + 线程安全 + 高性能（创建后无锁）}}
- 缺点：{{c2::代码复杂、依赖 volatile（JDK 1.5+ 才修复）}}

## 适用场景
{{c1::最常用的单例实现之一}}，面试高频。JDK 1.5+ 可用。
