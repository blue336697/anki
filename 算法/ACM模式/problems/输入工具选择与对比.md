# 输入工具选择与对比

## 三种工具的适用场景
ACM 模式下 Java 读入有三种主流方案：

| 方案 | 性能 | 易用性 | 适用场景 |
|------|------|--------|----------|
| Scanner | 最慢（~200ms/10^5行） | 最简单 | 数据量小(&lt;10^4)、小练习、快速验证 |
| BufferedReader + split | 快（~50ms/10^5行） | 适中 | 绝大多数题目，中大数据量 |
| BufferedReader + StringTokenizer | 更快（~30ms/10^5行） | 稍复杂 | 大量整数/单词输入 |
| FastReader（手写） | 最快（~20ms/10^5行） | 需自定义 | 极端性能要求、输入量 &gt;10^6 |

选择原则：{{c1::数据量小用 Scanner，中大数据用 BufferedReader + split，极限性能用手写 FastReader}}

## 选择决策树
- 只是练习/验证算法思路 → {{c1::Scanner}}
- 正式比赛/数据量 10^4~10^5 → {{c2::BufferedReader + String.split}}
- 数据量 &gt; 10^5 且为纯数字 → {{c3::BufferedReader + StringTokenizer}}
- OJ 平台输入量极大（&gt;10^6）→ {{c4::手写 FastReader}}

## 为什么 Scanner 慢
1. Scanner 内部有大量正则匹配和类型解析
2. nextInt() 等方法会做完整的数字解析和格式校验
3. 内部缓冲区较小（默认 1024 字符），频繁读取

## 为什么 BufferedReader 快
1. 直接读取字符流，内部缓冲区大（默认 8192 字符）
2. readLine() 一次性读整行，减少 IO 调用
3. 不进行类型解析，交给程序手动处理
