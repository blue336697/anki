# 算法牌组重构基线

> 快照时间：2026-07-24  
> 迁移期事实来源：当前 Anki `算法` 根牌组  
> 迁移完成后的唯一知识源：仓库中的逐题 Markdown

## 为什么必须重构

当前仓库和 Anki 已经形成双轨：

- Anki 有 405 个叶子牌组、2035 条笔记、2052 张卡片；本地只有 333 个 `problems/*.md`。
- Anki 中 90 个算法子牌组在初次批量导入后发生过新增或修改，最近修改时间是 2026-07-23。
- 有些题只存在于 Anki，例如动态规划的“规划兼职工作”；有些 Markdown 在 Anki 删除题目后仍然保留。
- 多个构建脚本仍把卡片正文硬编码在 Python 中，修改 Markdown 并不能完整重建当前牌组。
- 当前 APKG 使用内容生成 note GUID。只改答案也可能被 Anki 当作新笔记，不能直接用重新导入 APKG 代替增量更新。

因此迁移期间必须先读取 Anki，再回写 Markdown；不能直接用旧 Markdown 覆盖 Anki。

## 当前目录为什么不利于复习

1. 分类维度混杂：`力扣简单/困难` 是难度，`矩阵/回文` 是题目表象，`动态规划/双指针` 是解法，`字节变形题` 是来源。
2. 同一模式被拆散：滑动窗口题同时出现在“滑动窗口”“双指针”“字符串”和“字节变形题”。
3. 同名不一定是同一题：例如回溯中的“字符串的排列”要求枚举全部排列，滑动窗口中的同名题实际是“排列子串”。这类题要改成无歧义标题，而不是误合并。
4. 相同能力点重复建组：`搜索旋转排序数组/搜索旋转数组`、`用两个栈实现队列/用栈实现队列` 等需要逐题判定是重复、变体还是不同题号。
5. 非算法内容混入算法复习：单例模式和 Java 并发唤醒 API 不应占用算法新卡配额。
6. 一个题目拆成 8～10 张机械步骤卡并不总是高效。只有动态规划等确实需要状态推导的题型才应保留完整推导链；简单模拟题通常 3～4 张足够。

## 迁移规则

1. 先读取 Anki 叶子牌组及全部字段，记录 note ID、牌组、题目和更新时间。
2. 以“题目实体”合并重复项：同一道题的多种正确解法写入同一个 Markdown 的多个 `题解(...)`。
3. Anki 已删除而 Markdown 仍存在的题，先隔离，再从正式 `problems/` 移除。
4. Anki 中新增或改过的字段先回写 Markdown；回写时清理 Anki 编辑器产生的无意义 `<div>`，但保留语义。
5. 回写后做正确性审查：代码、状态定义、转移、边界和复杂度必须互相对应。
6. 重建 APKG 只用于校验和备份；迁移期不直接导入，避免生成重复笔记或破坏现有调度。
7. 全量对齐完成后，禁止直接在 Anki 修改正文。修改流程固定为：Markdown → 构建校验 → 按既有 note ID 更新 Anki。
