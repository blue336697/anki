# 搜索旋转数组（含重复并返回最小下标）
<!-- anki-deck: 搜索旋转数组 -->

## 题干
给定一个可能包含重复元素的旋转非递减数组 `nums` 和目标值 `target`。如果目标值存在，返回它在当前物理数组中的最小下标；否则返回 `-1`。

注意这不是 LeetCode 81 的标准问题：LeetCode 81 只要求判断目标值是否存在，而本题要求返回所有命中位置中的最小物理下标。

## 复杂度
时间：{{c1::O(n)}} — 最小物理下标可能落在旋转点两侧，且重复值会破坏二分的单调判定
空间：{{c1::O(1)}}

## 关键技巧
为什么这里不强行使用二分：

1. `[2,2,2,3,2]` 中，当 `nums[left] == nums[mid] == nums[right]` 时，无法判断旋转点位于哪一侧
2. 即使二分先找到一个 `target`，相同值还可能跨越旋转点同时出现在数组首尾
3. “继续向左二分”只能寻找当前有序片段内的左边界，不能证明已经得到整个物理数组的最小下标

既然最坏情况本来就是 O(n)，而题目又明确要求最小物理下标，从下标 0 开始扫描是最直接、可证明正确的解法。若面试官只问“是否存在”，再使用 LeetCode 81 的去重二分。

## 题解(线性扫描)
按物理下标从左到右扫描，第一次命中天然就是最小下标。

```java
class Solution {
    public int search(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == target) {
                return i;
            }
        }
        return -1;
    }
}
```

## 追问：如果只要求判断是否存在
当 `nums[left] == nums[mid] == nums[right]` 时，二分无法判断哪一侧有序，只能同时收缩 `left++`、`right--`；否则仍按“先判断哪一半有序，再判断 target 是否落在其中”处理。

该做法平均接近 O(log n)，但在大量重复元素下仍会退化为 O(n)。
