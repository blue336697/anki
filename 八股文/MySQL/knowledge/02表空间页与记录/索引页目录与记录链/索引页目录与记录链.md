# 索引页、页目录与记录链

## 结构定位
Q: InnoDB B+ 树索引页内部由哪些区域组成？
A:
- 通用 FIL header 后是 INDEX page header、`infimum`/`supremum` 伪记录、用户记录、free space、page directory 和 FIL trailer。
- 记录按 key 逻辑有序地组成单向链；物理插入位置可能复用空洞，不保证按地址连续。
- page directory 在页尾保存若干 slot，每个 slot 指向一组记录中的“组内最大记录”，用于页内二分定位。
- 页头保存记录数、heap top、free list、directory slot 数、level、index id 等状态。

## 记录头字段
Q: COMPACT 记录头的 next_record、heap_no、record_type、n_owned 分别做什么？
A:
- `next_record` 是到下一条逻辑记录的相对偏移，串起页内有序链。
- `heap_no` 标识记录在页内 heap 的编号，锁系统用页号加 heap_no 位图表示记录锁。
- `record_type` 区分普通、非叶子节点指针、infimum 和 supremum。
- `n_owned` 只在 directory slot 所指记录上记录本组拥有条数，便于二分后做短链表扫描。

## 页内查找算法
Q: 在一个索引页中如何定位第一个大于等于目标 key 的记录？
A:
1. 先对 page directory slot 二分，比较 slot 对应的组内最大 key，找到可能包含目标的最左组。
2. 从前一组边界记录沿 `next_record` 顺序比较，直到首个 `key >= target`。
3. 若是精确查找再校验完整 key；若超出 supremum，则按 B+ 树游标决定进入相邻页或回到父层。
4. 目录把纯链表 O(n) 缩小为 O(log slots + group_size)，组大小由页目录维护在小范围。

## 修改与整理
Q: 插入或删除记录后 page directory 为什么需要重分组？
A:
- 插入增加某组 `n_owned`，超过上限时把组拆开并新增 slot；删除过少时可能与相邻组合并。
- 删除通常先标记并挂 free list，空间可在页内复用；purge 后才真正移除仍被 MVCC 需要的版本。
- 页内重组会压实碎片，但需要 latch 和 redo；不能把它等同于 B+ 树层面的页合并。
- 顺序扫描走记录链和叶子页链，而不是对每行重新从根二分。

## 验证与误区
Q: “B+ 树页内也是数组二分，记录物理有序”有什么问题？
A:
- 二分的是稀疏 page directory，不是所有变长记录组成的连续数组；组内仍沿记录链扫描。
- 记录物理地址可因删除复用而无序，逻辑顺序由 next_record 与目录定义。
- 页目录、叶子双向页链、父子指针分别解决页内定位、范围遍历和树层导航，不能混为一组指针。
- 可用离线页解析核对 slot、heap_no、record chain；生产不要直接修改页内容。
