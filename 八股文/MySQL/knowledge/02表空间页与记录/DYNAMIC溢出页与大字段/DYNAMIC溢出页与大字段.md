# DYNAMIC 行格式、溢出页与大字段

## 结构定位
Q: DYNAMIC 行格式怎样存储不能留在聚簇页内的长列？
A:
- InnoDB 尽量让聚簇记录满足页内限制；长 VARCHAR、VARBINARY、BLOB、TEXT 的值可移到外部 LOB/overflow 页。
- 聚簇记录保留一个约 20 字节的外部引用，包含 space/page/offset、长度和标志，用于定位外部数据链。
- DYNAMIC 倾向把长值完整放到页外；旧 COMPACT 常保留前 768 字节前缀再加外部引用。
- 二级索引若索引该列前缀，索引 key 仍存于二级页，不能指望 off-page 绕过索引长度限制。

## 页链结构
Q: 大字段跨页后，读取路径和更新代价发生了什么？
A:
- 聚簇索引点查先读取主记录页，再按外部引用读取一个或多个 LOB 页，形成额外随机 I/O。
- Buffer Pool 分别缓存主记录页和外部页；只查未涉及大字段的列可避免读取外部内容。
- 更新大字段可能分配新外部页并记录 undo/redo，旧版本在 read view 与 purge 允许前不能释放。
- 大字段与高更新频率组合会放大 redo、undo、空间碎片、备份量和复制流量。

## 迁移算法
Q: 一条记录何时会把列移到页外，是否超过某个固定字段长度就一定外置？
A:
1. InnoDB 先计算整条聚簇记录是否满足页内最大记录约束。
2. 若过大，按内部策略选择可外置的长变长列，将其替换为外部引用，直到记录可放入页。
3. 因此是否外置取决于整行、页大小、行格式和其他列，而不是单列超过统一阈值。
4. 已外置值的读取和回滚仍通过 B-tree 记录、undo 版本与 LOB 页生命周期协同。

## 版本与边界
Q: `ROW_FORMAT=DYNAMIC` 是否意味着“行内永远不存长列内容且性能更好”？
A:
- 不是。短值仍直接行内存放；只有记录需要或策略选择时才外置。
- 外置提高单页可容纳行数，但读取大字段增加 I/O；是否更好取决于查询投影和数据分布。
- 8.x 默认表通常使用 DYNAMIC，但迁移自旧版本的表应以 `SHOW TABLE STATUS/SHOW CREATE TABLE` 为准。
- COMPRESSED 与页压缩、文件系统压缩是不同机制，CPU、Buffer Pool 和写放大特征不同。

## 工程验证
Q: 线上大字段表应该怎样设计与诊断？
A:
- 高频列表查询不要 `SELECT *`，让主路径只读取小列；大对象可拆到附表或对象存储并单独控制一致性。
- 观察平均/最大 LOB 大小、更新频率、Buffer Pool 命中、redo 速率、history list 和备份窗口。
- 加字段或改行格式可能重建全表，先用 `EXPLAIN ALTER TABLE`/文档矩阵确认算法与空间。
- 归档前同时考虑主表、LOB 页、undo 中旧版本和 binlog，删除业务行不代表空间即时下降。
