# OrderByGroupBy与临时表

## OrderBy卡
Q: MySQL order by 通常如何执行？
A:
- 如果索引顺序满足排序需求，可以直接按索引顺序返回
- 否则可能使用 filesort
- filesort 可能在内存中完成，也可能借助磁盘临时文件
- 全字段排序会把所需字段一起放入 sort buffer
- rowid 排序先排序主键或行定位，再回表取完整字段

## GroupBy卡
Q: group by 和 distinct 为什么可能使用临时表？
A:
- 分组需要把相同 group key 的记录聚合到一起
- 如果没有合适索引顺序，可能需要临时表或排序
- distinct 本质也是去重，类似分组
- 分组基数大、字段宽或内存不足时可能落盘
- 优化思路是利用索引顺序、减少字段、提前过滤和控制中间结果

## 临时表卡
Q: MySQL 内部临时表和用户临时表有什么区别？
A:
- 内部临时表由优化器执行 SQL 时自动创建
- 用户临时表通过 `create temporary table` 显式创建，会话内可见
- 内部临时表可能用于 group by、order by、union、派生表等场景
- 内存临时表放不下会转磁盘临时表
- 临时表会影响内存、磁盘 IO 和执行时延

## 正确性审查卡
Q: 排序、分组和临时表有哪些常见误区？
A:
- “filesort 一定表示磁盘排序”：错误。它是排序算法名，可能在内存完成
- “Using temporary 一定不能接受”：不一定。小数据量可能没问题
- “order by 字段有索引就一定不用排序”：错误。还要看 where、索引顺序和排序方向
- “group by 不需要索引”：数据量大时索引顺序很关键
- “select * 排序无影响”：错误。字段越宽，排序和临时表成本越高
