# B加树与聚簇索引

## B+树卡
Q: InnoDB 为什么使用 B+ 树作为主要索引结构？
A:
- B+ 树是多路平衡树，一个节点对应一个页，树高低，随机 IO 少
- 内部节点只存 key 和页指针，扇出更大
- 叶子节点按 key 有序并通过链表连接，适合范围查询
- 查询、排序、分组都可以利用索引的有序性
- 面试表达：数据库索引设计首先面向页 IO，而不是只看内存算法复杂度

## 聚簇索引卡
Q: InnoDB 聚簇索引和二级索引有什么区别？
A:
- 聚簇索引叶子节点保存完整行数据
- 二级索引叶子节点保存索引列和主键值
- 通过二级索引查到主键后，再查聚簇索引叫回表
- 覆盖索引能避免回表，因为查询字段都在二级索引中
- InnoDB 表数据本身就是按主键组织的一棵 B+ 树

## 主键卡
Q: InnoDB 主键设计为什么重要？
A:
- 主键决定聚簇索引的物理组织顺序
- 主键越短，二级索引叶子节点携带的主键值越小
- 趋势递增主键通常写入局部性好，页分裂少
- 随机 UUID 主键容易导致随机插入、页分裂和缓存局部性差
- 但自增主键也可能形成写热点，要结合写入并发和分库策略看

## 正确性审查卡
Q: B+ 树和聚簇索引有哪些常见误区？
A:
- “索引就是一张额外表”：不准确。InnoDB 主键索引本身就是数据组织方式
- “二级索引叶子保存完整行”：对 InnoDB 通常错误
- “主键只影响唯一性”：错误。还影响聚簇组织和所有二级索引大小
- “UUID 一定适合作主键”：不完整。随机 UUID 对 B+ 树写入不友好
- “索引越多越好”：错误。索引会增加写入、存储和优化器选择成本
