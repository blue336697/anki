# 隔离级别与事务语法

## ACID卡
Q: MySQL 事务的 ACID 分别依赖哪些机制实现？
A:
- 原子性主要依赖 undo log 回滚
- 持久性主要依赖 redo log 和刷盘策略
- 隔离性依赖锁和 MVCC
- 一致性依赖约束、业务逻辑以及原子性/隔离性/持久性的共同保证
- 面试表达：ACID 不是一个开关，而是一组机制协同出来的结果

## 语法卡
Q: MySQL 中事务开启、提交和隐式提交有哪些注意点？
A:
- `START TRANSACTION` 或 `BEGIN` 可显式开启事务
- `COMMIT` 提交，`ROLLBACK` 回滚，`SAVEPOINT` 可设置保存点
- 默认 `autocommit=1` 时，每条语句通常独立提交
- DDL、部分管理语句会触发隐式提交
- 面试边界：事务中混入 DDL 时要特别小心，它不一定按你以为的事务边界执行

## 隔离级别卡
Q: MySQL 支持哪些事务隔离级别？
A:
- Read Uncommitted 可能脏读，基本很少用于生产业务
- Read Committed 避免脏读，每次读生成新 ReadView
- Repeatable Read 是 InnoDB 默认隔离级别，快照读复用 ReadView
- Serializable 最强，通常通过更强锁语义降低并发
- InnoDB RR 下结合 MVCC 和 next-key lock 处理很多幻读场景

## 正确性审查卡
Q: MySQL 事务有哪些常见误区？
A:
- “开启事务后 DDL 也能一起回滚”：通常错误，DDL 可能隐式提交
- “autocommit=1 就没有事务”：错误。单条语句也是事务
- “一致性完全由数据库保证”：不完整。业务不变量也要应用层维护
- “隔离级别越高越应该默认使用”：不一定。要权衡并发和正确性
- “RR 下绝对不会幻读”：要区分快照读、当前读和具体加锁条件
