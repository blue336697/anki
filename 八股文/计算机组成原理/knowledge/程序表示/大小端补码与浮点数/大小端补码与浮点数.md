# 大小端补码与浮点数

## 概念卡
Q: 大端和小端是什么？

A:
- 大端：高位字节存放在低地址，阅读顺序更接近人写数字
- 小端：低位字节存放在低地址，x86 常见为小端
- 端序影响多字节整数在内存/网络/文件中的字节排列
- 网络字节序通常是大端
- 跨语言、跨机器解析二进制协议时必须显式约定端序

## 机制卡
Q: 为什么计算机常用补码表示有符号整数？

A:
- 补码让加减法可以统一用同一套二进制加法电路
- 0 只有一种表示，避免原码/反码的 +0 和 -0 问题
- n 位补码范围是 -2^(n-1) 到 2^(n-1)-1，负数比正数多一个
- 溢出按模 2^n 截断，Java int 溢出就是这种语义
- 面试常问：Integer.MIN_VALUE 取负仍是自己，因为正数范围装不下

## 边界卡
Q: 浮点数为什么有精度问题？

A:
- IEEE 754 浮点数用符号位、指数、尾数表示二进制科学计数法
- 很多十进制小数无法用有限二进制精确表示，例如 0.1
- 运算会舍入，连续计算会累积误差
- 金额计算不应直接用 float/double，应使用 BigDecimal 或整数分单位
- 浮点适合科学计算近似值，不适合精确十进制金额

## 对比追问卡
Q: int 溢出和浮点精度丢失有什么区别？

A:
- int 溢出是固定宽度补码按模截断，结果确定但可能超出业务预期
- 浮点误差来自二进制无法精确表示某些小数和舍入规则
- int 常见问题是越界、比较、取负、乘法溢出
- double 常见问题是相等比较、金额误差、累计误差
- 工程上要根据数据类型边界选择 long、BigInteger、BigDecimal 或范围检查

## 正确性审查卡
Q: 数值表示常见误区有哪些？

A:
- “double 能精确表示所有小数”：错，只能精确表示一部分二进制小数
- “int 溢出会报错”：Java int 溢出默认不会抛异常
- “网络传整数直接按本机内存发出去”：错，跨平台协议要约定字节序
- “BigDecimal new BigDecimal(0.1) 没问题”：应使用字符串或 valueOf，避免先引入 double 误差
