# 编译链接与装载

## 概念卡
Q: 从源代码到可执行程序大致经历哪些阶段？

A:
- 预处理：展开宏、处理 include、条件编译
- 编译：把高级语言转成汇编或中间表示并优化
- 汇编：生成目标文件，包含机器指令、符号表、重定位信息
- 链接：解析符号引用，合并目标文件和库，完成重定位
- 装载：操作系统把可执行文件映射进进程地址空间并准备运行

## 机制卡
Q: 链接器主要做什么？

A:
- 符号解析：把函数/全局变量引用绑定到定义
- 重定位：确定代码和数据最终地址，修正指令或数据中的地址引用
- 合并段：把多个目标文件的 text/data/bss 等段合并
- 处理静态库/动态库依赖
- 生成可执行文件或共享库

## 边界卡
Q: 静态链接和动态链接有什么区别？

A:
- 静态链接把库代码复制进可执行文件，部署简单但体积大，升级库需重新链接
- 动态链接运行时加载共享库，多个进程可共享库代码页
- 动态链接有符号查找、PLT/GOT、装载重定位等成本
- 动态库升级更灵活，但可能遇到 ABI 兼容问题
- Java 场景也有类似思想：类加载、动态绑定、JNI native library

## 对比追问卡
Q: 可执行文件里的 text、data、bss 大致是什么？

A:
- text 段：机器指令，通常只读可执行
- rodata：只读常量，如字符串常量
- data 段：已初始化的全局/静态变量
- bss 段：未初始化或零初始化的全局/静态变量，文件中通常不占真实内容
- heap/stack 是进程运行时内存区域，不是目标文件里直接存好的同类段

## 正确性审查卡
Q: 编译链接相关常见误区有哪些？

A:
- “编译就是生成可执行文件”：严格说还包括汇编、链接等阶段
- “bss 在文件里存一堆 0”：通常只记录大小，装载时清零
- “动态链接一定慢很多”：主要在装载/首次调用有成本，运行后影响取决于场景
- “Java 没有链接”：Java 有类加载、验证、准备、解析、初始化，只是机制不同
