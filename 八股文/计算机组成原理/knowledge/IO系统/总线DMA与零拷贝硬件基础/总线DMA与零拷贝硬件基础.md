# 总线DMA与零拷贝硬件基础

## 概念卡
Q: DMA 是什么？解决什么问题？

A:
- DMA Direct Memory Access 允许外设绕过 CPU 直接和内存搬运数据
- CPU 负责配置 DMA 描述符、缓冲区地址、长度和方向
- 数据搬运过程中 CPU 不需要逐字节复制，可以去执行其他任务
- DMA 完成后通过中断通知 CPU
- 它降低 CPU 拷贝开销，是高性能网络和磁盘 IO 的基础

## 机制卡
Q: 一次网卡收包从硬件到内存大致怎么走？

A:
- 驱动提前分配接收缓冲区，并把地址告诉网卡 DMA ring
- 数据包到达网卡后，网卡通过 DMA 写入内存缓冲区
- 网卡触发中断或 NAPI 轮询通知内核处理
- 内核协议栈解析包，放入 socket 接收队列
- 应用通过 read/recv 或 mmap/io_uring 等方式取走数据

## 边界卡
Q: 零拷贝到底“零”的是什么？

A:
- 零拷贝通常指减少 CPU 在用户态和内核态之间的数据复制，不是完全没有数据移动
- DMA 仍会在设备和内存之间搬运数据
- sendfile 可让文件数据从页缓存直接进入 socket 发送路径，少一次用户态拷贝
- mmap 减少 read 把内核页缓存复制到用户缓冲区的过程
- 还要考虑上下文切换、页固定、网卡能力、协议栈限制

## 对比追问卡
Q: DMA、页缓存、sendfile 三者怎么串起来？

A:
- 磁盘通过 DMA 把文件页读入内核页缓存
- 传统 read/write 会从页缓存复制到用户态，再从用户态复制回内核 socket 缓冲
- sendfile 让内核在文件页缓存和 socket 发送路径之间直接转发
- 支持 scatter-gather 的网卡还能进一步减少内存复制
- 面试表达：零拷贝是 OS、DMA、网卡能力配合的结果

## 正确性审查卡
Q: 关于零拷贝有哪些常见误区？

A:
- “零拷贝没有任何拷贝”：错，通常是减少 CPU 拷贝，DMA 仍然搬运
- “所有场景都适合 sendfile”：不适合需要用户态改写内容、加密压缩、业务处理的场景
- “DMA 不需要 CPU”：CPU 仍要配置、处理中断、维护缓冲区和一致性
- “只要零拷贝就一定最快”：小数据、复杂协议、TLS、上下文切换都可能改变收益
