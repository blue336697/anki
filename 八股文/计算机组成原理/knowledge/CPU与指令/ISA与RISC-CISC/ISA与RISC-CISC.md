# ISA与RISC-CISC

## 概念卡
Q: ISA 是什么？它和微架构有什么区别？

A:
- ISA Instruction Set Architecture 是软件能看到的“指令集架构契约”
- 它规定指令格式、寄存器、寻址方式、异常模型、内存模型等
- 微架构是 CPU 内部如何实现这套 ISA，比如流水线、乱序执行、缓存、分支预测
- 同一个 ISA 可以有不同微架构实现，例如不同代 x86 CPU 性能差异很大
- 面试表达：ISA 是接口规范，微架构是实现细节

## 机制卡
Q: RISC 和 CISC 的核心区别是什么？

A:
- RISC 倾向简单固定长度指令、load/store 架构、寄存器操作多、译码简单
- CISC 倾向复杂变长指令、寻址方式多、单条指令可能完成较复杂操作
- RISC 更利于流水线、译码和低功耗设计
- CISC 代码密度高、历史兼容强，但现代 x86 内部常把复杂指令译成微操作执行
- 现代差异没有教材里那么绝对，更多是历史包袱和实现策略差异

## 边界卡
Q: 为什么说现代 x86 外表 CISC、内部有 RISC 化倾向？

A:
- x86 需要兼容复杂变长指令，这是对软件生态的承诺
- CPU 前端会把复杂 x86 指令译码成更简单的 micro-ops
- 后端调度、乱序执行、执行单元处理的是更规整的微操作
- 这样既保留 CISC 兼容性，又获得类似 RISC 的流水线和执行效率
- 面试不要说“x86 就是慢”：现代性能取决于前端译码、缓存、分支预测、执行宽度等综合因素

## 对比追问卡
Q: ARM、x86、JVM 字节码分别处在哪一层？

A:
- ARM/x86 是硬件 ISA，最终由 CPU 直接或经内部微操作执行
- JVM 字节码是虚拟机指令集，不是物理 CPU ISA
- Java 字节码先由解释器执行或 JIT 编译成本机机器码
- JIT 后仍然落到 x86/ARM 等硬件 ISA 上运行
- 所以 Java 性能分析既要懂 JVM，也要懂底层 CPU 缓存、分支、内存屏障

## 正确性审查卡
Q: ISA、RISC/CISC 有哪些常见误区？

A:
- “RISC 一定比 CISC 快”：不准确，现代性能由微架构和工艺共同决定
- “CISC 一条指令做很多事所以一定更高效”：复杂译码和流水线压力也很高
- “ISA 和 CPU 实现是一回事”：错，ISA 是规范，微架构是实现
- “JVM 字节码就是机器码”：错，字节码需要解释或 JIT 到本机指令
