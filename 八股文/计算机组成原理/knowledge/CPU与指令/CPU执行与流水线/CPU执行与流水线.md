# CPU执行与流水线

## 概念卡
Q: CPU 执行一条指令大致经历哪些阶段？

A:
- 经典五级流水线：取指 IF、译码 ID、执行 EX、访存 MEM、写回 WB
- 取指从 PC 指向的地址读取指令，并更新下一条 PC
- 译码解析操作码、寄存器编号、立即数，并读寄存器堆
- 执行阶段由 ALU/分支单元完成计算、比较、地址生成
- 访存阶段访问 L1/L2/内存；写回把结果写入寄存器

## 机制卡
Q: 为什么 CPU 要做流水线？

A:
- 单条指令完整执行可能要多个阶段，若串行执行，硬件大部分时间空闲
- 流水线把不同指令放在不同阶段并行推进，提高吞吐量
- 理想情况下，五级流水线可以做到接近每个周期完成一条指令
- 它提升的是吞吐，不是单条指令延迟；单条指令仍要经过多个阶段
- 面试表达：流水线用空间换时间，把“工序并行”变成 CPU 指令吞吐

## 边界卡
Q: 流水线有哪些冒险？怎么处理？

A:
- 结构冒险：多个阶段争同一硬件资源，可通过资源复制或暂停解决
- 数据冒险：后一条指令依赖前一条结果，可用转发/旁路、插入气泡解决
- 控制冒险：分支跳转导致下一条 PC 不确定，可用分支预测、延迟槽、流水线冲刷
- 分支预测错会清空错误路径上的指令，导致性能损失
- 现代 CPU 还会做乱序执行、寄存器重命名来缓解依赖

## 对比追问卡
Q: CPI、IPC、主频和流水线有什么关系？

A:
- CPI 是每条指令平均周期数，越低越好；IPC 是每周期完成指令数，越高越好
- 运行时间约等于 指令数 × CPI × 时钟周期时间
- 提高主频会缩短周期时间，但可能受功耗和流水线深度限制
- 更深流水线可能提高频率，但分支预测失败代价更大
- 后端面试落点：线上 CPU 高不只看主频，还要看 cache miss、分支、锁竞争、系统调用

## 正确性审查卡
Q: 关于 CPU 流水线有哪些常见误区？

A:
- “流水线让单条指令更快”：不准确。主要提升吞吐，不一定降低单条延迟
- “CPU 一次只执行一条指令”：经典模型便于理解，现代 CPU 有超标量、乱序执行、多发射
- “CPU 高一定是计算慢”：不一定，可能是 cache miss、分支预测失败、自旋锁、GC 或系统调用频繁
- “Java 程序不用懂 CPU”：错。并发、缓存行、伪共享、JIT、volatile 屏障都和硬件模型相关
