# 流水线冒险与分支预测

## 概念卡
Q: 什么是流水线冒险？

A:
- 流水线冒险是指下一条指令无法在预期周期进入下一阶段，导致流水线停顿
- 结构冒险：硬件资源冲突
- 数据冒险：后一条指令依赖前一条结果
- 控制冒险：分支/跳转导致下一条指令地址不确定
- 本质是指令并行推进时出现资源、数据、控制流依赖

## 机制卡
Q: 数据冒险怎么处理？

A:
- 插入气泡：等待前一条指令结果写回，简单但损失周期
- 数据转发/旁路：结果还没写回寄存器，就从执行单元输出直接转给后续指令
- 编译器调度：调整无依赖指令顺序，填充等待周期
- 乱序执行：硬件动态调度可执行指令，绕开部分依赖等待
- 但真正的数据依赖无法消除，只能减少等待成本

## 边界卡
Q: 分支预测为什么重要？

A:
- 分支指令会让 CPU 不确定下一条 PC 是顺序地址还是跳转目标
- 如果等分支结果出来再取指，流水线会空转
- 分支预测先猜一条路径继续取指和执行
- 猜对提升吞吐，猜错需要冲刷水线中错误路径上的指令
- 深流水线和宽发射 CPU 中，分支预测失败代价更高

## 对比追问卡
Q: Java 代码中分支预测会影响性能吗？

A:
- 会。JIT 编译后的机器码仍然在真实 CPU 上执行
- 数据分布规律时，分支预测更容易命中，流水线更平稳
- 随机分支、复杂 if-else、不可预测状态机会增加预测失败
- 热点循环中，分支和内存访问模式都可能影响性能
- 但业务代码不要盲目为分支预测牺牲可读性，先用 profiler 证明热点

## 正确性审查卡
Q: 流水线冒险有哪些常见误区？

A:
- “流水线越深越好”：不一定，分支失败代价也更大
- “分支预测只影响 C/C++”：错，JIT 后 Java 也受影响
- “数据转发能解决所有依赖”：不能解决必须等待内存加载等场景
- “CPU 高一定是算法复杂度高”：也可能是分支失败、cache miss、锁竞争导致 CPI 变高
