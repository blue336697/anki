# 存储层次与局部性

## 概念卡
Q: 计算机为什么要设计多级存储层次？

A:
- CPU 速度远快于内存和磁盘，单一存储无法同时满足容量、速度、成本
- 多级存储用少量高速缓存承接热点数据，用大容量低速存储承接冷数据
- 典型层次：寄存器、L1/L2/L3 Cache、内存、SSD/HDD、远端存储
- 依赖程序局部性：最近访问的数据和附近数据很可能再次被访问
- 目标是让大多数访问命中靠近 CPU 的层级

## 机制卡
Q: 时间局部性和空间局部性是什么？

A:
- 时间局部性：刚访问过的数据/指令，短时间内可能再次访问
- 空间局部性：访问某地址后，附近地址很可能被连续访问
- 数组顺序遍历利用空间局部性，循环变量/热点对象利用时间局部性
- Cache line、预取、页缓存、数据库 buffer pool 都在利用局部性
- 面试落点：为什么顺序 IO 快、数组比链表缓存友好、批处理比随机访问快

## 边界卡
Q: 链表和数组在 CPU 缓存上有什么差异？

A:
- 数组内存连续，顺序遍历能充分利用 cache line 和硬件预取
- 链表节点分散，next 指针跳转导致随机访存，容易 cache miss
- 链表每个节点还多存指针，内存占用和 GC 压力更高
- 即使链表插入删除理论 O(1)，定位节点和缓存不友好会让实际性能变差
- 后端场景：热点路径优先考虑连续内存、批量处理、减少对象碎片

## 对比追问卡
Q: CPU Cache、操作系统页缓存、数据库 Buffer Pool 有什么相似和不同？

A:
- 相似：都是缓存下层慢速存储，利用局部性减少访问成本
- CPU Cache 缓存内存数据，硬件管理，粒度通常是 cache line
- 页缓存缓存磁盘文件页，由操作系统管理，减少磁盘 IO
- Buffer Pool 缓存数据库页，由数据库管理，可结合事务、脏页、淘汰策略
- 面试表达：层级不同、管理者不同、粒度不同，但目标都是减少慢路径访问

## 正确性审查卡
Q: 关于存储层次有哪些常见误区？

A:
- “内存访问都是 O(1) 所以一样快”：算法复杂度忽略了缓存层次，实际差异巨大
- “链表插入一定比数组快”：若需要定位、遍历或频繁分配，链表可能更慢
- “缓存越大越好”：容量、延迟、功耗、成本要权衡
- “顺序访问只对磁盘重要”：对 CPU cache、TLB、预取同样重要
