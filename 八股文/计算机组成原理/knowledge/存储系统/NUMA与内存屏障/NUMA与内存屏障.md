# NUMA与内存屏障

## 概念卡
Q: NUMA 是什么？

A:
- NUMA Non-Uniform Memory Access 指非统一内存访问架构
- 多路 CPU/多 socket 机器上，每个 CPU 节点有更近的本地内存
- 访问本地内存快，访问其他节点远端内存慢
- 操作系统会尽量把线程和内存分配到同一 NUMA 节点
- 对高性能服务，线程绑定、内存亲和性、跨节点访问都会影响延迟

## 机制卡
Q: 内存屏障解决什么问题？

A:
- 现代 CPU 和编译器会为了性能做重排序
- 内存屏障限制某些读写操作在屏障前后的可见顺序
- LoadLoad、LoadStore、StoreStore、StoreLoad 分别约束不同读写组合
- Java volatile、锁、Unsafe/VarHandle 底层会利用屏障建立 happens-before
- 屏障不是为了加速，而是用性能换正确性

## 边界卡
Q: NUMA 对普通 Java 后端什么时候重要？

A:
- 单机多 socket、大内存、高并发低延迟服务中更容易重要
- 如果线程在节点 A，热点内存却分配在节点 B，会增加远端访问延迟
- GC 线程、业务线程、Netty event loop、off-heap buffer 都可能受影响
- 容器调度如果没有 CPU/memory 亲和性，也可能造成跨 NUMA 抖动
- 普通小规模服务不用过早优化，先用 perf/numastat/延迟指标证明

## 对比追问卡
Q: 内存屏障和缓存一致性是什么关系？

A:
- 缓存一致性保证同一缓存行在多个核心之间维持一致协议
- 内存屏障约束本核心读写操作的顺序和对其他核心的可见时机
- 有缓存一致性不代表程序天然满足语言层 happens-before
- Java 内存模型在硬件屏障之上定义语言级可见性和有序性
- 面试表达：一致性是硬件协议，屏障是顺序约束，JMM 是语言规范

## 正确性审查卡
Q: NUMA 和内存屏障有哪些常见误区？

A:
- “多核内存访问都一样快”：NUMA 下本地/远端内存延迟不同
- “volatile 就是直接读主内存”：这是过时简化说法，本质是可见性和有序性语义
- “屏障越多越安全”：屏障有性能成本，应由锁/volatile/并发库正确表达
- “缓存一致性等于线程安全”：一致性不保证复合操作原子，也不自动建立业务不变量
