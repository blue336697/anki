# CPU缓存与CacheLine

## 概念卡
Q: Cache Line 是什么？为什么后端要关心？

A:
- Cache Line 是 CPU Cache 和内存之间传输的基本粒度，常见大小 64 字节
- CPU 访问某个地址时，会把该地址所在的一整行加载到缓存
- 顺序访问数组能顺带利用同一 cache line 上的多个元素
- 多线程写同一 cache line 上的不同变量，会产生伪共享
- Java 并发、队列、计数器、RingBuffer 都可能受 cache line 影响

## 机制卡
Q: CPU 读写数据时缓存大致怎么工作？

A:
- CPU 根据地址查 L1，未命中再查 L2/L3，最后访问内存
- 缓存以 cache line 为单位加载，不是只加载单个变量
- 写策略可能是 write-back，先写缓存并标记脏，之后再写回内存
- 多核场景需要缓存一致性协议协调各核心的副本状态
- cache miss 会让流水线等待，成为 CPU 密集程序的重要瓶颈

## 边界卡
Q: 什么是伪共享？

A:
- 多个线程写不同变量，但这些变量落在同一个 cache line 上
- 对线程来说没有共享同一个变量，对硬件来说共享了同一缓存行
- 一个核心写入会让其他核心对应 cache line 失效，引发频繁一致性通信
- 现象是 CPU 很高但业务吞吐不升，热点计数器/数组槽位尤其常见
- 解决：填充 padding、字段隔离、LongAdder 分散热点、避免多线程写相邻槽位

## 对比追问卡
Q: Cache miss 和 TLB miss 有什么区别？

A:
- Cache miss 是数据不在 CPU 数据缓存中，需要去更低层存储取 cache line
- TLB miss 是虚拟地址到物理地址的页表翻译缓存未命中，需要查页表
- 两者都可能拖慢访存，但发生在不同阶段：地址翻译 vs 数据访问
- 大页、连续访问、减少随机访问有助于改善 TLB/cache 友好性
- 面试中可以用“先翻译地址，再取数据”来组织回答

## 正确性审查卡
Q: 关于 CPU Cache 有哪些常见误区？

A:
- “变量小就只加载变量”：错，缓存按 cache line 加载
- “volatile 能解决伪共享”：volatile 保证可见性/有序性，不消除缓存行竞争
- “只有 C/C++ 需要关心缓存”：Java 对象布局、数组、并发计数器同样受影响
- “缓存命中完全由程序员控制”：硬件管理，但程序访问模式会显著影响命中率
