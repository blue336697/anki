# 内存对齐与结构体布局

## 概念卡
Q: 什么是内存对齐？

A:
- 内存对齐是让数据对象的起始地址满足特定倍数要求
- 例如 4 字节 int 通常希望放在 4 的倍数地址上
- 对齐能让 CPU 用更少的内存访问周期读取数据
- 未对齐访问可能需要多次读取、额外拼接，某些架构甚至会触发异常
- 结构体/对象布局会插入 padding 来满足字段对齐

## 机制卡
Q: 为什么结构体字段顺序会影响大小？

A:
- 每个字段有自己的对齐要求
- 编译器/运行时会在字段之间插入 padding，保证下一个字段地址对齐
- 结构体整体大小也通常要对齐到最大字段对齐粒度
- 小字段夹在大字段之间可能造成更多空洞
- 调整字段顺序可能减少 padding，提高缓存密度

## 边界卡
Q: Java 对象也有内存对齐问题吗？

A:
- 有。Java 对象有对象头、字段、padding，对齐粒度通常与 JVM 和平台有关
- compressed oops、对象头大小、字段重排都会影响对象大小
- 数组元素通常连续存放，比链表对象更 cache friendly
- 伪共享也和对象/字段是否落在同一 cache line 有关
- 具体布局可用 JOL 工具观察，不要凭感觉猜

## 对比追问卡
Q: 内存对齐和 Cache Line 有什么关系？

A:
- 内存对齐关注单个数据访问是否落在适合的地址边界
- Cache Line 关注 CPU 缓存和内存传输的基本粒度
- 良好对齐能减少跨边界访问，提升读写效率
- 数据紧凑布局能提高每个 cache line 可用数据量
- 但过度 padding 会增大内存占用，要在吞吐和空间之间权衡

## 正确性审查卡
Q: 内存对齐有哪些常见误区？

A:
- “对齐只是 C/C++ 的事”：Java 对象布局、数组、伪共享同样相关
- “字段越小一定越省内存”：字段顺序和 padding 可能让实际大小变大
- “padding 都是浪费”：有些 padding 是为了换取访问效率和硬件要求
- “对象大小等于字段大小之和”：还要算对象头、对齐和运行时布局
