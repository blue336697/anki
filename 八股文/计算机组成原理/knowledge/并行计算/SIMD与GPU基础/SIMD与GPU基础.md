# SIMD与GPU基础

## 概念卡
Q: SIMD 是什么？

A:
- SIMD Single Instruction Multiple Data，单条指令同时处理多个数据元素
- 适合数组、向量、矩阵、图像、音视频、机器学习等数据并行任务
- CPU 上常见 SIMD 指令集包括 SSE、AVX、NEON 等
- 它提升的是数据并行吞吐，不改变算法复杂度阶数
- Java 中 JIT 可能自动向量化，现代版本也有 Vector API 探索显式向量化

## 机制卡
Q: GPU 为什么适合大规模并行计算？

A:
- GPU 有大量相对简单的计算核心，适合同时跑大量相似任务
- 它用高吞吐掩盖单个线程延迟，强调数据并行
- 适合矩阵乘法、向量运算、图像处理、深度学习训练/推理
- CPU 更擅长复杂控制流、低延迟、分支多和系统调度
- GPU 高效的前提是数据搬运成本和并行规模能摊薄

## 边界卡
Q: 为什么不是所有任务都适合 GPU？

A:
- 分支复杂、任务规模小、数据依赖强时 GPU 利用率低
- CPU 到 GPU 的数据传输有成本，小任务可能传输成本超过计算收益
- 随机访存和不规则数据结构会降低吞吐
- GPU 编程还要考虑显存、kernel 启动、内存 coalescing 等细节
- 后端面试表达：GPU 适合大规模规则数据并行，不是通用加速魔法

## 对比追问卡
Q: SIMD、线程并行、GPU 并行怎么区分？

A:
- SIMD 是一条指令处理多个数据，发生在单核心/向量执行单元层面
- 线程并行是多个 CPU 核心执行多个线程，适合任务并行或请求并行
- GPU 并行是大量轻量线程执行相似计算，适合大规模数据并行
- 三者可以组合，例如多线程每个线程内部 SIMD，或 CPU 调度 GPU kernel
- 选择取决于数据规模、控制流复杂度、内存访问模式和延迟要求

## 正确性审查卡
Q: SIMD/GPU 有哪些常见误区？

A:
- “用了 GPU 一定更快”：不一定，数据传输和任务规模可能吃掉收益
- “SIMD 只和 C++ 有关”：JIT、向量库、数据库执行引擎都可能利用 SIMD
- “并行度越高越好”：内存带宽、同步、调度开销会成为瓶颈
- “GPU 适合所有后端任务”：多数 CRUD/网络 IO 服务瓶颈不在 GPU 计算
