# 冯诺依曼架构

## 概念卡
Q: 冯诺依曼架构是什么？五大组成是什么？

A:
- 冯诺依曼架构是一种“存储程序”计算机模型：程序指令和数据都存放在同一主存中
- 五大组成：运算器、控制器、存储器、输入设备、输出设备
- 运算器负责算术/逻辑运算，控制器负责取指、译码、发控制信号
- 存储器保存指令和数据，输入/输出设备负责和外部世界交互
- 现代 CPU 通常把运算器和控制器集成在处理器内部，但抽象仍然成立

## 机制卡
Q: 冯诺依曼架构下，程序为什么能被 CPU 执行？

A:
- 程序以指令序列形式存放在内存中，PC 保存下一条要执行的指令地址
- CPU 根据 PC 取指，把指令从内存取到指令寄存器
- 控制器译码，识别操作类型、寄存器、立即数、访存地址等
- 运算器/访存单元执行指令，结果写回寄存器或内存
- PC 更新到下一条指令或跳转目标，循环执行“取指-译码-执行”

## 边界卡
Q: 冯诺依曼架构的核心瓶颈是什么？

A:
- 核心瓶颈是 CPU 和存储器之间的数据/指令搬运速度不匹配，也叫冯诺依曼瓶颈
- 指令和数据共享存储和通路，CPU 再快也可能被取指、访存、内存带宽拖住
- 现代计算机用多级缓存、流水线、分支预测、预取、乱序执行缓解瓶颈
- 但内存墙仍然存在，cache miss、TLB miss、随机访存会显著拖慢程序
- 后端工程里数组顺序访问、批处理、减少对象碎片，本质都在改善这个瓶颈

## 对比追问卡
Q: 冯诺依曼架构和哈佛架构有什么区别？

A:
- 冯诺依曼架构：指令和数据共用同一存储空间和总线，结构简单、灵活
- 哈佛架构：指令存储和数据存储分离，取指和访存可并行，常见于嵌入式/DSP/微控制器
- 现代 CPU 往往是“改进型哈佛”：L1 指令缓存和 L1 数据缓存分离，但下层缓存/内存统一
- 面试不要绝对化：教材模型是抽象，现代处理器会混合使用多种设计
- 追问落点：为什么分离 I-Cache/D-Cache 能提高吞吐，为什么统一内存又方便程序加载和通用计算

## 正确性审查卡
Q: 冯诺依曼架构有哪些常见误区？

A:
- “冯诺依曼架构就是 CPU+内存”：不完整，还包括输入、输出、控制器、运算器和存储程序思想
- “现代计算机已经不是冯诺依曼架构”：不准确。现代处理器做了大量优化，但通用计算仍保留存储程序核心模型
- “指令和数据完全没有区别”：物理上都可编码存储，但执行权限、段页权限、缓存路径和安全机制会区分
- “只背五大部件就够了”：五年面试更看重你能否串到 CPU 执行、缓存层次、内存瓶颈和系统调用
