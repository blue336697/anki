# 性能指标与瓶颈定位

## 概念卡
Q: 计算机组成视角下，程序性能由哪些因素决定？

A:
- 经典 CPU 时间公式：CPU Time = 指令数 × CPI × 时钟周期时间
- 指令数受算法、编译器、代码路径影响
- CPI 受 cache miss、分支预测、流水线停顿、锁竞争等影响
- 时钟周期时间和 CPU 主频、微架构、功耗墙有关
- 后端定位要从 CPU、内存、IO、锁、GC、网络多个层面看

## 机制卡
Q: 如何从“CPU 飙高”拆出可能原因？

A:
- 用户态 CPU 高：热点计算、循环、序列化、正则、加解密、GC 用户态工作
- 内核态 CPU 高：系统调用频繁、网络包处理、锁竞争、上下文切换、中断
- iowait 高：线程等磁盘或网络 IO，不一定是 CPU 真在算
- load 高但 CPU 不高：可能大量线程阻塞、不可中断 IO 或锁等待
- 工具链：top、pidstat、perf、jstack、async-profiler、iostat、sar

## 边界卡
Q: 为什么同样 O(n) 的程序性能可能差很多？

A:
- 常数项不同：序列化、对象分配、虚函数/接口调用、边界检查等
- 缓存友好性不同：顺序数组访问和随机链表访问差距很大
- 分支预测不同：随机分支比规律分支更容易导致流水线冲刷
- 内存分配和 GC 不同：对象数量、逃逸、生命周期影响很大
- 并发下还要看锁竞争、伪共享、上下文切换

## 对比追问卡
Q: 吞吐、延迟、P99、QPS、TPS 怎么区分？

A:
- 吞吐：单位时间处理的工作量，QPS/TPS 是具体业务口径
- 平均延迟可能掩盖长尾，P95/P99 更能反映用户体验和系统抖动
- QPS 高不代表 P99 好，可能靠排队堆积换吞吐
- 后端压测要同时看 QPS、P50/P95/P99、错误率、资源利用率
- 性能优化要先定义目标：降延迟、提吞吐、降成本还是提高稳定性

## 正确性审查卡
Q: 性能分析有哪些常见误区？

A:
- “只看平均耗时”：会忽略长尾和抖动，面试要主动提 P99
- “CPU 高就加机器”：应先看热点、锁、GC、cache miss、系统调用
- “复杂度低就一定快”：硬件局部性和常数项可能决定实际表现
- “压测只看 QPS”：还要看错误率、资源水位、队列长度、下游瓶颈
