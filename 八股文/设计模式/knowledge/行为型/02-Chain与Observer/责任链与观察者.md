# 责任链与观察者
## 01-Chain
Q: 责任链怎样组织多个处理器？
A:
- 请求依次经过 handler，每个决定处理、修改、拒绝或传给 next；可表达过滤器、审批和中间件。
- 顺序是契约，短路与异常传播必须定义；链应由装配层构建。
- 与普通循环相比对象链便于独立扩展，但调试路径更隐蔽。
- 处理器共享可变 context 时需防并发和跨请求污染。
## 02-Observer
Q: Observer 的同步与异步版本有什么语义差异？
A:
- 同步观察者在发布调用栈内执行，失败/延迟影响主流程但一致性容易理解。
- 异步事件经队列解耦时间和可用性，却引入重复、乱序、最终一致与投递失败。
- 订阅者不应隐式决定发布者核心事务结果，关键规则应留在聚合。
- 监听器生命周期不清会造成内存泄漏。
## 03-代码
Q: Java 责任链怎样显式短路？
A:
```java
interface Handler { Result handle(Request r, Chain next); }
final class AuthHandler implements Handler {
    public Result handle(Request r, Chain next) {
        if (!r.authenticated()) return Result.unauthorized();
        return next.proceed(r);
    }
}
```
- Chain 管理 index 和顺序，handler 不需知道具体下一个类型。
## 04-事件对比
Q: Observer 与 DDD Domain Event 有什么区别？
A:
- Observer 是对象协作机制；Domain Event 是业务事实和建模概念，可用观察者、消息总线等实现。
- 本地观察者对象引用不适合跨进程可靠集成，领域事件还需契约、Outbox 和幂等。
- 不要把任何回调都命名领域事件。
- 业务语义优先于实现模式。
## 05-边界
Q: 责任链和观察者怎样避免“看不见的控制流”？
A:
- 注册点集中，处理器/订阅者命名清晰并输出 trace、顺序和耗时。
- 区分必须成功与 best-effort 监听者，禁止静默吞异常。
- 链长度和异步 fan-out 应有限制与背压。
- 核心用例测试要断言实际执行顺序和事件集合。
