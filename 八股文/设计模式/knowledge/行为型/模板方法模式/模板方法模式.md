# 模板方法模式

## 意图卡
Q: 模板方法模式解决什么问题？
A:
- 模板方法在父类中定义算法骨架，把可变步骤延迟到子类实现
- 它适合流程稳定、部分步骤因业务不同而变化的场景
- 父类控制流程顺序，子类只覆盖特定步骤
- 常见落点是导入流程、订单处理流程、测试框架、Spring 生命周期扩展
- 面试表达：模板方法解决“流程固定，步骤可变”的问题

## 钩子卡
Q: 模板方法中的抽象步骤和钩子方法有什么区别？
A:
- 抽象步骤是子类必须实现的变化点
- 钩子方法是可选扩展点，父类提供默认实现
- 钩子可以控制流程是否执行某些步骤
- 抽象步骤表达强约束，钩子表达可选能力
- 好的模板方法要控制扩展点数量，避免子类随意破坏流程

## Spring落点卡
Q: Spring 和 Java 中有哪些模板方法思想？
A:
- `JdbcTemplate` 固定资源获取、执行、异常转换、释放流程
- `RestTemplate` 封装 HTTP 调用流程
- Servlet 的 `service` 分发到 `doGet`、`doPost` 也有模板思想
- Spring Bean 生命周期中部分扩展点也类似模板钩子
- 工程价值是把资源管理和异常处理沉淀到稳定骨架中

## 正确性审查卡
Q: 模板方法模式有哪些常见误区？
A:
- “模板方法必须用抽象类”：典型实现是抽象类，但核心是固定流程骨架
- “子类越自由越好”：错误。自由度过高会破坏模板约束
- “模板方法和策略一样”：不同。模板偏继承和流程骨架，策略偏组合和行为替换
- “公共逻辑都能上提到父类”：不一定。上提前要确认流程真的稳定
- “继承层级深没问题”：危险。深继承会让行为来源难以追踪
