# 装饰器模式

## 意图卡
Q: 装饰器模式解决什么问题？
A:
- 装饰器在不修改原对象的前提下，动态给对象叠加新职责
- 装饰器和被装饰对象实现同一接口，内部组合被装饰对象
- 它比继承更灵活，可以运行时组合多个增强能力
- 典型场景是 IO 流、请求包装、响应包装、功能增强链
- 面试表达：装饰器解决“职责叠加”，核心是组合和透明替换

## 对比卡
Q: 装饰器模式和代理模式怎么区分？
A:
- 装饰器重点是增强对象能力，可以一层层叠加职责
- 代理重点是控制访问，例如懒加载、权限、远程调用、事务
- 装饰器通常由调用方主动组合，代理常由框架或工厂生成
- 二者结构相似，区别在设计意图
- 面试时不要只画类图，要说清增强职责和访问控制的差异

## 工程落点卡
Q: Java 和 Web 开发中有哪些装饰器模式例子？
A:
- Java IO 的 `BufferedInputStream`、`DataInputStream` 包装基础流
- Servlet 中 `HttpServletRequestWrapper` 和 `HttpServletResponseWrapper`
- 日志、压缩、加密、缓存等可叠加处理链
- Spring 中部分包装器和 Bean 后处理也有装饰思想
- 工程价值是避免为每种组合创建一个子类

## 正确性审查卡
Q: 装饰器模式有哪些常见误区？
A:
- “装饰器就是继承增强”：错误。装饰器核心是组合增强
- “装饰层越多越灵活”：不完整。层数过多会增加调试难度
- “装饰器可以改变接口”：错误。改变接口更接近适配器
- “装饰器不影响行为顺序”：错误。不同包装顺序可能产生不同结果
- “装饰器和责任链一样”：不同。装饰器通常每层都调用下层，责任链可能中途终止
