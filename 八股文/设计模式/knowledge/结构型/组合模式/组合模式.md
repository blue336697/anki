# 组合模式

## 意图卡
Q: 组合模式解决什么问题？
A:
- 组合模式把单个对象和对象集合用统一接口表示
- 它适合树形结构，例如组织架构、菜单、文件目录、权限树、规则树
- 调用方可以一致地处理叶子节点和组合节点
- 核心价值是屏蔽树形结构中“单个”和“整体”的差异
- 面试表达：组合模式解决树结构的统一遍历和统一操作

## 透明安全卡
Q: 组合模式中的透明方式和安全方式有什么区别？
A:
- 透明方式把增删子节点方法放在统一接口中，调用方更一致
- 透明方式的问题是叶子节点也暴露无意义的子节点操作
- 安全方式只在组合节点中提供子节点管理方法
- 安全方式类型更准确，但调用方需要区分叶子和组合节点
- 工程中通常根据 API 易用性和类型安全取舍

## 工程落点卡
Q: 组合模式在后端工程中有哪些常见落点？
A:
- 权限菜单树、部门组织树、商品类目树
- 规则引擎中的条件组和条件项
- SQL AST、表达式树、流程编排节点
- 前端页面组件树或表单配置树
- 关键是递归处理、终止条件和避免循环引用

## 正确性审查卡
Q: 组合模式有哪些常见误区？
A:
- “有树结构就必须组合模式”：不一定。简单树用普通递归即可
- “组合节点和叶子节点行为完全一样”：错误。统一接口不代表内部语义一致
- “递归实现不会有风险”：错误。深树可能栈溢出，脏数据可能产生环
- “组合模式只适合 UI”：错误。权限、规则、组织架构都常用
- “透明方式一定更好”：不完整。它牺牲了叶子节点的类型安全
