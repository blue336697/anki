# 原型模式

## 意图卡
Q: 原型模式解决什么问题？
A:
- 原型模式通过复制已有对象来创建新对象
- 适合对象创建成本高、初始化复杂、配置大体相同但局部不同的场景
- 它能避免重复执行昂贵初始化逻辑
- 常见例子是模板对象复制、规则配置复制、游戏对象复制、文档快照
- 面试表达：原型模式关注“基于已有状态快速派生新对象”

## 深浅拷贝卡
Q: 原型模式中的浅拷贝和深拷贝有什么区别？
A:
- 浅拷贝复制对象本身，引用字段仍指向同一对象
- 深拷贝会递归复制引用对象，避免新旧对象共享可变内部状态
- 如果对象内部字段不可变，浅拷贝通常足够
- 如果包含可变集合、数组、缓存对象，浅拷贝容易引发串改
- 工程实践中要明确哪些字段共享，哪些字段必须复制

## Java落点卡
Q: Java 中使用原型模式有哪些实现方式？
A:
- 实现 `Cloneable` 并重写 `clone()`，但语义历史包袱较重
- 使用拷贝构造器或静态工厂，表达更清晰
- 使用序列化/反序列化做深拷贝，但性能和兼容性成本较高
- 使用 MapStruct、BeanUtils 等工具时要注意深浅拷贝语义
- 面试表达：Java 里不推荐盲目依赖 `clone()`，更推荐显式拷贝逻辑

## 正确性审查卡
Q: 原型模式有哪些常见误区？
A:
- “复制一定比 new 快”：错误。深拷贝可能更慢
- “clone 默认就是深拷贝”：错误。Object.clone 是浅拷贝
- “BeanUtils 拷贝就安全”：错误。它通常也是浅层属性复制
- “原型模式只是设计模式题”：不完整。配置复制和模板派生很常见
- “所有字段都深拷贝最好”：不一定。不可变对象和共享资源可以安全共享
