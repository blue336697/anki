# 单例、生命周期与并发安全
## 01-意图
Q: Singleton 真正保证什么，为什么常被滥用？
A:
- 保证某作用域内一个实例并提供访问点，但 JVM、ClassLoader、进程、容器 scope 的“一个”并不相同。
- 全局可变单例隐藏依赖、污染测试并制造并发热点，不能用它替代明确所有权。
- 无状态共享服务通常由 DI 容器 singleton scope 管理即可。
- 分布式系统的“全局唯一”需外部协调，不是 Java static。
## 02-并发
Q: 双重检查锁为什么必须配合 volatile？
A:
- 对象创建包含分配、初始化、发布，若重排发布引用在初始化前，其他线程可能看到半初始化对象。
- volatile 建立发布/读取 happens-before，第一次非锁检查减少初始化后锁开销。
- 现代 Java 内存模型下写法可用，但复杂且不如 holder/enum 清晰。
- 构造期间逸出 `this` 仍可能破坏安全发布。
## 03-Holder代码
Q: Initialization-on-demand holder 怎样实现惰性线程安全单例？
A:
```java
final class IdGenerator {
    private IdGenerator() {}
    private static class Holder {
        static final IdGenerator INSTANCE = new IdGenerator();
    }
    static IdGenerator instance() { return Holder.INSTANCE; }
}
```
- JVM 类初始化锁保证一次初始化，只有首次访问 Holder 才创建。
## 04-enum
Q: enum 单例有什么优势和边界？
A:
- JVM 保证每枚举常量一次初始化，天然抵抗普通反射构造并正确支持序列化身份。
- 适合无复杂继承需求的进程内唯一服务；测试替换和参数化构造仍不方便。
- 资源需要 close、按租户/请求 scope 时单例生命周期不合适。
- 热部署多 ClassLoader 仍可各有实例。
## 05-审查
Q: 哪些对象不应该做单例？
A:
- 持有请求/用户可变状态、非线程安全客户端、依赖不同配置的租户对象不应全局共享。
- 数据库连接不应单例，连接池管理多个连接；线程池也需明确关闭与隔离。
- 为方便调用把 repository/service 做静态单例，会阻止 mock 与事务上下文。
- 先问生命周期和并发语义，再选择模式。
