# Class 文件、字节码执行与动态调用

> 基线：Java SE 21/25 class file 与 HotSpot。字节码是栈式 JVM 的中间表示，不是最终机器码。

## 01-Class文件结构
Q: 一个 class 文件从头到尾有哪些核心结构？
A:
- `magic` 标识 class 格式，minor/major version 约束运行时可接受的 class 版本。
- 常量池保存 UTF-8、数值、类、字段/方法引用、MethodHandle、InvokeDynamic、Dynamic 等结构化常量。
- access flags、this/super、interfaces 描述类型关系；fields/methods 保存成员及其属性。
- 方法 `Code` 属性包含最大栈深、局部变量槽数、字节码、异常表和嵌套调试/验证属性。
- attributes 是可扩展机制，未知非关键属性可按规范忽略；class 文件不是 Java 源码的一一序列化。

## 02-栈式执行模型
Q: 局部变量表和操作数栈怎样协作执行一个表达式？
A:
- 每个栈帧按方法 `max_locals` 与 `max_stack` 建立局部变量槽和操作数栈容量。
- `iload/aload` 把局部变量值压栈，算术/比较指令消费栈顶操作数并把结果压回，`istore/astore` 再写回局部变量。
- 实例方法局部变量槽 0 通常保存 `this`；静态方法从第一个参数开始。
- `long/double` 在 class 文件局部变量模型中占两个 slot，引用和多数基础值按 verifier 类型跟踪。
- JIT 编译后值可能进入寄存器或被消除，操作数栈是字节码语义模型，不代表 CPU 逐条维护同一内存栈。

## 03-指令编码
Q: JVM 操作码为什么是一字节？`wide`、switch 对齐和 `_0.._3` 指令解决什么？
A:
- 普通 opcode 占一个无符号字节，所以编码空间最多 256；不同指令再携带定长或变长操作数。
- `iload_0` 等把常用局部变量索引编码进 opcode，减少字节数；更大索引用普通 load/store 携带操作数。
- `wide` 扩展部分局部变量索引和 `iinc` 常量宽度，而不是把整个指令集改成两字节 opcode。
- `tableswitch`、`lookupswitch` 是变长指令，并按当前位置加入 padding 以对齐 4 字节边界。
- byte/short/char/boolean 许多计算使用 int 指令语义，数组读写和转换处再保留具体类型规则。

## 04-验证与StackMapTable
Q: verifier 如何知道每个跳转目标的操作数栈类型是安全的？
A:
- 编译器在 `StackMapTable` 中记录关键控制流位置的局部变量和操作数栈类型帧。
- 验证器检查每条路径消费/产生的类型、栈高度和合流状态是否兼容。
- 跳转不能进入任意指令中间，异常 handler 入口栈状态也有明确约束。
- 这让 JVM 执行时无需为每条普通指令重复做完整动态类型检查。
- 手工字节码增强若忘记重算 frame、max stack 或异常表，常产生 VerifyError，而非业务运行到该分支才失败。

## 05-五类invoke
Q: `invokestatic`、`invokespecial`、`invokevirtual`、`invokeinterface`、`invokedynamic` 如何区分？
A:
- `invokestatic` 调用静态方法，不需要接收者；目标由类与方法符号引用解析。
- `invokespecial` 用于构造器、private 调用及特定 super 调用语义，绕过普通虚分派。
- `invokevirtual` 按接收者实际类型做类虚方法分派；final 目标仍可由 JIT 更积极去虚拟化。
- `invokeinterface` 从接口方法引用出发，在实际实现类型上选择目标；运行时可用 itable/缓存等实现加速。
- `invokedynamic` 由 bootstrap method 首次链接调用点并返回 CallSite，分派逻辑不固定为 Java 类/接口虚调用。

## 06-虚分派与JIT
Q: invokevirtual 每次都必须慢速查虚方法表吗？
A:
- 语义上目标取决于接收者实际类型，但解释器/JIT 可使用 vtable、inline cache 和类型 profile 加速。
- 单态调用点可被推测内联；少量多态可生成类型检查链；高度多态会限制内联。
- 新实现类加载或 profile 改变会使推测失效，触发去优化和重编译。
- 因此“动态绑定”是语言语义，不代表每次机器码都进行完整层次搜索。
- 性能判断应看 JIT 编译日志/profile，而不是只看字节码 opcode。

## 07-invokedynamic与condy
Q: Lambda、字符串拼接和 ConstantDynamic 为什么使用动态链接机制？
A:
- Lambda 的 invokedynamic 调用点由 LambdaMetafactory 等 bootstrap 逻辑链接，避免把语言实现永久固定成匿名内部类字节码形态。
- JDK 9+ 字符串拼接常由 StringConcatFactory 链接，使运行时可按参数形态选择优化策略。
- ConstantDynamic（condy）让常量池条目在首次解析时通过 bootstrap method 计算并缓存结果。
- bootstrap 不是每次普通调用都重新执行；CallSite/解析结果建立后可被 JVM 优化。
- 动态链接提高语言和库演进弹性，也让 agent/字节码工具必须正确处理 BootstrapMethods、MethodHandle 和动态常量。

## 08-异常表与finally
Q: catch/finally 在字节码中为什么主要依靠异常表而不是一条 catch 指令？
A:
- Code 属性异常表用 start_pc、end_pc、handler_pc、catch_type 描述受保护区和处理入口。
- 运行时发生异常时，JVM 在当前方法异常表中查匹配 handler；未命中则弹出帧继续向调用者传播。
- finally 常被编译器复制到正常返回和各异常退出路径，或通过 catch-all handler 执行清理后重新抛出。
- 多个 return 遇到 finally 时，编译器需保存返回值、执行 finally，再按控制流返回或被 finally 新异常覆盖。
- try-with-resources 还会生成 close 与 suppressed exception 逻辑，字节码比源码表面复杂。

## 09-synchronized字节码
Q: synchronized 方法和代码块在 class 文件层面怎样表示？
A:
- synchronized 实例方法/静态方法通过方法 access flag `ACC_SYNCHRONIZED` 表示，调用时分别锁接收者或对应 Class。
- synchronized 代码块显式使用 `monitorenter` 与 `monitorexit`。
- 编译器通过正常路径和异常 handler 保证退出临界区时执行 monitorexit；反编译时常看到重复释放路径。
- monitor 是可重入的，JVM 还会使用轻量锁、锁膨胀、锁消除等实现优化。
- 偏向锁属于旧 HotSpot 历史路径，JDK 15 已默认关闭并废弃，不能作为 JDK 21/25 默认模型。

## 10-switch与分支
Q: `tableswitch` 和 `lookupswitch` 如何选择？String/enum switch 是否直接使用它们？
A:
- tableswitch 用 low/high 范围和跳转表，适合值较密集的整数 case；空洞也占表项。
- lookupswitch 保存有序 match-offset 对，适合离散值；规范描述查找语义，不承诺具体实现必须二分。
- javac 根据 case 分布和代码尺寸启发式选择，不能只用“连续/不连续”作为绝对规则。
- String switch 通常先基于 hashCode 分组，再用 equals 消除碰撞，最后映射到整数分支。
- enum switch 的编译策略可包含合成映射结构；具体输出随编译器版本变化，应以 javap 结果为准。

## 11-iinc与求值顺序
Q: 为什么 `i = i++` 最终通常保持原值？这说明了什么？
A:
- 后置自增先产生表达式旧值，再对局部变量执行增量，最后赋值把旧值写回同一变量。
- 字节码常表现为 `iload` 保存旧值、`iinc` 修改局部变量、`istore` 用旧值覆盖。
- 前置自增先修改局部变量，再把新值作为表达式结果。
- 独立语句 `i++` 与 `++i` 在无需表达式结果时可能产生等价字节码，不能据此宣称一般语义相同。
- 这个例子适合理解 Java 求值顺序与局部变量/操作数栈，不应扩展成所有类型和并发场景的性能结论。

## 12-javap与诊断
Q: 怎样用 `javap -v -c -p -l -s` 系统分析一个 class？
A:
- `-c` 查看方法字节码，`-v` 查看常量池、flags、Code、BootstrapMethods、StackMapTable 等完整属性。
- `-p` 显示 private 成员，`-l` 显示行号和局部变量调试表，`-s` 显示描述符。
- 先核对 class major version 与编译参数，再从方法描述符确定槽位和返回类型。
- 按控制流画局部变量表、操作数栈和异常表；遇到 invokedynamic 再追 bootstrap method 与参数。
- javap 解释的是 class 中间表示，不等于 JIT 最终机器码；后者需编译日志、JITWatch 或反汇编工具。

## 13-正确性审查
Q: 字节码面试中哪些说法需要明确拒绝？
A:
- “字节码就是 CPU 最终执行指令”：错误，解释器执行或 JIT 编译后机器码才在 CPU 上运行。
- “invokevirtual 每次都线性查方法”：错误，JVM 有 vtable、缓存、内联和去虚拟化。
- “lookupswitch 规范保证二分查找”：不应把常见实现策略说成强制语义。
- “JDK 21 字符串 `+` 一定编译成显式 StringBuilder”：错误，现代 javac 常使用 invokedynamic。
- “synchronized 默认经历偏向锁升级”：过时，偏向锁已退出现代默认路径。
