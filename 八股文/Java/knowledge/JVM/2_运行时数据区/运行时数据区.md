# JVM 运行时数据区

> 基线：JVM 规范概念 + JDK 21/25 HotSpot 实现。规范区域与 HotSpot 物理实现必须分开回答。

## 01-区域总图
Q: JVM 运行时数据区怎样划分？哪些线程私有，哪些线程共享？
A:
- 程序计数器、Java 虚拟机栈和本地方法栈具有线程私有语义，生命周期通常跟随线程。
- 堆和方法区具有线程共享语义；对象实例主要分配在堆，类型元数据、运行时常量池等属于方法区的规范职责。
- HotSpot 以 Metaspace 实现方法区的主要类型元数据，内存来自 native memory，不等于“方法区就是 Metaspace”。
- 直接内存、代码缓存、线程栈、GC 辅助结构和 JNI 内存不属于 Java 堆，却会占用进程 RSS。
- 判断 OOM 不能只看 `-Xmx`；容器限制下应把 heap、metaspace、code cache、direct buffer、thread stack 和 native allocator 一起建模。

## 02-虚拟机栈与栈帧
Q: Java 方法调用时栈帧内部有哪些部分？局部变量表为什么不等于普通对象数组？
A:
- 每次方法调用创建栈帧，典型组成包括局部变量表、操作数栈、动态链接信息和方法返回相关状态。
- 局部变量表以 slot 组织基本类型值和对象引用；`long`、`double` 在 class 文件局部变量模型中占两个 slot，具体机器实现可优化。
- 操作数栈承载字节码计算中间值，例如 `iload`、`iadd`、`invoke*` 消费和产生栈元素。
- 对象通常在堆上，栈帧里保存引用；JIT 逃逸分析可能标量替换对象，但不能把它机械表述成“对象都分配到栈”。
- 深递归或过大栈帧会引发 `StackOverflowError`；创建过多平台线程还可能因 native stack/地址空间不足而失败。

## 03-堆与分代
Q: Java 堆为什么经常分代？新生代、老年代是不是 JVM 规范强制结构？
A:
- 分代基于“多数对象朝生夕死、少数对象长期存活”的弱分代假说，用不同策略降低回收成本。
- 新生代常通过复制/疏散快速回收，存活对象达到条件后晋升；老年代承担长寿命对象和晋升压力。
- 分代不是 JVM 规范强制布局，也不是所有收集器都使用相同结构；ZGC 在 JDK 21 引入分代实现，历史非分代 ZGC 仍需区分。
- G1 以 Region 组织堆，逻辑上仍有 Eden、Survivor、Old、Humongous 等角色，不是传统连续新老年代。
- 对象年龄、动态年龄判断、担保与大对象规则是具体收集器实现细节，回答时必须带版本和收集器前提。

## 04-方法区与Metaspace
Q: 方法区、永久代和 Metaspace 的关系是什么？
A:
- 方法区是 JVM 规范定义的逻辑区域，保存每个类的结构、运行时常量池、方法和字段信息等。
- PermGen 是旧 HotSpot 对部分方法区职责的实现，JDK 8 已移除；不能把永久代当成所有 JVM 的规范结构。
- Metaspace 使用 native memory 保存类元数据，容量受进程/容器内存和 `MaxMetaspaceSize` 等参数影响。
- 字符串常量池自 JDK 7 起位于堆中；类静态字段所引用的对象也仍是普通堆对象，不能简单说“静态变量都在方法区”。
- 动态生成类、频繁创建类加载器而无法卸载，会导致 Metaspace 增长甚至 `OutOfMemoryError: Metaspace`。

## 05-直接内存与堆外内存
Q: DirectByteBuffer 的内存在哪里？为什么堆看起来不大仍可能 OOM？
A:
- DirectByteBuffer 的 Java 包装对象在堆上，实际数据缓冲通常通过 native allocator 在堆外申请。
- 优点是某些 I/O 路径可减少 Java 堆与 native 缓冲区之间的复制；代价是申请释放成本高、受 GC 触发清理时机影响。
- 上限通常受 `-XX:MaxDirectMemorySize` 和运行时实现控制；失败可能抛 `OutOfMemoryError: Direct buffer memory`。
- 除 direct buffer 外，线程栈、Metaspace、Code Cache、GC 表、压缩类空间、JNI 和 libc arena 都会消耗 native memory。
- 排障结合 `jcmd VM.native_memory`、NMT、进程 RSS、容器 memory.current 和 direct buffer pool 指标，不能只分析 heap dump。

## 06-OOM映射
Q: 常见 JVM 内存错误分别对应什么区域和排查入口？
A:
- `Java heap space`：堆无法满足分配；区分真实泄漏、容量不足、大对象突发和 GC overhead。
- `Metaspace`：类元数据增长；检查动态代理/字节码生成、ClassLoader 数量、热部署残留。
- `Direct buffer memory`：直接缓冲上限或释放不及时；检查池化、引用链、Netty 之外的 NIO 使用和 native 指标。
- `unable to create native thread`：进程/容器线程数、虚拟内存、每线程栈大小或系统限制不足，不是 Java 堆 OOM。
- 进程被容器 OOMKill 时可能没有 Java OOM 日志；必须结合 cgroup、内核事件和总 RSS 判断。

## 07-正确性审查
Q: 运行时数据区有哪些高频错误表述？
A:
- “方法区就是永久代/Metaspace”：错误；前者是规范概念，后两者是 HotSpot 不同年代的实现。
- “所有对象一定在堆”：从语言可观察语义看对象由 JVM 管理；JIT 可能消除分配或标量替换，不能按源码机械映射。
- “直接内存不受 JVM 管理”：不严谨。内存位于堆外，但 DirectByteBuffer 生命周期和部分上限仍受 JVM 协调。
- “只有堆会 OOM”：错误；Metaspace、direct buffer、线程创建和 code cache 等都有独立失败模式。
- “新生代/老年代是规范强制”：错误，它们是常见收集器设计，不是 JVM 规范必须布局。
