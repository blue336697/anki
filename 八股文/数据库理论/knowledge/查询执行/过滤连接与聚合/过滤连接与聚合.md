# 过滤连接与聚合

## Filter卡
Q: Filter 算子在执行计划中有什么作用？
A:
- Filter 根据谓词判断 tuple 是否保留
- 谓词可以是比较、范围、等值、组合条件等
- 过滤越早执行，越能减少后续 Join 和 Aggregate 的输入规模
- 优化器会尝试谓词下推，把过滤推到更靠近数据源的位置
- 面试表达：过滤不是简单 where 判断，它影响整个执行计划的数据量

## Join卡
Q: 数据库常见 Join 算法如何比较？
A:
- Nested Loop Join 简单，适合小表驱动或内表有索引的场景
- Hash Join 先构建哈希表再探测，适合等值连接和较大数据集
- Sort Merge Join 先排序再归并，适合已排序输入或范围归并场景
- Join 算法选择取决于数据量、索引、内存、排序状态和连接条件
- 面试表达：Join 性能通常由连接顺序、算法选择和基数估算共同决定

## Aggregate卡
Q: 聚合算子如何执行？Hash Aggregate 和 Sort Aggregate 有什么区别？
A:
- 聚合按 group key 分组，并维护 count、sum、avg、min、max 等状态
- Hash Aggregate 用哈希表保存分组状态，通常不要求输入有序
- Sort Aggregate 先按 group key 排序，再顺序合并相邻分组
- 分组数量大或内存不足时，Hash Aggregate 可能溢写到磁盘
- 如果输入已经按 group key 有序，Sort Aggregate 可能更划算

## 正确性审查卡
Q: 过滤、连接、聚合有哪些常见误区？
A:
- “where 写在 SQL 后面就最后执行”：错误。优化器会重排逻辑执行位置
- “Hash Join 总是最快”：错误。非等值连接、内存不足或已有顺序时未必合适
- “聚合只看函数复杂度”：不完整。分组基数和内存才是关键
- “小表一定做驱动表”：通常有利，但还要结合选择率和索引
- “谓词下推没有风险”：不完整。外连接、窗口函数等场景要保持语义等价
