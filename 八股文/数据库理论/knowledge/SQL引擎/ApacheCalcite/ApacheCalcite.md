# ApacheCalcite

## 定位卡
Q: Apache Calcite 在数据库和大数据系统中扮演什么角色？
A:
- Calcite 是动态数据管理框架，提供 SQL 解析、校验、关系代数和优化能力
- 它本身不是完整数据库，不负责存储和执行所有物理任务
- 很多系统用 Calcite 作为 SQL 前端或优化器组件
- 它可以对接不同数据源，通过 Adapter 暴露统一关系模型
- 面试表达：Calcite 更像可嵌入的 SQL 优化框架，不是单机数据库内核

## 流程卡
Q: Calcite 处理一条 SQL 的大致流程是什么？
A:
- Parser 把 SQL 文本解析成 AST
- Validator 做语义校验、类型推断、表字段解析
- RelBuilder 或转换器把 AST 转成关系代数 RelNode
- Optimizer 根据规则和代价把逻辑计划改写成更优计划
- 最后由具体引擎把物理计划执行或翻译到目标系统

## 优化卡
Q: Calcite 的规则优化和代价优化如何理解？
A:
- 规则优化通过匹配模式改写计划，例如谓词下推、投影裁剪
- 代价优化为不同计划估算成本，选择较优实现
- VolcanoPlanner 支持基于规则和代价的搜索
- 统计信息质量会影响代价估算效果
- Calcite 的价值在于把通用 SQL 优化能力抽象出来供多个系统复用

## 正确性审查卡
Q: Apache Calcite 有哪些常见误区？
A:
- “Calcite 是数据库”：不准确。它不等同于完整存储引擎和执行引擎
- “接入 Calcite 就自动高性能”：错误。统计信息、规则、执行引擎同样关键
- “Parser 完就是优化器”：错误。解析、校验、关系代数转换和优化是不同阶段
- “规则越多越好”：不一定。规则搜索空间和优化耗时也要控制
- “Calcite 只能用于传统数据库”：错误。流处理、湖仓、联邦查询都可能使用
