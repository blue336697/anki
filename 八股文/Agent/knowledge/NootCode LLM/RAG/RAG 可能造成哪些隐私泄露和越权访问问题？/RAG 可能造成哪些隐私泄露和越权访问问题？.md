# RAG 可能造成哪些隐私泄露和越权访问问题？

来源：https://www.nootcode.com/problems/rag-privacy-leakage-and-unauthorized-access

## 面试直接回答卡
Q: 面试中如何直接回答“RAG 可能造成哪些隐私泄露和越权访问问题？”

A:
- RAG 的隐私和越权风险主要来自一个事实：它会把外部文档检索出来放进模型上下文。只要检索、权限、缓存、引用或日志有一环出错，模型就可能把用户本不该看到的数据生成出来。
- 常见风险包括跨租户召回、ACL 过滤遗漏、文档删除后索引未清、权限变更后缓存未失效、引用展示泄露文档标题、日志保存敏感 chunk、prompt injection 诱导模型输出检索内容。
- 例如 A 租户用户搜索“年度裁员计划”，如果共享向量库没有强制 `tenant_id=A` 过滤，就可能召回 B 租户 HR 文档；即使答案不直接粘贴全文，只总结“B 公司计划裁员 20%”也已经泄露。
- RAG 还可能发生间接泄露：用户通过多次提问推断某文档是否存在、某人是否在名单中、某项目是否被某部门访问。
- 防护上要做到检索前后 ACL、租户隔离、最小权限、敏感信息脱敏、缓存隔离、日志脱敏、引用权限校验、删除传播和审计。
- 面试里要强调：隐私保护不能靠模型自律，越权内容不应该进入模型上下文，生成后过滤只是最后兜底。

## 风险类型卡
Q: RAG 里常见隐私泄露和越权访问有哪些？

A:
- 跨租户泄露：A 租户检索到 B 租户文档。
- 角色越权：普通员工看到管理层、财务、HR 文档。
- 删除残留：文档已删除但 embedding、缓存或日志仍保留。
- 引用泄露：答案隐藏正文但暴露敏感文档标题、路径、页码。
- 日志泄露：LLM 请求、rerank 输入、评估样本保存了原文片段。
- 推断泄露：通过“是否检索到”推断某人、项目或事件存在。

## Prompt Injection 卡
Q: Prompt injection 如何放大 RAG 的隐私风险？

A:
- 攻击者可以把恶意指令写进网页、PDF、邮件或知识库文档。
- RAG 检索后，这些指令进入模型上下文，伪装成“系统提示”或“开发者消息”。
- 如果模型执行它，可能输出其他片段、调用工具或绕过回答约束。
- 正确做法是把外部内容标成非可信数据，只用于事实参考，不能作为命令。
- 工具调用和数据访问权限必须由服务端控制，不能由文档内容决定。

## 引用泄露卡
Q: 为什么引用和来源也可能泄露隐私？

A:
- 文档标题可能包含敏感信息，例如“张三绩效改进计划”。
- 文件路径可能暴露组织结构、项目代号或客户名称。
- 页码和章节名可能暗示文档内容或存在性。
- 高亮片段可能包含手机号、邮箱、身份证号、密钥等 PII。
- 因此引用展示前也要做权限校验和脱敏，而不是只校验答案正文。

## 防护卡
Q: RAG 隐私和越权风险如何防护？

A:
- 检索前使用认证身份注入租户、角色、项目空间和 ACL filter。
- 检索后再次校验 chunk 权限，防止索引层过滤失效。
- LLM 上下文只放当前用户有权访问的最小必要证据。
- 缓存按用户、角色、租户、ACL version 和 index version 隔离。
- 日志和评估数据脱敏，限制内部访问。
- 对敏感字段做识别和脱敏，对高风险操作转人工确认。

## 删除与权限变化卡
Q: 文档删除或权限变化为什么会导致隐私问题？

A:
- 删除业务文档不等于删除向量索引、关键词索引和缓存。
- 权限收回后，旧答案缓存可能仍可被访问。
- 用户离职或转岗后，历史会话上下文可能还包含旧权限下的内容。
- 重新索引延迟期间，旧权限 metadata 可能继续生效。
- 所以删除和权限变化要触发索引更新、缓存失效、会话权限重检和审计记录。

## 正确性审查卡
Q: 解释 RAG 隐私风险时有哪些误区？

A:
- 不要说“模型不会主动泄露”，模型会基于进入上下文的内容生成。
- 不要只保护答案正文，引用、缓存、日志、评估数据也要保护。
- 不要只做生成后脱敏，越权内容不应进入上下文。
- 不要忽略删除和权限变更的异步延迟。
- 不要把外部文档里的指令当命令，RAG 文档是低信任数据。
