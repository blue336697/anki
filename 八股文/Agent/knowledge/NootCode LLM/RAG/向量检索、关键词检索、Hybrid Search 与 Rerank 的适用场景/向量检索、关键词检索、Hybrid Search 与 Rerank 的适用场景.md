# 向量检索、关键词检索、Hybrid Search 与 Rerank 的适用场景

来源：https://www.nootcode.com/problems/vector-keyword-hybrid-search-rerank-scenarios

## 面试直接回答卡
Q: 面试中如何直接回答“向量检索、关键词检索、Hybrid Search 与 Rerank 的适用场景？”

A:
- 向量检索适合找语义相近的内容，关键词检索适合找精确词、编号、代码符号和专有名词，Hybrid Search 把两者召回合并，Rerank 再用更强但更贵的模型精排候选结果。
- 向量检索的优势是能处理同义改写，例如“报销餐补”能匹配“误餐补助标准”；缺点是对精确 ID、错误码、函数名、版本号不稳定。
- 关键词检索的优势是精确和可解释，例如搜 `ERR_REFUND_409`、`refund_order`、合同编号，缺点是用户换一种说法可能召回不到。
- Hybrid Search 适合企业知识库和代码/文档混合场景，因为真实问题往往既有语义意图，又有精确实体。
- Rerank 适合候选召回后再精排，比如先召回 50 个 chunk，再用 cross-encoder 或 LLM reranker 选最相关的 5 个放入上下文。
- 工程上常见做法是“高召回的 hybrid search + 高精度 rerank + 权限和版本过滤”，而不是押宝单一检索方式。

## 向量检索卡
Q: 向量检索适合什么，为什么会失败？

A:
- 适合语义相似、自然语言问答、同义改写和概念性问题。
- 典型例子：用户问“离职后社保怎么处理”，可以匹配“员工离职社保停缴流程”。
- 失败点是精确实体弱，例如订单号、错误码、API 字段、类名和版本号可能被语义相近内容干扰。
- 向量相似度常用 cosine similarity：`cos(a,b)=a·b/(||a||·||b||)`，它衡量方向相近，不保证事实相关。
- 所以向量分数高只能说明 embedding 空间接近，不等于证据一定能回答问题。

## 关键词检索卡
Q: 关键词检索适合什么，为什么不能单独依赖它？

A:
- 适合精确匹配：错误码、合同号、API 名、函数名、人名、字段名、法规条款号。
- 典型例子：用户问 `HTTP 429` 或 `q4_K_M`，关键词匹配通常比向量更直接。
- 它可解释性强，命中词能展示给用户或用于调试。
- 缺点是召回依赖字面词，用户说“限流了”而文档写“请求频率超限”时可能漏召回。
- 对中文、英文、缩写、同义词和分词质量也比较敏感。

## Hybrid Search 卡
Q: Hybrid Search 为什么常用于生产 RAG？

A:
- 它把向量召回的语义覆盖和关键词召回的精确匹配结合起来。
- 用户问题里可能同时包含“语义意图 + 精确实体”，例如“退款接口 ERR_409 怎么处理”。
- 向量检索负责找到“退款冲突处理”相关文档，关键词检索保证 `ERR_409` 不丢。
- 合并时可以用 RRF：`score(d)=Σ 1/(k + rank_i(d))`，按多个排序列表的名次融合。
- Hybrid 的目标通常是提高召回率，后面还需要 rerank 提升排序精度。

## Rerank 卡
Q: Rerank 解决什么问题？和检索有什么区别？

A:
- 第一阶段检索追求快和召回广，rerank 追求更准确地判断候选是否能回答问题。
- Reranker 通常同时看 query 和文档片段，比单独向量相似度更能理解细粒度匹配。
- 例如 query 问“退款重试间隔”，候选里有“支付重试间隔”和“退款错误码”，reranker 应把真正包含退款重试规则的片段排前。
- 代价是计算更贵，所以通常只对前几十或几百个候选做精排。
- Rerank 不能找回第一阶段完全漏掉的文档，因此前置召回仍然重要。

## 工程实践卡
Q: 如何选择检索策略？

A:
- FAQ 和自然语言知识库：向量检索 + rerank 通常有效。
- API 文档、日志、代码仓库：关键词/BM25 和结构化检索权重更高。
- 企业综合知识库：优先 hybrid search，再加 rerank。
- 高风险答案：宁可少量高置信证据，也不要大量低相关片段。
- 查询中包含 ID、错误码、版本号、函数名时，应提高关键词和精确过滤权重。

## 正确性审查卡
Q: 解释检索策略时有哪些误区？

A:
- 不要说向量检索一定比关键词检索高级，精确实体场景关键词更可靠。
- 不要把 rerank 当召回，它只能重排已有候选。
- 不要只看相似度分数，分数阈值会受 embedding 模型、语料和归一化影响。
- 不要忽略权限、版本和来源过滤，这些过滤通常应在 rerank 前后都参与。
- 不要让检索策略脱离内容类型，代码、表格、PDF 和普通文本的最佳方案不同。
