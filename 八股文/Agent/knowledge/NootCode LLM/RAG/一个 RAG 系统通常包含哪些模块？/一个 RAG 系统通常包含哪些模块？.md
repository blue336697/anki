# 一个 RAG 系统通常包含哪些模块？

来源：https://www.nootcode.com/problems/rag-system-modules

## 面试直接回答卡
Q: 面试中如何直接回答“一个 RAG 系统通常包含哪些模块？”

A:
- 一个完整 RAG 系统通常分成离线建库链路和在线问答链路。离线链路负责把文档变成可检索、可权限控制、可追溯的索引；在线链路负责理解用户问题、检索证据、生成答案和做校验。
- 离线模块包括文档接入、解析清洗、切分 chunk、元数据抽取、embedding、向量/关键词索引、权限标签、版本和删除同步。
- 在线模块包括 query rewrite、权限过滤、检索、hybrid search、rerank、上下文组装、prompt 构造、LLM 生成、引用展示、答案校验和日志评估。
- 例如企业知识库问答不是把 PDF 丢进向量库就结束，还要保留页码、标题层级、更新时间、租户 ID、ACL、chunk ID，否则答案无法验证，也容易越权。
- 生产级 RAG 还需要监控和反馈闭环：记录问题、召回片段、模型答案、用户反馈、失败类型，并用这些数据优化切分、检索和 rerank。
- 所以回答这题要讲清楚“数据怎么进来、怎么被检索、怎么进入上下文、答案怎么被验证、文档变化怎么同步”。

## 离线建库卡
Q: RAG 的离线建库链路通常有哪些步骤？

A:
- 文档接入：接收 PDF、网页、Markdown、数据库记录、代码仓库等来源。
- 解析清洗：抽取正文、标题、表格、图片 OCR、代码结构，去掉导航和广告噪声。
- 切分 chunk：按语义、章节、表格行列、代码符号等方式切分。
- 元数据抽取：记录文档 ID、来源、作者、版本、更新时间、页码、权限标签。
- 表征与索引：生成 embedding，同时建立关键词索引或结构化索引。
- 生命周期管理：处理更新、删除、重建索引和索引状态。

## 在线检索卡
Q: RAG 的在线问答链路通常有哪些步骤？

A:
- 解析用户问题，必要时改写 query、补全上下文或拆成子问题。
- 根据用户身份、租户、角色做权限过滤。
- 用向量检索、关键词检索或 hybrid search 召回候选 chunk。
- 用 reranker、业务规则、版本规则对候选证据重新排序。
- 对证据去重、压缩、合并，并按上下文窗口预算组装。
- 把证据和引用标识交给 LLM 生成答案，再做校验和展示。

## 元数据卡
Q: 为什么 RAG 不能只存 chunk 文本和向量？

A:
- 没有文档 ID 和 chunk ID，就无法追溯答案来自哪里。
- 没有页码、标题层级和表头，引用无法让用户验证。
- 没有租户、角色、ACL，检索结果可能越权。
- 没有版本和更新时间，旧文档可能覆盖新规则。
- 没有来源可信度，模型可能把草稿、论坛、正式制度混为一谈。

## 引用与校验卡
Q: RAG 生成后还需要哪些校验模块？

A:
- 格式校验：输出是否符合 JSON、Markdown 或 UI 展示要求。
- 引用校验：每个关键结论是否有对应 chunk 支持。
- 敏感信息校验：是否泄露不该展示的手机号、密钥、内部字段。
- 冲突检测：多个证据是否版本不同或结论相互矛盾。
- 失败兜底：证据不足时输出“不确定”或转人工，而不是编造。

## 监控闭环卡
Q: RAG 系统为什么需要日志和评估闭环？

A:
- 仅看最终答案很难定位问题来自检索还是生成。
- 日志应记录 query、用户权限、召回 chunk、分数、rerank 结果、prompt 摘要、答案和引用。
- 失败样本可以反推切分策略、同义词表、reranker、top-k 和 prompt 约束。
- 用户反馈可以分为“没找到文档”“答案不对”“引用不对”“权限问题”等标签。
- 没有闭环，RAG 很容易停留在 demo 效果，难以稳定运营。

## 正确性审查卡
Q: 解释 RAG 系统模块时有哪些误区？

A:
- 不要把 RAG 简化成“向量库 + LLM”，生产系统还需要权限、版本、引用和评估。
- 不要只讲在线链路，离线解析、切分和索引质量决定召回上限。
- 不要忽略删除和权限变化，索引里的旧数据也会造成泄露。
- 不要让模型自己补齐缺失证据，证据不足要有明确失败路径。
- 不要只优化 embedding，相邻模块如 rerank、query rewrite、chunk metadata 同样关键。
