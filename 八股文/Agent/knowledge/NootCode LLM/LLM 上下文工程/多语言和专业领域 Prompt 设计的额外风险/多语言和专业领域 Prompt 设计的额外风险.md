# 多语言和专业领域 Prompt 设计的额外风险

来源：https://www.nootcode.com/problems/multilingual-domain-specific-prompt-risks

## 面试直接回答卡
Q: 面试中如何直接回答“多语言和专业领域 Prompt 设计有哪些额外风险？”

A:
- 多语言和专业领域 prompt 的风险在于：同一句指令在不同语言、文化、术语体系里可能不等价，模型还可能把专业词误翻译、误归类或用通用常识替代领域规则。
- 多语言场景要关注语言切换、术语一致性、分词/token 成本、地区合规和翻译歧义。比如中文“风控通过”不能简单翻成 “risk control passed”，在英文业务系统里可能需要映射成具体状态码。
- 专业领域场景要关注权威来源、版本、单位、边界和责任。例如医疗、法律、金融、运维里，一个词用错可能导致严重后果。
- 工程上不能只让模型“用专业语气回答”，而要提供术语表、字段映射、单位规范、来源引用、专业校验和人工审核。
- 面试总结：多语言和专业 prompt 的核心不是语言更漂亮，而是语义、术语、单位、法规和业务状态必须可验证地一致。

## 多语言风险卡
Q: 多语言 prompt 有哪些常见风险？

A:
- 翻译歧义：同一词在不同上下文含义不同。
- 术语不一致：同一业务概念多种翻译。
- 文化差异：礼貌、拒绝、风险提示表达不同。
- token 成本差异：不同语言的 tokenization 效率不同。
- 混合语言输入：用户中英混杂，模型可能错误切换语言或术语。

## 专业领域风险卡
Q: 专业领域 prompt 有哪些常见风险？

A:
- 模型用通用解释替代领域规范。
- 术语、单位、版本、法规边界错误。
- 把建议说成诊断、结论或法律意见。
- 忽略上下游系统字段含义。
- 没有引用权威来源或最新政策。

## 具体例子卡
Q: 举例说明专业术语错误的风险。

A:
- 金融风控里 “chargeback” 可能涉及拒付流程，不只是普通退款。
- 如果模型把它翻成“退款”，可能走错业务流程。
- 正确做法是维护术语表：`refund=商户主动退款`，`chargeback=持卡人争议拒付`。
- 输出时应保留原术语或映射到内部标准字段。
- 高风险结论应由业务规则和人工审核确认。

## 可追问原理卡
Q: 为什么多语言会影响 token 和上下文成本？

A:
- Tokenizer 对不同语言切分效率不同。
- 同样语义的中文、英文、混合文本 token 数可能不同。
- 专业术语、代码、数字、标点会进一步影响 token 数。
- 多语言 prompt 如果同时放原文、译文、术语表，会消耗更多上下文窗口。
- 因此多语言系统要控制术语表长度、检索范围和输出预算。

## 工程实践卡
Q: 如何降低多语言和专业 prompt 风险？

A:
- 维护术语表和字段映射，不让模型自由翻译关键术语。
- 使用权威来源和版本化政策文档。
- 对金额、单位、时间、法律条款做程序校验。
- 高风险领域输出加免责声明、引用和人工审核。
- 对多语言样本建立评测集，覆盖混合语言、缩写和歧义表达。

## 正确性审查卡
Q: 解释多语言和专业 prompt 时有哪些误区？

A:
- 不要认为“让模型用某语言回答”就完成本地化。
- 不要让模型自由翻译业务状态码和专业术语。
- 不要把专业语气当成专业正确性。
- 不要忽略单位、时区、法律辖区和版本差异。
- 不要在高风险领域让模型直接给最终结论。
