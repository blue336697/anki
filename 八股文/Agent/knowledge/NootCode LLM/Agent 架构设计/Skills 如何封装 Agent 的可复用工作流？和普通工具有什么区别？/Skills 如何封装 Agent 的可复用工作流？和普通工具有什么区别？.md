# Skills 如何封装 Agent 的可复用工作流？和普通工具有什么区别？

来源：https://www.nootcode.com/problems/agent-skills-reusable-workflows

## 面试直接回答卡
Q: 面试中如何直接回答“Skills 如何封装 Agent 的可复用工作流？和普通工具有什么区别？”

A:
- Skill 可以理解为给 Agent 使用的一套可复用能力包，它封装的不只是一个 API 调用，而是一段完成某类任务的方法、约束、步骤、模板、脚本、示例和领域知识。
- 普通工具更像原子能力，例如 `search_docs(query)`、`send_email(to, body)`、`run_sql(sql)`；Skill 更像“如何可靠完成一类任务”，例如“生成 Anki 牌组”“修复前端视觉问题”“做代码审查”。
- Skill 可以告诉 Agent 何时使用、先读哪些资料、按什么步骤执行、用哪些脚本、如何验收结果、常见坑是什么。
- 例如一个“生成 Anki 卡片”的 skill 不只是调用写文件工具，还包含卡片结构、目录规范、APKG 生成脚本、复杂度写法、图片处理和验收检查。
- 但 Skill 不是权限系统，也不是安全兜底。Skill 可以指导模型怎么做，真正的文件写入、工具调用、发布、删除等动作仍要由工具 schema、权限、审计和人工确认控制。
- 面试里可以总结：工具是“能做什么”，Skill 是“如何把一组工具和知识组织成可靠工作流”。

## 对比卡
Q: Skill 和普通工具的关键区别是什么？

A:
- 粒度不同：工具是原子动作，Skill 是可复用流程。
- 内容不同：工具主要是接口 schema，Skill 还包含步骤、策略、模板、示例和验收标准。
- 生命周期不同：工具关注调用成功，Skill 关注任务完成质量。
- 组合方式不同：一个 Skill 可以使用多个工具、文件、脚本和外部资料。
- 风险不同：Skill 提供指导，但不应绕过工具权限和执行层控制。

## 组成卡
Q: 一个好的 Skill 通常包含什么？

A:
- 触发条件：什么任务应该使用它，什么任务不该使用它。
- 工作流步骤：先读什么、再执行什么、如何处理异常。
- 资源和模板：脚本、示例、格式规范、评估清单。
- 领域约束：目录结构、命名规则、质量标准、安全边界。
- 验收方法：如何检查输出是否完整、正确、可运行。
- 失败处理：缺少输入、工具失败、权限不足时如何降级。

## 例子卡
Q: 用一个例子说明 Skill 比工具多了什么。

A:
- 工具：`write_file(path, content)` 只能写文件。
- Skill：`anki-apkg-generator` 会说明八股文卡片如何拆知识点、每个知识点几张卡、正确性审查怎么写、APKG 输出到哪里。
- Agent 使用 Skill 后，不只是“能写 md”，而是知道应该写成哪些卡、如何校验、何时生成 APKG。
- 工具解决动作，Skill 解决任务方法论和质量约束。
- 这能减少每次从零写 prompt 的成本，也让不同 Agent 执行同类任务更一致。

## 工程实践卡
Q: Skill 在 Agent 系统中如何治理？

A:
- Skill 要版本化，避免流程变化后旧任务不可复现。
- Skill 要有适用范围和禁用范围，避免误触发。
- Skill 内引用的脚本和模板要可测试，不能只靠自然语言描述。
- 高风险 Skill 仍要走工具权限、审批和审计。
- 记录每次任务使用了哪个 Skill、版本和关键参数，便于复盘。

## 边界卡
Q: Skill 有哪些边界？

A:
- Skill 不能保证模型一定正确执行，仍需要校验和测试。
- Skill 不能替代工具 schema，参数类型和权限必须结构化。
- Skill 不能替代业务规则，强约束规则要用代码或策略引擎。
- Skill 太宽泛会变成大 prompt，难维护、难评估。
- Skill 太细碎又会增加选择成本，应围绕稳定高频任务封装。

## 正确性审查卡
Q: 解释 Skill 时有哪些误区？

A:
- 不要把 Skill 等同于普通函数调用，它封装的是流程和知识。
- 不要把 Skill 当成安全边界，真正权限在工具和服务端。
- 不要让 Skill 包含过时流程，版本和回归测试很重要。
- 不要为了复用而过度抽象，低频一次性任务不一定需要 Skill。
- 不要忽略验收标准，Skill 的价值是稳定完成任务，而不只是调用工具。
