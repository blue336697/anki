# 什么是 Agent？它和单次 LLM 调用、固定工作流有什么区别？

来源：https://www.nootcode.com/problems/what-is-agent

## 面试直接回答卡
Q: 面试中如何直接回答“什么是 Agent？它和单次 LLM 调用、固定工作流有什么区别？”

A:
- Agent 可以理解为围绕一个目标持续感知、决策、调用工具、观察结果并更新状态的系统。它不是一次 prompt 得到一次回答，而是一个带循环和状态的执行体。
- 单次 LLM 调用通常是“输入上下文，输出文本或一次工具调用”，没有持续任务状态，也不会自己决定下一步。
- 固定工作流是开发者预先写好的步骤，例如先查订单、再算金额、再发通知，流程确定，模型最多填参数或生成文本。
- Agent 的区别在于步骤不完全固定，它可以根据中间观察动态决定下一步，例如先搜索资料、发现缺权限后请求授权、再改用另一个工具、最后汇总结果。
- 但 Agent 不是“让模型自由发挥”。生产级 Agent 必须有工具白名单、权限校验、预算、停止条件、人工确认、审计日志和可恢复状态。
- 面试里可以总结为：Agent = LLM 决策能力 + 工具执行能力 + 任务状态 + 控制循环 + 工程护栏。

## 核心组成卡
Q: 一个 Agent 通常由哪些核心部分组成？

A:
- Goal：任务目标，例如“帮用户完成退款排查”。
- State：任务状态，包括历史步骤、已拿到的信息、计划、工具结果、错误和预算。
- Policy/Planner：决定下一步做什么，可以是模型、规则或二者结合。
- Tools：可调用的外部能力，例如检索、数据库、浏览器、代码执行、发邮件。
- Observation：工具返回的事实结果，供下一轮决策使用。
- Control：停止条件、权限、成本限制、人工确认、审计和回滚。

## 对比卡
Q: Agent 和单次 LLM 调用有什么区别？

A:
- 单次调用通常只有一次输入输出，Agent 有多轮 action/observation 循环。
- 单次调用主要生成文本，Agent 可以改变外部状态或持续推进任务。
- 单次调用上下文主要在请求里，Agent 需要持久化任务状态。
- 单次调用失败通常返回错误，Agent 可能重试、换工具、澄清或降级。
- 单次调用更可控、更便宜，Agent 更灵活但风险和工程复杂度更高。

## 对比卡
Q: Agent 和固定工作流有什么区别？

A:
- 固定工作流的步骤由代码预定义，适合确定性业务流程。
- Agent 的步骤可以根据中间结果动态变化，适合开放式、多路径、信息不完整的任务。
- 固定工作流可测试性强、成本稳定、风险低。
- Agent 能处理更多异常分支，但需要更强的监控和边界。
- 强约束业务逻辑应优先用固定工作流，Agent 可负责解释、检索、辅助判断和异常处理。

## 例子卡
Q: 举例说明 Agent 相比普通 LLM 调用多了什么能力。

A:
- 用户说：“帮我查这个报错为什么线上只在晚上出现。”
- 单次 LLM 只能根据已有日志猜测原因。
- Agent 可以先查监控指标，再检索发布记录，再看定时任务，再对比白天和夜间流量。
- 如果发现日志权限不足，它可以请求授权或提示用户上传片段。
- 最终答案不仅是文本，还能附上证据、执行过的检查步骤和下一步建议。

## 边界卡
Q: 哪些场景不适合直接用 Agent？

A:
- 业务流程高度确定，例如付款扣款、库存扣减、权限审批，核心判断应由代码和规则系统执行。
- 动作不可逆或高风险，例如删除数据、转账、发布生产配置，需要人工确认和审批。
- 任务目标模糊且没有可验证反馈，Agent 容易无限探索。
- 成本和延迟必须稳定的接口，Agent 多步循环可能超预算。
- 工具结果不可验证或权限体系薄弱时，Agent 容易做出错误动作。

## 正确性审查卡
Q: 解释 Agent 时有哪些误区？

A:
- 不要把 Agent 等同于“一个更长的 prompt”，核心是循环、状态、工具和控制。
- 不要说 Agent 一定比固定工作流好，确定性流程通常更适合代码。
- 不要把工具结果当指令，工具结果是观察数据，不应覆盖系统和开发者规则。
- 不要让模型自由决定高风险动作，权限和审批必须在执行层兜底。
- 不要忽略停止条件，没有预算和终止策略的 Agent 很容易循环和失控。
