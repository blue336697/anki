# Agent 什么时候应该继续行动，什么时候应该停止、失败或请求人工确认？

来源：https://www.nootcode.com/problems/agent-continue-stop-fail-human-confirmation

## 面试直接回答卡
Q: 面试中如何直接回答“Agent 什么时候应该继续行动，什么时候应该停止、失败或请求人工确认？”

A:
- Agent 的继续、停止、失败和人工确认不应该完全交给模型临场判断，而应该由状态机、风险策略、预算和验收标准共同决定。
- 可以继续行动的条件是：目标仍明确，下一步动作在权限和工具白名单内，预计能带来新信息或推进状态，且没有超过时间、token、成本、步骤和重试预算。
- 应该停止的条件是：目标已满足，验收标准通过，继续行动没有新增价值，或者用户请求只需要当前结果。
- 应该失败的条件是：必要工具不可用、权限不足、关键输入缺失、连续重试仍失败、证据冲突无法消解，且没有安全替代路径。
- 应请求人工确认的条件是：动作不可逆、高成本、涉及隐私或资金、会影响生产环境、用户意图不明确但后果严重，或模型置信度不足。
- 面试里要强调：Agent 停止策略和安全策略是架构的一部分，不是 prompt 末尾写一句“完成后停止”。

## 继续行动卡
Q: Agent 满足什么条件可以继续行动？

A:
- 当前目标和子目标明确，没有关键歧义。
- 下一步动作是低风险、可逆或只读动作。
- 工具调用在白名单内，参数通过 schema 和权限校验。
- 上一步 observation 带来了新的信息或改变了状态。
- 当前预算、重试次数和最大步数尚未超过阈值。

## 停止卡
Q: Agent 什么时候应该停止？

A:
- 用户目标已经完成，验收标准已满足。
- 已拿到足够证据，可以给出可靠答案。
- 继续检索或调用工具只会增加成本，不会显著提高质量。
- 遇到无答案场景，并且已经完成必要检索和说明。
- 用户明确要求只做某一步，不应擅自扩展任务。

## 失败卡
Q: Agent 什么时候应该显式失败？

A:
- 必要工具不可用，且没有替代工具。
- 用户没有权限，权限系统返回拒绝。
- 输入缺失且用户不补充时无法继续。
- 连续重试后仍得到同类错误。
- 证据冲突且无法按版本、来源或权限规则判断。
- 失败时应返回原因、已完成步骤和可恢复建议。

## 人工确认卡
Q: Agent 什么时候必须请求人工确认？

A:
- 动作不可逆，例如删除数据、提交审批、发布配置。
- 动作涉及资金、隐私、法律、生产环境或外部发送。
- 模型需要在多个高风险方案中做取舍。
- 用户指令模糊但执行后果严重。
- 工具结果和用户陈述冲突，且继续执行可能造成损失。
- 确认界面应展示动作、参数、影响范围和可回滚性。

## 例子卡
Q: 用一个例子说明 continue/stop/fail/human 的区别。

A:
- 用户让 Agent 排查接口超时。
- Continue：先查监控、日志、发布记录，这些是只读且能带来新信息。
- Stop：发现超时由某版本发布导致，证据充分，生成报告即可。
- Fail：日志系统不可用，监控也无权限，无法继续验证。
- Human：如果要回滚生产版本，必须请求人工确认，不能自动执行。

## 正确性审查卡
Q: 解释 Agent 行动边界时有哪些误区？

A:
- 不要让模型自己无限判断“还可以继续”，要有硬预算和状态机。
- 不要把失败都包装成继续尝试，连续重试会浪费成本并掩盖问题。
- 不要把人工确认只做成口头提示，高风险动作应在工具网关强制拦截。
- 不要因为用户催促就绕过权限和审批。
- 不要忽略部分完成，失败时也应返回已完成步骤和可恢复状态。
