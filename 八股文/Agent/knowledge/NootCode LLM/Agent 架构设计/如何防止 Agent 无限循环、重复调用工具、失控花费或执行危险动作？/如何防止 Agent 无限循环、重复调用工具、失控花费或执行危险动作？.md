# 如何防止 Agent 无限循环、重复调用工具、失控花费或执行危险动作？

来源：https://www.nootcode.com/problems/agent-loop-cost-safety-controls

## 面试直接回答卡
Q: 面试中如何直接回答“如何防止 Agent 无限循环、重复调用工具、失控花费或执行危险动作？”

A:
- 防止 Agent 失控要靠多层控制，而不是只靠 prompt 里写“不要循环”。核心是预算控制、状态去重、工具权限、风险分级、人工确认、审计和可中断执行。
- 无限循环通常来自目标不清、没有停止条件、工具结果无法改变状态或模型反复尝试同一动作。系统应设置最大步数、最大时间、最大 token、最大费用、最大重试次数和无进展检测。
- 重复调用工具要靠 action signature 去重，例如同一工具、同一参数、同一状态下重复调用就阻断或复用缓存。
- 危险动作要做工具分级：只读工具可自动调用，低风险写操作需要幂等和回滚，高风险写操作需要人工确认或审批。
- 失控花费要有 per-task、per-user、per-tenant 的预算和限流，超过阈值自动暂停并说明当前进度。
- 生产级 Agent 的安全性来自执行网关和状态机，模型负责提出下一步，系统负责决定是否允许执行。

## 循环控制卡
Q: 如何识别和阻断 Agent 无限循环？

A:
- 设置硬限制：最大步骤数、最大耗时、最大 token、最大费用。
- 检测无进展：连续几步没有新 observation、状态没有变化、答案质量没有提高。
- 检测重复动作：相同工具和参数在相同状态下反复调用。
- 检测语义重复：模型反复搜索同一 query 或换词搜索同一目标。
- 触发后停止、总结已做步骤，并请求用户补充信息或人工介入。

## 工具去重卡
Q: 如何防止 Agent 重复调用同一个工具？

A:
- 为每次工具调用生成 action signature：工具名、规范化参数、目标对象、任务状态版本。
- 相同 signature 已成功时直接复用结果。
- 相同 signature 已失败时按错误类型决定是否重试。
- 对写操作使用 idempotency key，避免重复提交。
- 对高成本工具设置 cooldown 和并发限制。

## 成本控制卡
Q: 如何防止 Agent 失控花费？

A:
- 设置任务级预算：token、工具调用次数、外部 API 成本、运行时间。
- 设置用户和租户级限流，防止单用户拖垮系统。
- 对高成本工具做显式成本预估和确认。
- 长任务分阶段汇报，让用户决定是否继续。
- 日志记录每步成本，便于计费、告警和优化。

## 危险动作卡
Q: 如何防止 Agent 执行危险动作？

A:
- 工具按风险分级：只读、低风险写、高风险写、不可逆动作。
- 只给当前任务暴露最小必要工具，避免工具过载。
- 服务端做权限校验，用户和模型都不能伪造权限。
- 高风险动作要求人工确认，确认内容包括参数、影响范围和回滚方案。
- 对写操作加入 dry-run、幂等键、审批、审计和回滚。

## 例子卡
Q: 举例说明如何阻断失控 Agent。

A:
- Agent 连续 5 次搜索“退款失败原因”，每次只换了近义词。
- 系统发现 query 语义重复，且没有新证据进入状态。
- 触发无进展规则，停止搜索并提示：“已检索退款日志、风控记录和订单状态，仍缺少错误码。”
- 如果下一步要批量重试退款，工具网关要求人工确认和幂等键。
- 这样既避免了循环，也避免了高风险动作自动执行。

## 正确性审查卡
Q: 解释 Agent 安全控制时有哪些误区？

A:
- 不要只靠 prompt 控制循环，必须有执行层硬限制。
- 不要把所有工具暴露给 Agent，工具集越大越容易误调用。
- 不要把写操作和只读操作同等对待，风险分级是必要的。
- 不要只记录最终答案，审计需要每一步 action 和 observation。
- 不要让模型决定自己是否有权限，权限来自服务端认证和授权系统。
