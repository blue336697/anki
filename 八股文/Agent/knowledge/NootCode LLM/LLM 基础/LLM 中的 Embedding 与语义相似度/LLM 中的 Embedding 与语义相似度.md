# LLM 中的 Embedding 与语义相似度

来源：https://www.nootcode.com/problems/llm-embeddings-and-semantic-similarity

## 面试直接回答卡
Q: 面试中如何直接回答“Embedding 和语义相似度是什么？”

A:
- Embedding 是把文本、图片或其他对象映射成高维向量，让语义可以用数学方式计算。语义接近的内容在向量空间里通常距离更近，比如“退钱没到账”和“退款到账延迟”可能比字面完全相同的无关句子更接近。
- 在 RAG 里，通常会先把文档切成 chunk，用 embedding 模型转成向量并写入向量库；用户问题也转成向量后，系统按相似度召回 top-k 片段，再做过滤、rerank 和生成。
- 但 embedding 检索不是关键词检索的完全替代。向量检索擅长同义表达和语义泛化，关键词检索更擅长错误码、接口名、版本号、配置 key、数字等精确匹配，所以生产系统常做 hybrid search。
- 还要强调边界：相似不等于相关，相关也不等于正确。召回片段可能过期、无权限或不能回答当前问题。
- 工程上要关注切分策略、元数据、权限过滤、更新时间、评测集和索引重建，不能把“向量库”直接等同于完整 RAG 系统。

## 概念卡
Q: Embedding 是什么，为什么能用于语义相似度？

A:
- Embedding 是把文本、图片或其他对象映射为高维向量的表示。
- 语义相近的内容通常在向量空间中距离更近，例如“退钱没到账”和“退款到账延迟”。
- 常见相似度计算包括余弦相似度、点积和欧氏距离，具体取决于模型和索引配置。
- Embedding 常用于语义检索、聚类、去重、推荐、RAG 召回和相似问题匹配。
- 面试一句话：Embedding 把非结构化语义转成可计算向量，但它不是事实正确性的保证。

## 机制拆解卡
Q: 基于 Embedding 的语义检索流程是什么？

A:
1. 文档清洗与切分：按标题、段落、表格、代码块或业务结构切 chunk。
2. 向量化：用 embedding 模型把每个 chunk 转成向量。
3. 建索引：把向量、文档 id、来源、更新时间、权限、标签写入向量库。
4. 查询向量化：用户问题也转成向量。
5. 相似度召回：找 top-k 近邻。
6. 过滤与 rerank：按权限、时间、业务线过滤，再用重排模型提升相关性。

## 相似度公式卡
Q: 语义相似度常见的 cosine similarity 怎么算？

A:
- 文本 A 和文本 B 会先被 embedding 模型转成向量 `a` 和 `b`。
- cosine similarity 公式是 `cos(a,b) = (a · b) / (||a|| × ||b||)`。
- 分子 `a · b` 表示两个向量方向上的重合程度。
- 分母把向量长度归一化，避免仅仅因为某个向量模长更大就显得更相似。
- 值越接近 1，方向越接近，通常表示语义越相似；但这只代表向量空间相似，不代表事实正确。

## 具体例子卡
Q: 为什么语义相似不等于能回答问题？

A:
- 用户问“订单 123 为什么退款失败”，向量检索可能召回“退款失败常见原因”文档。
- 这个文档语义相关，但它不能说明订单 123 的真实支付流水、风控状态和退款网关返回码。
- 真正回答还需要订单数据库、支付日志、权限校验和最新状态。
- 所以 RAG 里 embedding 负责召回候选上下文，不负责证明事实。
- 面试追问时要强调：相似度解决“可能相关”，事实正确还要靠数据源和校验。

## 对比追问卡
Q: Embedding 检索和关键词检索有什么区别？

A:
- Embedding 擅长语义泛化，能匹配“退款失败”和“退钱没到账”这类同义表达。
- 关键词检索擅长精确术语，适合 HTTP 504、配置 key、接口名、版本号、错误码。
- 纯向量检索可能把语义相近但不能回答问题的片段召回。
- 纯关键词检索可能漏掉同义改写和自然语言问题。
- 企业 RAG 常用 hybrid search：关键词保证精确，向量保证语义召回，再用 rerank 排序。

## 边界与误区卡
Q: Embedding 有哪些局限？

A:
- 相似不等于相关：文本主题接近，不代表能回答当前问题。
- 相关不等于正确：召回文档可能过期、错误或无权限。
- 数字、否定、时间、版本、代码符号等精确信息，纯 embedding 可能弱。
- chunk 切得太碎会丢上下文，切得太大又会引入噪声。
- 换 embedding 模型通常需要重建索引，因为向量空间变了。

## 工程实践卡
Q: 如何提升 Embedding 检索质量？

A:
- 按内容结构切分，不要只按固定字符数粗暴切。
- 保留元数据：来源、更新时间、权限、业务线、文档类型、标题路径。
- 做混合检索和 rerank，而不是只靠向量距离。
- 建真实评测集，评估 recall、precision、MRR、引用正确率。
- 对权限和敏感数据先过滤再入上下文，避免模型看到不该看的材料。

## 正确性审查卡
Q: 解释 Embedding 时要避免哪些说法？

A:
- “向量距离近就答案正确”：错误，它只是表示空间中的相似度。
- “向量库就是 RAG”：不完整，RAG 还包括切分、权限、检索、rerank、生成、引用和评估。
- “top-k 越大越好”：不一定，过大会增加噪声和成本。
- “Embedding 能替代数据库查询”：不适合精确事实、事务状态和权限判断。
- “模型会自己处理权限”：错误，权限必须在检索和上下文注入前处理。
