# LLM 多次运行为何会产生不同的输出

来源：https://www.nootcode.com/problems/llm-output-variance-across-runs

## 面试直接回答卡
Q: 面试中如何直接回答“为什么同一 prompt 多次运行会得到不同输出？”

A:
- LLM 生成不是天然确定性函数。模型每一步会计算下一个 token 的概率分布，如果使用 sampling，就可能从多个候选 token 中抽到不同结果。
- 一旦早期某个 token 不同，后续上下文就改变了，后面每一步的概率分布也会随之变化，所以两个回答可能从一个小差异逐渐变成不同结构。
- Greedy decoding 每步选概率最高的 token，通常更稳定；temperature、top-p、top-k 放得越开，sampling 的多样性越强，输出差异也越明显。
- 除了解码随机性，实际输入也可能不同：历史对话被裁剪、RAG 召回片段变化、工具结果变化、系统提示词或模型版本变化，都会改变输出。
- 生产系统如果要求稳定，要固定 prompt、上下文、参数、模型版本和工具结果，并用 schema、parser、测试或人工确认控制关键输出。

## 核心原因卡
Q: 为什么同一个提示词多次调用 LLM 可能得到不同输出？

A:
- 模型每一步会给出下一个 token 的概率分布，如果使用 sampling，就可能从多个候选中抽到不同 token。
- 一旦早期 token 不同，后续上下文也不同，后面每一步的概率分布都会变化。
- Temperature、top-p、top-k 越放宽，多样性通常越高，输出差异也越明显。
- 即使使用低随机性，实际输入也可能不同，例如历史被裁剪、检索片段顺序变化、工具结果变化。
- 因此 LLM 输出要按概率系统管理，而不是默认同输入必然同输出。

## 机制拆解卡
Q: 输出差异来自哪些层面？

A:
- 解码层：greedy 每步选最高概率，sampling 按概率抽样。
- 参数层：temperature、top-p、top-k、max tokens、stop sequence 影响生成路径。
- 输入层：系统提示词、上下文窗口、历史摘要、RAG 片段、工具结果可能变化。
- 服务层：模型版本、部署策略、并发和内容过滤策略可能变化。
- 后处理层：格式修复、重试、审核和降级策略会改变最终输出。

## 举例卡
Q: 早期 token 差异如何放大成不同答案？

A:
- 用户问“如何优化 RAG 检索质量”，第一次模型开头写“首先要优化文档切分”，后续会围绕 chunk、元数据、rerank 展开。
- 第二次模型开头写“首先要建立评测集”，后续可能围绕指标、标注、线上反馈展开。
- 两个答案都可能合理，但因为早期 token 选择不同，整条回答路径不同。
- 如果早期 token 走偏，例如把 RAG 误解成 fine-tuning，后续会持续沿错误方向生成。
- 所以关键任务要靠约束和校验把生成路径拉回目标。

## 概率分叉卡
Q: 为什么一个小 token 差异会让后续答案越来越不同？

A:
- 假设回答第一个 token 时，模型给“首先”概率 0.42，给“核心”概率 0.35。
- 第一次采样选到“首先”，后续上下文变成“首先...”，模型可能继续生成步骤型答案。
- 第二次采样选到“核心”，后续上下文变成“核心...”，模型可能继续生成概念总结型答案。
- 因为每一步的概率分布都条件依赖已经生成的 token，早期分叉会改变后续所有分布。
- 这就是为什么同一个 prompt 的差异不是孤立词语变化，而可能演变成结构、重点和结论的变化。

## 控制策略卡
Q: 如何降低输出不稳定性？

A:
- 降低随机性：使用较低 temperature、较窄 top-p，必要时使用 greedy。
- 固定输入：控制 prompt 模板、上下文顺序、检索 top-k、工具返回格式。
- 结构化输出：用 schema、函数调用、枚举和 parser 校验。
- 版本记录：记录模型版本、prompt 版本、采样参数、检索结果和工具调用。
- 高风险场景：不要把模型自由输出直接作为执行依据，要交给规则、程序或人工确认。

## 边界与误区卡
Q: 输出差异有哪些常见误区？

A:
- “同样 prompt 一定同样答案”：不成立，除非系统明确提供并满足确定性条件。
- “temperature=0 绝对一致”：不严谨，服务端实现和版本变化仍可能影响。
- “不一致就是质量差”：开放式创意任务中多样性可能是优势。
- “多跑几次投票一定更准”：不一定，可能放大共同偏差并增加成本。
- “只固定用户问题就能复现”：不够，还要固定上下文、工具结果、参数和版本。

## 正确性审查卡
Q: 生产系统如何看待 LLM 输出差异？

A:
- 对创意任务接受差异，但要定义安全和质量边界。
- 对结构化抽取、SQL、代码、客服政策回复，要尽量压低差异并做校验。
- 对评测实验，要固定输入、参数和版本，否则结果抖动无法比较。
- 对线上问题，要有可追踪日志，能复盘当时模型看到了什么。
- 对强约束决策，模型输出只能作为候选或解释，不能直接替代确定性系统。
