# LLM 采样参数

来源：https://www.nootcode.com/problems/llm-sampling-parameters

## 面试直接回答卡
Q: 面试中如何直接回答“LLM 采样参数是什么，怎么影响输出？”

A:
- 采样参数作用在解码阶段，也就是模型已经算出下一个 token 的概率分布之后，系统要如何从候选 token 里选一个出来。
- 最稳定的方式是 greedy decoding，每一步都选概率最高的 token，所以输出通常更可复现，但也更容易保守、重复，缺少多样性。
- 如果使用 sampling，模型会按概率抽样。temperature 会改变分布的尖锐程度，top-k 会限制只在概率最高的 k 个 token 中选择，top-p 会限制在累计概率达到阈值的候选集合中选择。
- 因此事实问答、客服政策、结构化 JSON、代码生成通常要降低随机性，并配合 schema、测试或校验；广告文案、头脑风暴、创意写作可以适当提高多样性。
- 采样参数只能影响输出稳定性、发散程度和长度，不能单独保证事实正确。高风险业务仍然要靠检索来源、规则系统、程序校验和人工确认兜底。

## 核心机制卡
Q: LLM 采样参数主要控制什么？

A:
- 模型每一步会输出候选 token 的概率分布，采样参数决定如何从这个分布里选择下一个 token。
- Greedy decoding 每步选择概率最高的 token，输出通常更稳定、更可复现，但可能保守、重复或缺少创造性。
- Sampling 会按概率随机选择 token，使低概率候选也有机会出现，输出更有多样性。
- Temperature、top-p、top-k、max tokens、stop sequence、presence/frequency penalty 都会影响最终输出。
- 面试一句话：采样参数是解码层的控制杆，不是模型知识本身，也不是正确性保证。

## 机制拆解卡
Q: temperature、top-p、top-k 如何影响输出？

A:
- Temperature 会缩放 logits：低 temperature 让高概率 token 更突出，高 temperature 让分布更平，增加发散。
- Top-k 只保留概率最高的 k 个候选 token，再从中选择或采样。
- Top-p 选择累计概率达到 p 的最小候选集合，候选数量会随分布形状动态变化。
- Max tokens 控制最长输出，过小会截断，过大增加成本并可能诱发冗长。
- Stop sequence 控制停止位置，设置不当会提前截断或无法及时停止。

## Temperature 公式卡
Q: temperature 从数学上如何改变 token 概率分布？

A:
- 模型先输出每个候选 token 的 logits，记作 `z_i`。
- 不加 temperature 时，概率大致是 `P_i = exp(z_i) / Σ exp(z_j)`。
- 加 temperature 后，通常是 `P_i = exp(z_i / T) / Σ exp(z_j / T)`。
- 当 `T < 1`，较大的 logits 会被进一步放大，高概率 token 更容易被选中，输出更稳定。
- 当 `T > 1`，分布被拉平，低概率 token 更有机会出现，输出更多样但也更容易跑偏。
- 当 `T` 接近 0 时，行为接近 greedy decoding，但工程上仍不能把它当成绝对确定性保证。

## Top-p 例子卡
Q: top-p 和 top-k 的差异能用一个具体例子说明吗？

A:
- 假设候选 token 概率是：A=0.50，B=0.20，C=0.15，D=0.10，E=0.05。
- `top-k=3` 会固定保留 A、B、C，不管它们累计概率是多少。
- `top-p=0.8` 会从高到低累加：A+B+C=0.85，达到 0.8 后停止，所以保留 A、B、C。
- 如果分布变成 A=0.90，B=0.04，C=0.03，D=0.02，E=0.01，`top-p=0.8` 只保留 A。
- 所以 top-k 是固定候选数量，top-p 是按累计概率动态决定候选集合大小。

## 举例卡
Q: 不同任务如何选择采样策略？

A:
- 客服政策问答：使用低随机性，并要求引用知识库来源，避免自由发挥。
- JSON 抽取：低 temperature 加 schema 校验，重点是字段稳定和类型正确。
- 广告文案：可以提高 temperature 或 top-p，一次生成多个候选再筛选。
- 代码生成：通常偏低随机性，并通过编译、测试、静态检查验证。
- 头脑风暴：可以提高多样性，但仍要设置主题、禁区、长度和评分标准。

## 输出差异卡
Q: 采样参数为什么会导致同一个 prompt 多次输出不同？

A:
- Sampling 下每一步都有概率抽样，第一次可能选 A token，第二次可能选 B token。
- 早期 token 一旦不同，后续上下文就不同，后面的概率分布也会改变。
- Temperature 越高、top-p 越宽，越容易产生不同路径。
- 即使用 greedy，服务端模型版本、系统提示词、工具结果、检索上下文也可能导致差异。
- 因此线上要记录参数、prompt 版本和模型版本，不能只记录用户原始问题。

## 工程实践卡
Q: 生产系统如何使用采样参数？

A:
- 按任务分层配置参数，而不是全站一个 temperature。
- 对强格式输出使用低随机性、schema、parser 和失败重试。
- 对高风险事实答案要求来源和校验，不依赖“调低 temperature”来防幻觉。
- 对创意任务允许多样性，但要用审核规则过滤风险内容。
- 对关键业务动作，采样结果只能作为建议，最终执行必须由规则、程序逻辑、权限和人工确认兜底。

## 正确性审查卡
Q: 解释采样参数时有哪些常见误区？

A:
- “temperature=0 就绝对确定”：不严谨，服务端实现、版本和上下文仍可能变化。
- “低 temperature 就不会幻觉”：错误，错误上下文和缺失知识仍会导致错误答案。
- “top-p/top-k 越大越好”：不对，候选过宽会增加噪声和跑偏。
- “采样参数能解决业务正确性”：不能，业务正确性要靠数据来源、规则、校验和审计。
- “greedy 一定最优”：不一定，它稳定但可能僵硬、重复或错过更自然表达。
