# LLM 幻觉问题与缓解策略

来源：https://www.nootcode.com/problems/llm-hallucination-and-mitigation

## 面试直接回答卡
Q: 面试中如何直接回答“什么是 LLM 幻觉，如何缓解？”

A:
- LLM 幻觉指的是模型生成了看起来流畅、自信、结构完整，但和事实、给定上下文或业务规则不一致的内容。比如没有查询配置中心，却回答“退款接口超时时间是 3 秒”，这就是把常见经验包装成了事实。
- 幻觉的根源在于 LLM 的训练目标是预测高概率文本，不是天然查询事实数据库。知识缺失、上下文不足、检索结果错误、prompt 前提错误、采样随机性和用户要求“必须回答”都会增加幻觉概率。
- 缓解幻觉不能只靠一句“请不要胡说”。工程上通常要用 RAG 或工具提供真实来源，要求模型引用依据，允许它在缺少依据时说不知道，并对 JSON、SQL、代码、链接、金额、配置项等做程序化校验。
- 还要按风险分级处理：低风险闲聊可以容忍一定不确定性，高风险医疗、法律、金融、运维、权限和交易场景必须有人审、规则校验和审计。
- 所以幻觉很难被彻底消除，系统设计的目标是降低发生概率、限制影响范围，并让错误可发现、可追踪、可回滚。

## 概念卡
Q: 什么是 LLM 幻觉？

A:
- 幻觉是模型输出看起来专业、完整、语气自信，但内容与事实来源、给定上下文或业务规则不一致。
- 它可能是编造引用、虚构接口参数、错误解释配置、把推测说成事实。
- 幻觉不是单纯“模型没知识”，也可能来自上下文冲突、检索错误、采样发散或问题前提错误。
- 因为 LLM 的目标是生成高概率文本，不是天然执行事实数据库查询。
- 面试表达：幻觉是概率生成系统的固有风险，必须通过系统工程治理。

## 机制拆解卡
Q: LLM 为什么会产生幻觉？

A:
1. 知识缺失：模型没有训练到新知识、私有知识或长尾知识。
2. 上下文不足：prompt 没给关键事实，模型用常见模式补全。
3. 上下文冲突：多个来源互相矛盾，模型混合生成。
4. 解码随机：sampling 可能让早期 token 走到错误路径。
5. 任务压力：用户要求必须回答，模型可能减少“不确定”表达。
6. 检索污染：RAG 召回错误、过期或无权限文档，模型仍尝试整合。

## 事实校验链路卡
Q: 如果用户问“线上配置是多少”，怎样避免模型编造答案？

A:
- 不要让模型凭记忆回答配置值，因为训练数据里通常没有你的实时私有配置。
- 正确链路是先调用配置中心或只读查询工具，拿到配置项、环境、版本和更新时间。
- 模型只能基于工具返回值组织解释，例如“生产环境 timeout=5s，更新时间为...，来源为配置中心...”。
- 如果工具查不到，就回答“当前没有可验证来源”，而不是猜一个默认值。
- 高风险配置变更还要走审批、变更单和回滚，不让模型直接改配置。

## 举例卡
Q: 用工程例子说明幻觉的风险。

A:
- 用户问“退款接口超时时间是多少”，模型没有访问配置中心，却回答“默认 3 秒”。
- 这个答案像常见工程经验，但可能与真实配置完全不一致。
- 如果排障人员据此修改调用方超时，会把问题引向错误方向。
- 更可靠做法是让模型调用配置查询工具，或回答“当前上下文没有来源，需要查询配置中心”。
- 关键点：模型可以组织解释，但事实来源必须来自工具、文档、数据库或人工确认。

## 缓解策略卡
Q: 工程上如何缓解 LLM 幻觉？

A:
- 用 RAG 或工具提供最新、授权、可引用的事实来源。
- 要求模型区分“事实、推测、建议”，缺少依据时允许说不知道。
- 对输出加结构约束：schema、枚举、字段类型、引用格式。
- 对关键结论做后置校验：链接是否存在、字段是否真实、代码是否能编译、金额是否正确。
- 对高风险动作加入人工确认和审计，避免错误答案直接变成执行动作。

## 边界与误区卡
Q: 幻觉治理有哪些边界和误区？

A:
- “加 RAG 就没有幻觉”：错误。检索可能错，模型也可能误读。
- “让模型一步步思考就能保证正确”：错误，推理流畅不等于事实正确。
- “低 temperature 能消除幻觉”：错误，它只能降低随机性，不能补齐事实来源。
- “模型自检就够”：不够，自检仍是模型生成，需要外部校验。
- “幻觉只影响答案文本”：不对，如果接入工具，错误结论可能触发错误操作。

## 正确性审查卡
Q: 回答幻觉问题时，怎样体现工程成熟度？

A:
- 要从“模型为什么会错”扩展到“系统如何让错误不伤人”。
- 要能区分低风险生成和高风险决策，不能把所有输出同等处理。
- 要强调来源、权限、版本、引用和校验，而不是只优化 prompt。
- 要说明关键业务逻辑必须由规则系统、程序逻辑、权限系统或人工确认兜底。
- 要承认无法绝对消除幻觉，因此需要监控、评测、失败样本回流和持续改进。
