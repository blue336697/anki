# 缓存穿透击穿雪崩

## 穿透卡
Q: 什么是缓存穿透？如何解决？
A:
- 缓存穿透是查询不存在的数据，缓存和数据库都没有
- 攻击或异常请求会持续打到数据库
- 可缓存空值并设置短 TTL
- 可用布隆过滤器在访问缓存前拦截明显不存在的 key
- 还要做参数校验、限流和风控

## 击穿卡
Q: 什么是缓存击穿？如何解决？
A:
- 缓存击穿是热点 key 过期瞬间，大量请求同时打到数据库
- 可用互斥锁只允许一个请求重建缓存
- 可用逻辑过期，让旧值先服务请求，后台异步刷新
- 热点 key 可设置更长 TTL 或不过期，配合主动更新
- 关键是避免大量请求同时重建同一热点数据

## 雪崩卡
Q: 什么是缓存雪崩？如何解决？
A:
- 缓存雪崩是大量 key 同时失效或 Redis 整体不可用
- 大量请求直接压到数据库，可能级联故障
- TTL 增加随机抖动，避免同一时刻过期
- 多级缓存、限流、熔断、降级和预热可以降低冲击
- Redis 高可用和容量治理也属于雪崩防护

## 正确性审查卡
Q: 缓存穿透、击穿、雪崩有哪些常见误区？
A:
- “缓存空值没有副作用”：不完整。要控制 TTL，避免污染和不一致
- “布隆过滤器不会误判”：错误。它可能误判存在，但不能误判不存在
- “热点 key 永不过期就安全”：不完整。要考虑主动更新和脏数据
- “雪崩只靠随机 TTL”：不够。Redis 故障也会导致雪崩
- “缓存问题只影响缓存层”：错误。最终会冲击数据库和业务链路
