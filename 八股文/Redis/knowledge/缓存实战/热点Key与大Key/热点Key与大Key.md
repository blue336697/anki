# 热点Key与大Key

## 热点Key卡
Q: 什么是热点 key？它有什么风险？
A:
- 热点 key 是被大量请求集中访问的 key
- 它可能让单个 Redis 节点 CPU、带宽或连接数成为瓶颈
- Cluster 中热点 key 仍只落在一个槽和一个节点
- 热点过期会引发缓存击穿
- 解决思路包括本地缓存、key 拆分、读副本、限流和热点预热

## 大Key卡
Q: 什么是大 key？它有什么风险？
A:
- 大 key 是 value 很大或集合元素很多的 key
- 读写大 key 会阻塞主线程并占用网络带宽
- 删除大 key 可能造成延迟尖刺
- 迁移、持久化和复制也会被大 key 拖慢
- 应拆分大对象、限制集合大小、使用 scan/hscan 分批处理

## 删除卡
Q: Redis 如何安全处理大 key 删除？
A:
- 避免直接 `del` 超大 key 阻塞主线程
- 使用 `unlink` 异步释放内存
- 集合类 key 可分批删除成员后再删除 key
- 删除前要评估 key 大小、访问流量和复制影响
- 线上可配合低峰、限速和监控延迟

## 正确性审查卡
Q: 热点 key 和大 key 有哪些常见误区？
A:
- “Cluster 能自动解决热点”：错误。热点 key 仍在单节点
- “大 key 只是占内存”：不完整。还影响延迟、复制、迁移和删除
- “unlink 没有成本”：不完整。释放内存转后台，但总成本仍存在
- “热点 key 设置永不过期就行”：不够。读压力仍在
- “hgetall 很方便可以随便用”：危险。大 hash 会阻塞和占用网络
