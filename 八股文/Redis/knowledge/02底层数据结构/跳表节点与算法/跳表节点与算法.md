# 跳表节点与算法

> 版本基线：Redis 7.4 OSS。答案中的结构体与函数名以官方源码为准；版本差异会显式标注。

## 01-节点布局

Q: Redis 7.4 的 zskiplistNode 和 zskiplist 各保存什么？

A:
```c
typedef struct zskiplistNode {
    sds ele;
    double score;
    struct zskiplistNode *backward;
    struct zskiplistLevel {
        struct zskiplistNode *forward;
        unsigned long span;
    } level[];
} zskiplistNode;
```
- `zskiplist` 保存 header、tail、length 和当前最高 level。
- 每节点柔性数组 level[] 长度随机；level 0 串起全部节点，backward 只需一条即可支持反向遍历。

## 02-随机层高

Q: zslRandomLevel 如何生成层高，为什么最大 32 层？

A:
- 从 level=1 开始，以概率 p=0.25 继续升层，直到失败或达到 `ZSKIPLIST_MAXLEVEL=32`。
- 节点达到第 k 层的概率约为 p^(k-1)，高层节点指数减少，形成稀疏索引。
- 期望层数为 1/(1-p)=4/3，平均额外 forward/span 开销受控。
- 32 层对 2^64 量级元素已足够；这是概率结构，不要求像平衡树那样旋转维护严格高度。

## 03-插入路径

Q: 跳表插入时 update[] 和 rank[] 分别解决什么问题？

A:
1. 从最高层向下搜索，`update[i]` 记录第 i 层新节点之前的节点。
2. `rank[i]` 累计走过的底层元素数，用于计算插入后各层 span。
3. 随机得到新节点层高；若超过当前最高层，新增层的前驱设为 header。
4. 逐层改 forward，拆分前驱原 span；未包含新节点的更高层 span 加 1。
5. 更新 backward、后继的 backward、tail 和 length。

## 04-span与排名

Q: span 为什么能让 ZRANK 从线性扫描变成 O(log N) 期望复杂度？

A:
- `span` 表示沿某层 forward 一跳跨过多少个 level-0 节点。
- 查找目标时每次向前跳都把 span 加到 rank；向下层继续，最终累积得到 1-based 排名。
- 按排名找元素则判断 `traversed + span` 是否超过目标，能跳就跳，不能就下降。
- forward 负责有序搜索，span 负责秩统计；只背“跳表有多层指针”不足以解释 ZRANK。

## 05-排序规则与复杂度

Q: 相同 score 的成员如何排序？跳表各操作复杂度如何？

A:
- 先按 double score 升序；score 相同再按成员 SDS 字典序，保证全序和精确定位。
- 查找、插入、删除、按 rank 定位平均 O(log N)，最坏概率性 O(N)；范围输出还需 O(M) 返回 M 个元素。
- 反向范围利用 level-0 的 backward 与 tail，不需要每层都保存后退指针。
- 跳表实现简单、范围遍历自然；Redis 还配套 dict 解决按 member 精确查 score 的需求。
