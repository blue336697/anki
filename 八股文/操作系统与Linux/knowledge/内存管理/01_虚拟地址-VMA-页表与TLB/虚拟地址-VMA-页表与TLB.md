# 虚拟地址、VMA、多级页表与 TLB

> 基线：以 64 位 Linux 通用模型为主。页表级数、虚拟地址宽度、页大小和内核地址布局依架构与配置变化。

## 01-虚拟内存目的
Q: 虚拟内存同时解决了哪些问题？
A:
- 为每个进程提供独立、连续的地址视图，使程序链接和分配不必直接管理物理页位置。
- 页表权限隔离不同进程和用户/内核访问，非法读写由 MMU 触发异常交给内核。
- 同一物理页可映射到多个虚拟地址，实现共享库、共享内存、文件映射和 COW。
- 按需分页允许地址空间大于当前驻留物理内存，但超额承诺最终仍受内存、swap 和 OOM 约束。

## 02-mm_struct
Q: Linux `mm_struct` 表达什么？
A:
- 它代表一个用户地址空间，保存页表根、VMA 集合、地址范围、RSS 统计、锁和体系结构 MMU 上下文。
- 同一进程线程组通常共享一个 `mm_struct`，所以线程能直接访问彼此用户内存。
- fork 创建新的 mm 并复制页表/COW 关系；内核线程通常没有自己的用户 mm，可借用活动地址空间。
- `task_struct` 指向 mm，把“可调度实体”和“地址空间”解耦，解释了线程为何独立调度却共享内存。

## 03-VMA
Q: `vm_area_struct` 描述的是什么，为什么不能为每个字节建一个对象？
A:
- VMA 描述一段连续虚拟地址区间，区间内权限、映射类型、文件与偏移、匿名策略等属性一致。
- 一次 mmap、堆扩展、栈或 ELF 段通常形成 VMA；mprotect、munmap 可拆分或合并区间。
- 缺页时内核先定位包含地址的 VMA，再判断读写执行权限以及匿名/文件映射处理函数。
- 现代内核使用 Maple Tree 等结构管理 VMA，旧教材常写红黑树；核心目标都是高效范围查询与修改。

## 04-多级页表
Q: 为什么 64 位系统使用多级页表？
A:
- 单级页表若覆盖巨大稀疏虚拟空间会为未使用地址也分配海量表项。
- 多级结构只为实际使用的地址范围逐层分配页表页，顶层索引指向下级表，叶子 PTE 指向物理页。
- Linux 通用页表代码按 PGD、P4D、PUD、PMD、PTE 五级抽象编写；硬件层级较少时可 fold 掉中间级。
- 大页可在更高层级形成叶子映射，减少页表占用与 TLB 压力。

## 05-PTE
Q: 一个页表项除了物理页号还保存什么？
A:
- present、read/write、user/supervisor、execute-disable 等位控制映射存在性和访问权限。
- accessed/young 与 dirty 位帮助内核判断页面活跃度和写回需求，具体由硬件或软件协同维护。
- 不 present 的条目可编码 swap 位置、迁移、文件或其他内核状态，而不一定表示该地址完全非法。
- PTE 格式由架构定义，Linux 通过 helper 抽象，不能把某一 x86 位布局当成所有平台通用。

## 06-地址翻译
Q: CPU 访问一个用户虚拟地址时，翻译路径是什么？
A:
1. MMU 先用虚拟页号和地址空间标签查询 TLB；命中后立即得到物理页框与权限。
2. 未命中时硬件或架构代码从页表根逐级 page walk，读取各级表项。
3. 有效叶子表项被填入 TLB，页内偏移与物理页框组合成物理地址。
4. 条目不存在或权限不符会触发 page fault，内核判断可补页、COW、信号还是内核错误。

## 07-TLB
Q: TLB 为什么对性能关键？
A:
- 多级 page walk 需要多次内存访问；TLB 缓存近期虚拟页到物理页的翻译和权限，省掉大多数 walk。
- 工作集页数超过 TLB 覆盖范围会增加 TLB miss，即使数据本身在 CPU cache 中也需先翻译地址。
- 大页用一个 TLB 项覆盖更大范围，可提升覆盖率，但增加内存碎片和回收/延迟风险。
- perf 的 dTLB/iTLB miss 与 page fault 是不同事件：前者可能仅触发硬件 page walk，不必进入内核。

## 08-TLB shootdown
Q: 多核修改页表后为什么需要 TLB shootdown？
A:
- 其他 CPU 可能缓存了同一地址空间的旧 PTE；仅修改内存中的页表不会自动让远端 TLB 立即失效。
- 内核向运行过该 mm 的相关 CPU 发送 IPI，使其按范围或上下文失效 TLB，再确认旧映射不可使用。
- 大范围 unmap、mprotect、频繁内存映射会产生跨核同步和停顿，线程越分散成本可能越高。
- PCID/ASID 可减少地址空间切换时的全量失效，但不能消除真正修改映射后的同步要求。

## 09-用户与内核映射
Q: 每个进程的页表只包含自己的用户空间吗？
A:
- 用户区映射因进程不同，内核需要在系统调用和中断中访问统一内核代码与数据。
- 传统布局会在每个进程页表中保留受 supervisor 权限保护的内核映射，用户态无法直接访问。
- KPTI 等缓解措施可能在用户运行时使用更精简页表，并在进入内核时切换，降低侧信道暴露。
- 实际布局依架构、内核配置、KASLR 和安全策略变化，不能背固定地址分界作为永恒事实。

## 10-VSZ与RSS
Q: VSZ、RSS、PSS、USS 分别反映什么？
A:
- VSZ 是进程虚拟地址范围总量，包含未实际 fault 的匿名区、mmap 文件和保留地址，不等于物理内存。
- RSS 是当前驻留物理页总量，共享页会在每个进程中重复计入。
- PSS 把共享页按映射进程数分摊，更适合估算某进程对系统物理内存的比例贡献。
- USS 关注私有驻留页，进程退出更可能直接释放；排障需结合 `/proc/<pid>/smaps_rollup` 而非只看 top RES。

## 11-ASLR
Q: ASLR 与 PIE 如何改变进程地址布局？
A:
- ASLR 随机化栈、mmap 区、共享库等位置，PIE 可让主程序代码也在随机基址加载。
- 目标是增加攻击者预测地址和构造利用链的难度，不提供内存访问本身的完整安全。
- 调试 core、perf 符号化和地址日志需要结合具体进程 maps 与构建符号还原。
- 关闭 ASLR 可方便实验但会降低安全性，不应作为生产定位的长期措施。

## 12-正确性审查
Q: 关于虚拟内存和页表，哪些说法需要纠正？
A:
- “虚拟地址一定对应一个物理页”错误；可以尚未分配、在 swap、文件中或非法。
- “64 位进程能直接使用完整 2^64 地址”错误；CPU 实现的虚拟地址位数和内核布局更小。
- “TLB miss 就是 page fault”错误；有效 PTE 的硬件 page walk 不进入缺页处理。
- “Linux VMA 永远用红黑树”已过时；现代内核已采用 Maple Tree 等实现，面试应讲范围映射语义。
