# task_struct、线程组与进程生命周期

> 基线：Linux 调度实体以 task 为核心，用户语义中的进程和线程由资源共享关系构成，不是内核中两套完全独立对象。

## 01-task_struct
Q: `task_struct` 为什么是理解 Linux 进程线程的核心？
A:
- 每个可调度 task 都有一个 `task_struct`，保存状态、调度信息、内核栈关联、PID 关系、凭据、信号和资源指针。
- 多个 task 可以共享 `mm_struct`、文件表、信号处理等对象，形成用户看到的多线程进程。
- 调度器调度的是 task，不是抽象的“整个进程”；同一进程的多个线程可同时运行在不同 CPU。
- `task_struct` 很大且版本变化频繁，面试应理解关键指针关系而非背字段全集。

## 02-PID与线程组
Q: Linux 中 PID、TID、TGID 怎样对应进程和线程？
A:
- 每个 task 都有内核 PID 标识；在线程组内，主线程 PID 常作为 TGID，其他线程拥有各自 TID。
- 用户态 `getpid()` 通常返回 TGID，`gettid()` 返回当前 task 的线程 ID。
- `/proc/<tgid>/task/<tid>` 展示一个进程的线程集合；调度与信号可按线程或线程组作用。
- PID namespace 会让同一 task 在不同命名空间看到不同 PID，因此日志排障需确认观察层。

## 03-fork
Q: `fork()` 创建子进程时内核复制和共享了什么？
A:
- 内核创建新的 task、PID、内核栈和必要调度状态，并复制或引用父进程的资源描述。
- 用户地址空间通常复制页表并把可写页改成写时复制，不立即复制全部物理页。
- 文件描述符表被复制，但表项指向相同 open file description，因此文件偏移和状态标志可能共享。
- 子进程从 fork 返回点继续，返回值不同；多线程进程 fork 后子进程只保留调用线程，锁状态尤其危险。

## 04-clone
Q: `clone/clone3` 如何统一实现进程与线程创建？
A:
- clone flags 决定子 task 是否共享地址空间、文件表、文件系统上下文、信号处理和线程组等资源。
- pthread 创建线程会选择一组共享标志，使多个 task 共享进程级资源但保留独立寄存器、栈和调度状态。
- 容器运行时还会结合 PID、mount、user 等 namespace flag 创建不同隔离视图。
- “进程用 fork、线程用完全另一套内核机制”不准确；底层都围绕复制 task 和选择共享边界。

## 05-execve
Q: `execve()` 为什么不是创建新进程？
A:
- exec 用新程序映像替换当前 task 所在线程组的用户地址空间，加载 ELF、解释器、栈、参数和环境。
- 成功后 PID 通常不变，但代码、数据、堆栈和大多数执行上下文被替换，调用不会返回旧程序。
- 带 `FD_CLOEXEC` 的文件描述符会关闭，其他描述符可继承；凭据还可能因可执行文件属性变化。
- 多线程进程执行 exec 时，其他线程会被终止并收敛到执行者，不能把旧线程状态继续带入新程序。

## 06-exit与僵尸
Q: 进程退出后为什么还会留下 zombie？
A:
- 退出 task 释放地址空间、文件和多数资源，但保留 PID、退出码和少量统计，等待父进程获取结果。
- 父进程通过 `wait/waitpid` 回收这些信息后，内核才能最终释放进程描述。
- zombie 不占用用户内存和 CPU，但大量积累会消耗 PID 和内核对象，说明父进程没有正确 wait。
- 父进程先退出时，孤儿会被指定 subreaper 或 init 类进程接管并负责回收。

## 07-进程状态
Q: Linux 常见 task 状态分别表达什么？
A:
- `TASK_RUNNING` 同时包含正在 CPU 上执行和位于 runqueue 等待执行，不能从 R 简单判断正占用 CPU。
- 可中断睡眠通常显示 S，可被信号唤醒；不可中断睡眠常显示 D，多用于必须等待的内核 IO 路径。
- stopped/traced 表示被作业控制信号或调试器停止；EXIT_ZOMBIE 表示已退出待回收。
- 状态是瞬时采样，排障要结合内核栈、等待通道、持续时间和资源指标。

## 08-文件描述符继承
Q: fork 和 exec 对文件描述符的影响为什么常导致管道不结束或端口泄漏？
A:
- fork 后父子各有 fd 表项，但引用同一内核 file 对象；只有所有写端引用关闭，管道读端才看到 EOF。
- exec 默认保留未设置 close-on-exec 的 fd，服务启动子进程时可能意外泄漏监听 socket、文件或凭据通道。
- 使用 `O_CLOEXEC` 在创建时原子设置比“创建后再 fcntl”更安全，可避免多线程竞态。
- 排障可查看 `/proc/<pid>/fd`、`lsof` 和 socket inode，确认真正持有引用的进程。

## 09-信号
Q: 信号怎样与线程组和系统调用交互？
A:
- 信号可以发给特定线程，也可发给进程并由某个未屏蔽线程接收；每线程有 mask，处理动作多为进程级共享。
- 内核通常在返回用户态等安全点安排 signal handler，使用用户栈或备用信号栈建立上下文。
- 阻塞系统调用可能返回 `EINTR`，也可能根据 `SA_RESTART` 和具体调用自动重启。
- handler 只应调用 async-signal-safe 操作，普通锁和 malloc 可能因重入死锁。

## 10-正确性审查
Q: 关于 Linux 进程线程，哪些说法需要纠正？
A:
- “线程只是用户态概念，内核只调度进程”错误；Linux 调度每个 task，线程也是独立调度实体。
- “fork 会立刻复制父进程全部物理内存”错误；通常依赖页表复制和 COW。
- “exec 创建一个新 PID”错误；它替换当前进程映像，通常保留 PID。
- “僵尸进程仍在运行并占大量内存”错误；它已停止执行，只保留待父进程回收的少量状态。
