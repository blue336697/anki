# 开放寻址、探测序列与删除语义

> 基线：所有 entry 都放在槽数组中；核心正确性是不让查找在目标之前错误终止。

## 01-基本模型
Q: 开放寻址哈希表在内存中长什么样，与拉链法本质差异是什么？
A:
- 它只有一组槽数组，冲突元素按探测序列占用其他槽，不为每个元素额外分配链表节点。
- 槽至少有 EMPTY、OCCUPIED，支持删除时通常还有 DELETED/TOMBSTONE；紧凑实现会把状态放在独立控制字节数组。
- 查询沿与插入完全相同的探测序列，遇到匹配 key 成功，遇到从未使用的 EMPTY 才能确定不存在。
- 优点是连续内存和少指针，缺点是高负载下簇聚集、删除复杂且容量必须始终留空。

## 02-线性探测
Q: Linear Probing 如何工作，什么是 primary clustering？
A:
- 初始槽为 h，依次检查 `h,h+1,h+2...` 并按容量环绕；实现简单且相邻槽可被 cache line 一次加载。
- 已占用的连续区间会形成 cluster，新冲突元素落在区间任一位置都会接到末尾，使区间越来越长。
- 这种正反馈称 primary clustering，导致成功和失败查询探测长度快速上升，尤其在装载因子接近 1 时。
- 好的 hash、较低负载和批量控制字节扫描能缓解，但不能消除线性探测的簇性质。

## 03-二次探测与双重哈希
Q: Quadratic Probing 和 Double Hashing 如何改善线性探测？
A:
- 二次探测使用 `h+c1*i+c2*i²`，减少相邻初始槽合并成大簇，但相同初始槽仍共享序列，存在 secondary clustering。
- 双重哈希用第二个哈希决定步长 `h1+i*h2`，不同 key 的序列更独立，分布通常更接近随机探测。
- 步长必须与容量互质才能遍历所有槽；容量为 2 的幂时步长通常要求奇数。
- 更复杂探测减少聚簇，却可能损失连续访问和 SIMD 优势，不能只按理论碰撞次数选。

## 04-墓碑删除
Q: 为什么开放寻址删除不能直接把槽改成 EMPTY，墓碑又带来什么问题？
A:
- 某 key 可能越过该槽才被插入；直接 EMPTY 会让后续查询提前判断“不存在”，切断探测链。
- 标记 TOMBSTONE 表示此处可供插入复用，但查询必须继续；这样保持可达性。
- 墓碑积累会拉长失败查询，即使 size 很小也可能很慢，因此要跟踪 occupied 与 deleted 数并在阈值重建。
- 插入通常记住遇到的第一个墓碑，但仍继续查到 EMPTY 以确认后面没有同 key，之后才能复用。

## 05-后移删除
Q: Backward-shift deletion 如何避免墓碑，它为什么只适用于特定探测策略？
A:
- 删除槽后向前扫描后继簇，把那些“理想槽位在空洞之前”的元素向后移动，直到遇到真正空槽。
- 对线性探测，可用元素从理想位置到当前位置的环形距离判断是否能填洞，从而保持查询可达。
- 它让表长期没有墓碑、查询更稳定，但一次删除可能移动多个 entry，迭代器和引用更容易失效。
- 对任意二次或双哈希序列，简单后移不一定保持原探测路径，不能直接套用。

## 06-Robin-Hood
Q: Robin Hood Hashing 的核心不变量是什么，它为什么改善尾部探测距离？
A:
- 记录元素距理想槽的 probe distance；插入时若新元素走得比当前位置元素更远，就交换，像“从富者取位给穷者”。
- 它不能必然降低平均探测总量，但会压缩距离方差和最大值，使查询尾延迟更稳定。
- 查找若当前步数已经超过槽中元素的距离，可提前判定不存在，因为后续不应出现更“靠家”的目标。
- 删除常配合 backward shift；交换和搬移意味着 entry 地址不稳定，不适合暴露内部指针。

## 07-控制字节
Q: 为什么现代开放寻址表会把控制元数据和 key/value 分离？
A:
- 每槽控制字节保存 EMPTY/DELETED 和 hash 的短指纹；查询先连续读取一组控制字节，用 SIMD 比较多个指纹。
- 只有指纹匹配才加载较大的 key/value 并做完整 equality，减少无关数据 cache miss。
- 元数据连续而紧凑，可以一次 cache line 筛查许多槽，也让失败查询更快。
- 短指纹会有假阳性但不能有假阴性；最终 key 比较仍是正确性的最后关卡。

## 08-负载与复杂度
Q: 开放寻址的期望探测次数怎样随装载因子变化？
A:
- 在理想均匀假设下，α 越接近 1，尤其失败查询必须找到 EMPTY，成本呈非线性上升。
- 不同模型公式不同，但共同结论是不能把容量用满；例如线性探测还受到簇聚集影响，比独立随机探测更差。
- 删除墓碑应计入“有效占用”，否则以 size/capacity 判断会严重低估真实探测压力。
- 工程上要监控 probe length 分布并在阈值扩容或重建，而不是等待插入完全失败。

## 09-选型
Q: 什么时候优先开放寻址，什么时候优先拉链法？
A:
- 元素较小、追求缓存局部性、可整体扩容且不要求 entry 稳定地址时，开放寻址通常更紧凑更快。
- 负载变化大、节点需稳定地址、删除频繁或 value 很大时，拉链法能避免搬动大对象并允许 α>1。
- 开放寻址扩容需要整张数组，峰值内存明显；拉链表虽也换桶数组，但节点可能复用。
- 并发实现中槽位搬移和发布协议更难；最终选择要同时考虑内存布局、删除、迭代和同步模型。
