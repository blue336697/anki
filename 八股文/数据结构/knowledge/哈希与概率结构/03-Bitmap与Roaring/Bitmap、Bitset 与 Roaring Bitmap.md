# Bitmap、Bitset 与 Roaring Bitmap

> 基线：位图用 key 的值域直接换取 O(1) 定位；压缩位图解决稀疏值域的空间浪费。

## 01-Bitmap表示
Q: Bitmap 如何把整数 x 映射到具体 bit？
A:
- 设机器字宽 w，字下标是 `x/w`，字内偏移是 `x%w`；置位执行 `words[i] |= 1<<offset`。
- 查询、设置和清除都是 O(1)，且一个 bit 表示一个布尔状态，空间约为值域上界 U/8 字节。
- 它隐含 key 是可映射的非负整数且值域可控；任意字符串需先建立 ID 或哈希映射。
- 并发置位同一机器字不同 bit 仍会发生读改写竞争，需要原子 OR 或分片。

## 02-集合运算
Q: Bitmap 为什么特别适合集合交并差？
A:
- 交集是逐机器字 AND，并集 OR，异或 XOR，差集可用 `A & ~B`；每条指令同时处理 32/64 个元素状态。
- 连续数组可被 SIMD 和硬件预取加速，复杂度是 O(U/wordSize)，与实际集合元素数无直接关系。
- `popcount` 指令可快速统计结果中 1 的数量，常用于标签筛选、权限和分析查询。
- 当 U 极大而集合很稀疏时，扫描整个位域反而浪费，需压缩位图或排序整数数组。

## 03-空间边界
Q: 何时普通 Bitmap 比 HashSet 更省空间，何时会失控？
A:
- Bitmap 成本主要由最大值域 U 决定，与实际 n 无关；HashSet 成本随 n 增长但每元素有槽、hash 和空闲空间。
- ID 稠密且上界可接受时，1 bit/值远小于哈希表每元素几十字节级开销。
- 只有少数 ID 却最大值很大时，直接分配 U bits 会产生巨大空洞；负数或 64 位稀疏 ID 也不能直接展开。
- 可以分块延迟分配、坐标压缩或使用 Roaring/EWAH 等压缩表示。

## 04-层次位图
Q: 层次位图怎样加速寻找第一个空闲或已占用位置？
A:
- 底层位图记录具体槽，上层每个 bit 概括一个底层机器字是否“存在目标状态”，可继续建立多级摘要。
- 查找先在最高层定位非空分组，再逐级下降，避免线性扫描大量全零或全一字。
- 内存分配器、CPU 集、文件块管理常使用类似 summary bitmap；更新底层边界状态时必须同步传播上层。
- 层数约为 log_word(U)，但并发更新与一致性维护比单层位图复杂。

## 05-Roaring分区
Q: Roaring Bitmap 的顶层结构是什么？
A:
- 32 位整数通常拆成高 16 位和低 16 位；高位定位 container，低位在 container 内表示成员。
- 顶层保存有序高位 key 与对应 container 指针，查询先二分或索引高位，再在局部 65536 值域中操作。
- 分块让稠密区用 bitmap、稀疏区用数组，各自接近最佳表示，同时支持按高位并行合并。
- 真实库可能还有 run container、索引和序列化优化，但核心是按块自适应表示。

## 06-三类Container
Q: Array、Bitmap、Run container 分别适合什么数据分布，如何转换？
A:
- Array container 用排序 16 位整数，适合低基数；查询二分，合并可线性归并。
- Bitmap container 固定 65536 bits 即 8 KiB，适合稠密块，位运算非常快。
- Run container 保存连续区间 `(start,length)`，适合长连续段，如大量连续 ID。
- 当基数或 run 数跨阈值时转换容器；阈值由空间与操作成本共同决定，不只是元素个数。

## 07-Roaring集合运算
Q: 两个 Roaring Bitmap 求交集时具体怎样执行？
A:
- 先像归并有序数组一样对齐高 16 位 container key；不同高位块可直接跳过。
- 相同块按容器组合选择算法：bitmap-bitmap 做 AND，array-array 双指针，array-bitmap 逐值测 bit。
- 输出基数变化后再选择最紧凑容器，可能从 bitmap 降为 array 或把连续结果编码为 run。
- 复杂度与参与的块数和容器类型相关，通常避免扫描整个 32 位值域。

## 08-Rank与Select
Q: 位图上的 rank 和 select 操作是什么，怎样实现？
A:
- `rank(x)` 统计不大于 x 的 1 数量；`select(k)` 找第 k 个 1 的位置，它们支持压缩索引和序号映射。
- rank 可给每个大块保存前缀计数，再对目标块内机器字 popcount；避免从头扫描。
- select 先通过前缀计数定位块，再在机器字中用硬件指令或查表定位第 k 个置位。
- 额外摘要用空间换查询速度，更新频繁时维护成本更高，因此静态位向量更容易做到高效 succinct index。

## 09-工程边界
Q: Bitmap/Roaring 适用于哪些后端场景，哪些场景不该用？
A:
- 适合整数 ID 集合、标签倒排、去重状态、权限集合和基数统计前的精确表示，交并筛选特别高效。
- 不直接保存 value；若需 key-value 映射还要配套数组或其他索引，删除 ID 后的复用语义也需谨慎。
- 普通 Bitmap 适合稠密有界值域，Roaring 适合分布混合且需要压缩与快速集合运算。
- 若只做近似成员判断且不需枚举元素，Bloom Filter 更省空间；若需有序范围与 payload，应选树或排序结构。
