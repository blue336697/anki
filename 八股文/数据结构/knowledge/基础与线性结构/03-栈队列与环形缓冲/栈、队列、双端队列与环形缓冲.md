# 栈、队列、双端队列与环形缓冲

> 基线：这些是抽象数据类型；数组或链表只是实现，边界、满空判定和并发可见性决定实现是否正确。

## 01-栈的表示
Q: 数组栈内部如何表示，push/pop 的真实过程是什么？
A:
- 用连续 buffer 和 top/size 表示有效前缀；push 先检查或扩容，再写 `buffer[size++]`，pop 先减 size 再取元素。
- 需要明确 top 指向“最后元素”还是“下一个空槽”，两种约定都可行但不能混用，否则产生 off-by-one。
- 对引用元素 pop 后应清空槽位，避免容器继续持有对象导致内存不能回收。
- push 摊还 O(1)、pop O(1)，但扩容 push 最坏 O(n)；固定容量栈可提供确定延迟但要定义溢出策略。

## 02-调用栈
Q: 函数调用栈与数据结构中的栈是什么关系，栈帧里通常有什么？
A:
- 调用栈应用 LIFO 管理活跃函数，每次调用建立栈帧，返回时按相反顺序释放。
- 栈帧通常包含返回地址、保存寄存器、局部变量、溢出的参数和对齐空间，具体布局由 ABI 和编译优化决定。
- 递归深度受线程栈大小限制；尾调用优化并非所有语言、编译器和调试模式都保证。
- 栈内存快主要因为指针式批量管理与局部性，不是因为物理介质不同；缺页和缓存规则仍适用。

## 03-队列的数组实现
Q: 为什么普通数组队列不能每次 dequeue 都整体左移，正确表示是什么？
A:
- 每次左移会让 dequeue 变成 O(n)；应维护 head 指向队首、tail 指向下一个写槽，让两端只移动索引。
- 如果索引只增不复用，前部空位会浪费并最终越界；因此需要环绕、周期压缩或分段存储。
- 链式队列维护 head/tail，空队列时两者一致更新；漏改 tail 会留下悬空指针。
- API 还要定义容量满时阻塞、失败、覆盖旧数据还是扩容，不同语义对应完全不同的队列。

## 04-环形缓冲表示
Q: 环形缓冲区的内存布局和索引推进公式是什么？
A:
- 固定数组首尾逻辑相连，head/tail 通过 `(index+1)%capacity` 前进；容量为 2 的幂时可用 `index & (capacity-1)`。
- 模运算索引只用于访问数组，长期运行的逻辑序号可单调递增，用差值判断占用并减少 wrap 状态。
- 每个元素仍物理连续或近连续，越过数组末尾时分成两段，缓存行为通常优于链式队列。
- 必须处理整数回绕；使用无符号差值要求容量和序号位宽满足约束，不能只靠“很久才溢出”。

## 05-满空判定
Q: 环形队列怎样区分 head==tail 时的“空”和“满”？
A:
- 方案一浪费一个槽：`head==tail` 为空，`next(tail)==head` 为满，有效容量是 capacity-1。
- 方案二额外保存 size/count，满为 size==capacity，但并发更新时 count 会成为额外共享热点。
- 方案三保存 wrap bit/phase，索引相同且相位不同表示满；无界逻辑序号也可用 `tail-head` 判定。
- 必须把容量语义写入接口和测试，尤其覆盖 0、1、刚好满、绕回和多次循环。

## 06-双端队列
Q: Deque 如何在两端 O(1) 插入删除，为什么它也可实现栈和队列？
A:
- 环形数组 deque 在 front 前移写入或在 back 写入后移，两端索引都按容量取模；扩容时把逻辑顺序复制成新数组连续前缀。
- 双向链表 deque 用头尾哨兵实现两端 O(1)，地址稳定但节点开销和缓存表现更差。
- 只使用同一端 push/pop 就是栈；一端入另一端出就是 FIFO 队列，因此 deque 是更一般的 ADT。
- 工作窃取调度器也使用 deque，但 owner 与 thief 的并发协议远比普通容器复杂。

## 07-单调队列
Q: 单调队列内部维护什么不变量，为什么滑动窗口最值是 O(n)？
A:
- 队列保存候选元素的索引，并使对应值单调；新元素进入时从尾部删除不可能再成为最值的元素。
- 窗口左边界推进时，从头部删除已过期索引；队首始终是当前窗口最大或最小值。
- 每个索引至多入队一次、出队一次，总操作数 O(n)，而不是每个窗口都 O(k) 扫描。
- 必须保存索引而非仅保存值，否则无法判断重复值中哪个已经离开窗口。

## 08-阻塞队列
Q: 有界阻塞队列如何组织锁和条件变量，为什么要用 while 检查条件？
A:
- 共享状态是缓冲区、head、tail、count；生产者等待 `notFull`，消费者等待 `notEmpty`，状态改变后通知对方。
- 条件变量允许线程原子地释放互斥锁并睡眠，醒来后重新持锁；谓词必须在同一把锁保护下检查。
- 使用 while 是因为虚假唤醒、广播竞争或状态在重新抢锁前已被其他线程消费，if 会越过容量边界。
- 关闭、超时、中断和批量操作需纳入状态机，否则永久等待或丢失唤醒比数据结构本身更难排查。

## 09-背压与选型
Q: 队列容量为什么是系统稳定性参数，应该如何处理积压？
A:
- 无界队列把流量峰值转化为内存增长和更长排队延迟，最终可能 OOM；有界队列把过载显式暴露。
- 满时可阻塞上游、拒绝、降级、丢弃旧/新消息或落盘，必须根据业务可靠性和延迟目标选择。
- Little 定律在稳定系统中给出 `L=λW`；当到达率长期高于处理率，任何有限队列最终都会满。
- 监控应包含深度、最老元素年龄、入出速率和拒绝数；只看 CPU 无法判断排队延迟。
