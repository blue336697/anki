# 并查集、路径压缩与按秩合并

> 基线：Disjoint Set Union 维护集合划分，只高效回答连通与合并，不保存可撤销的完整图结构。

## 01-数组表示
Q: 并查集在数组中如何表示一片森林？
A:
- 每个元素 i 保存 parent[i]；根满足 parent[root]==root，所有指向同一根的节点属于同一集合。
- 另存 rank（高度上界）或 size（集合元素数）指导合并；初始化时每个元素独立成根。
- find 沿 parent 到根，union 先 find 两根，若相同则已连通，否则连接两棵树。
- 元素不是稠密整数时，先用 map 建 ID，或直接用 parent map 做动态集合。

## 02-find与路径压缩
Q: 路径压缩 find 具体修改什么，为什么不改变集合语义？
A:
- 递归形式 `parent[x]=find(parent[x])`，在返回时把路径上每个节点直接挂到根。
- 迭代可先找根再走一遍路径改 parent，或使用 path halving 让每个节点跳向祖父。
- 修改只缩短同一棵树内到相同根的路径，不连接不同集合，因此集合划分不变。
- 它让后续查询更快，但属于写操作；只读并发 find 也可能因压缩产生数据竞争。

## 03-按秩合并
Q: Union by rank/size 为什么能避免高树，rank 与真实高度有什么区别？
A:
- 总把较小/较矮树根挂到较大/较高树根，避免长链；rank 相等时任选一边为根并将其 rank 加一。
- 一旦使用路径压缩，真实高度可能下降，但 rank 通常不减，它只是安全的历史高度上界。
- 若按 size 合并，根保存准确集合大小并相加，可同时回答集合基数；非根 size 通常无意义。
- 不能比较任意节点的 rank 后直接挂，必须先 find 得到两棵树的根。

## 04-复杂度
Q: 路径压缩加按秩合并为何是近似常数时间？
A:
- 对 m 次操作、n 个元素，总复杂度是 O(m α(n))，α 是反 Ackermann 函数，在现实规模下小于很小常数。
- 这是操作序列的摊还界，不代表单次 find 严格 O(1)；第一次访问深路径仍会走多个父节点。
- 只使用按秩合并可保证 O(log n)，只用路径压缩也有改善，但二者组合给经典最强界。
- 面试无需展开完整证明，但应说明 rank 分层增长困难、压缩让节点很快跳过低层祖先。

## 05-连通性应用
Q: 并查集怎样用于无向图连通分量和环检测？
A:
- 遍历边 (u,v)，若 find(u)!=find(v) 就 union；最终相同根的顶点处于同一连通分量。
- 若处理一条无向边时两端已同根，加入它会在当前森林中形成环。
- 维护 componentCount，初始化为 n，每次成功 union 减一，可 O(1) 得到分量数。
- 它只知道是否连通，无法返回实际路径；需要路径时还应保存生成森林或使用图遍历。

## 06-Kruskal
Q: Kruskal 最小生成树为什么使用并查集？
A:
- 边按权从小到大处理；若两端属于不同分量，加入边并 union，否则跳过以避免环。
- 并查集负责快速判断当前森林连通性，排序成本 O(E log E) 通常主导，DSU 操作近似 O(E α(V))。
- 只适用于无向图最小生成森林；图不连通时结果是每个分量的 MST。
- 相同权重可有多个合法 MST，稳定排序只影响选择哪一棵，不影响最小总权重。

## 07-局限与删除
Q: 为什么普通并查集不支持边删除和集合拆分？
A:
- union 丢失了“集合由哪些边连接”的足够信息，路径压缩还把树改成仅服务查根的扁平结构。
- 删除一条边后是否断开需要知道替代路径，普通 parent/rank 无法判断。
- 离线动态连通可倒序处理删除为添加，或用 rollback DSU 配合分治时间线；在线需更复杂动态树结构。
- 因此 DSU 是单调合并结构，不应当作通用动态图索引。

## 08-Rollback DSU
Q: 可回滚并查集怎样实现，为什么通常禁用路径压缩？
A:
- 每次 union 把被修改的 parent、size/rank 旧值压入栈，记录快照栈高度；rollback 弹栈恢复到指定高度。
- 按 size 合并可保持树高 O(log n)，且一次 union 只改常数个字段，容易精确撤销。
- 路径压缩一次 find 会改路径上许多 parent，记录量和回滚复杂度上升，所以通常不用。
- 它支持撤销 union，不直接支持任意删除；常与 segment tree over time 结合处理离线边活跃区间。

## 09-常见错误
Q: 实现并查集最常见的错误有哪些？
A:
- union 直接连接 u、v 而非各自根，可能破坏 rank/size 含义并产生深链。
- rank 当集合大小使用，或在不等 rank 合并时也加一；两者更新规则不同。
- 递归 find 在未按秩控制的坏输入上可能栈溢出；迭代版本更稳健。
- 并发 union/find 不能靠普通数组原子读写自然正确，CAS 连接、压缩和线性化点需要专门设计。
