# 邻接矩阵、邻接表与 CSR 图存储

> 基线：图算法的复杂度首先由存储表示决定；V、E、方向、权重和更新模式必须同时说明。

## 01-图模型
Q: 图数据结构需要明确哪些语义，节点和边通常保存什么？
A:
- 图由顶点集合 V 和边集合 E 构成，需明确有向/无向、是否允许自环与平行边、是否带权。
- 顶点可由稠密整数 ID 映射到数组，也可由业务 key 经 map 映射；边可保存终点、权重、类型和版本。
- 无向边通常在邻接结构中保存两个方向，因此物理 entry 数可能是 2E。
- 算法中的 E 是逻辑边还是物理条目要统一，否则空间和遍历计数会差一倍。

## 02-邻接矩阵
Q: 邻接矩阵的内存布局、操作复杂度和适用场景是什么？
A:
- 用 V×V 单元记录边是否存在或权重；按行连续时 `matrix[u][v]` 可 O(1) 判断边。
- 空间 O(V²)，枚举某顶点所有邻居要扫描整行 O(V)，与实际度数无关。
- 稠密图、V 较小、频繁边存在性查询或矩阵算法适合；布尔矩阵可按 bit 压缩并用位运算加速。
- 带权图要为“不存在边”选择独立哨兵，不能与合法 0 权混淆。

## 03-邻接表
Q: 邻接表如何表示，为什么遍历复杂度是 O(V+E)？
A:
- 每个顶点保存出边集合，可用链表、动态数组、哈希集合或排序数组；总条目与边数同阶。
- 遍历所有顶点一次，再遍历每条有向边一次，所以时间 O(V+E)，空间也通常 O(V+E)。
- 动态数组邻接局部性好但删除边需查找；哈希邻接存在性期望快却空间大且顺序不稳定。
- 是否保存入边决定反向遍历成本；同时保存 in/out 会加倍索引并增加更新一致性要求。

## 04-CSR
Q: CSR（Compressed Sparse Row）在内存中具体长什么样？
A:
- `offset` 长度 V+1，顶点 u 的邻居位于 `edges[offset[u]..offset[u+1])`；edges 连续保存终点，权重可平行数组保存。
- offset 差值就是出度，遍历邻居连续且无每顶点对象/指针开销，适合静态稀疏大图。
- 构建需统计度数、前缀和并按目标位置填边，空间 O(V+E)。
- 中间插入会搬动后续边和 offset，动态更新昂贵；可批量重建或叠加 delta structure。

## 05-边列表与COO
Q: Edge List/COO 表示有什么用途，为什么不适合直接做邻接遍历？
A:
- 它把每条边保存为 `(src,dst,weight)`，结构简单、易于输入输出、排序和批处理。
- 找某个顶点邻边若未排序需扫描 E；按 src 排序并加 offset 后就接近 CSR。
- Kruskal 只需按权排序边，边列表非常自然；流式图处理也可顺序消费。
- 多字段 AoS 易用，拆成 src/dst/weight 的 SoA 可改善只读取部分字段时的向量化和缓存。

## 06-BFS存储交互
Q: BFS 使用哪些辅助数据结构，图表示如何影响它？
A:
- BFS 用 FIFO queue 保存边界，用 visited bitmap/array 防重复；从源点按层扩展邻居。
- 邻接表/CSR 使总扫描 O(V+E)；邻接矩阵则可能对每个出队顶点扫描 V，达到 O(V²)。
- 队列中保存顶点 ID 通常比保存完整对象紧凑；距离和父节点用与 ID 对齐的数组。
- 大图并行 BFS 的 frontier 可用 bitmap，方向优化会在 top-down 与 bottom-up 扫描间切换。

## 07-DFS存储交互
Q: 递归 DFS 与显式栈 DFS 的状态有什么差异？
A:
- 递归把“当前顶点和下一个待访问邻边位置”隐含在调用栈帧；深图可能栈溢出。
- 显式栈若只压顶点，弹出时一次性扩展，会产生与递归不同的访问顺序；精确模拟需保存邻接迭代器位置。
- 有向图环检测常用白/灰/黑三色，灰表示当前递归路径；普通 visited 无法区分已完成与回边。
- 存储结构若迭代顺序不稳定，DFS 输出顺序也不稳定，但连通性等正确性不应依赖顺序。

## 08-动态图
Q: 高更新率动态图应怎样选择存储结构？
A:
- 每顶点哈希邻接支持期望 O(1) 加删和判边，但碎片与内存高；排序数组查询快，插删需搬移。
- 分块邻接或 base CSR + delta log 让大部分扫描保持连续，同时周期性合并更新。
- 边版本/MVCC 可支持快照遍历，但旧版本增加空间和过滤成本。
- 图分区要考虑度分布；超级节点会造成单邻接表热点、锁竞争和任务不均衡。

## 09-选型检查
Q: 面试中选择图存储应按什么顺序回答？
A:
- 先给 V、E 与密度，明确有向/权重/平行边，再说明核心操作是判边、邻居遍历还是频繁更新。
- 稠密且判边多选矩阵；稀疏动态选邻接表；稀疏静态和扫描吞吐优先选 CSR；边排序处理选 edge list。
- 再补充顶点 ID 映射、visited/queue 等辅助结构以及缓存/空间成本。
- 不应只背“邻接表 O(V+E)”而忽略底层 children 容器和输入的动态性。
