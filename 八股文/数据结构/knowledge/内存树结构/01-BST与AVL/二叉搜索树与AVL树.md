# 二叉搜索树与 AVL 树

> 基线：BST 提供有序性，AVL 用高度不变量把最坏路径压到对数级；旋转必须同时保持搜索顺序和元数据。

## 01-BST节点与不变量
Q: 二叉搜索树节点长什么样，核心不变量是什么？
A:
- 基础节点含 key/value、left、right，可选 parent；AVL 还保存 height 或 balance factor，增强树可保存 subtreeSize。
- 对任一节点 x，左子树 key 按比较器小于 x，右子树大于 x；重复 key 必须明确覆盖、计数或固定放置规则。
- 中序遍历得到有序序列，这是查找、前驱后继、旋转正确性的核心依据。
- 比较器必须满足全序的自反/反对称/传递约束，比较语义变化会让已构建树失效。

## 02-查找与高度
Q: BST 查询复杂度为什么取决于高度，最坏如何退化？
A:
- 每次比较只选择一个子树，访问节点数至多为根到目标或空叶的路径长度，即 O(h)。
- 随机插入时普通 BST 期望高度约 O(log n)，但有序输入会形成单链，高度 n，查询退化 O(n)。
- “二叉”不代表高度就是 log n；必须有完全性、随机性或显式平衡不变量才能保证。
- 每节点一次指针跳转，实际缓存行为也比排序数组二分更差，但树支持动态有序更新。

## 03-前驱后继
Q: BST 如何寻找一个节点的中序后继？
A:
- 若节点有右子树，后继是右子树中一路向左的最小节点。
- 若无右子树，沿 parent 向上，直到第一次从某祖先的左子树上来，该祖先就是后继。
- 没有 parent 时可从根搜索并记录“当前大于 key 的最小祖先”，时间仍为 O(h)。
- 前驱是镜像操作；这一机制支持有序迭代和范围扫描，但跨节点仍有 pointer chasing。

## 04-BST删除
Q: BST 删除节点的三种情况是什么，双子节点为何可转成简单情况？
A:
- 无子节点直接断开；只有一个子节点则让该子节点替代自己，并修复 parent 链。
- 有两个子节点时，用右子树最小后继或左子树最大前驱替换逻辑内容，再物理删除那个替代节点。
- 后继不可能有左孩子，否则它不是右子树最小值，所以物理删除最终只落到 0/1 子节点情况。
- 若节点含 key 以外的身份、锁或外部引用，简单复制 payload 可能不安全；可选择 transplant 整个节点。

## 05-AVL平衡因子
Q: AVL 树维护什么不变量，高度为何是 O(log n)？
A:
- 每个节点平衡因子 `bf=height(left)-height(right)` 必须属于 {-1,0,1}，并保存可由子树推导的正确高度。
- 给定高度 h 的最少节点数满足 `N(h)=1+N(h-1)+N(h-2)`，增长近似 Fibonacci。
- 因为 Fibonacci 指数增长，反过来 h 只按 log n 增长，所以查找、插入和删除最坏 O(log n)。
- 严格平衡让读路径短，但每次结构变化都需沿祖先更新高度并可能旋转。

## 06-旋转本质
Q: 左旋和右旋在指针层面做了什么，为什么不会破坏 BST 顺序？
A:
- 左旋 x：令 y=x.right，把 y.left 挂到 x.right，再令 x 成为 y.left；还要修复 parent 和根引用。
- 旋转前局部顺序是 `A < x < B < y < C`，旋转后中序仍是 `A,x,B,y,C`，所以搜索不变量不变。
- 右旋完全镜像；旋转只改常数个指针，结构操作 O(1)，但触发位置的查找是沿路径完成的。
- AVL 必须按“先旧根、后新根”更新高度，增强树还要同步 subtreeSize、聚合值等元数据。

## 07-四种失衡
Q: AVL 的 LL、RR、LR、RL 如何判断和修复？
A:
- 节点 bf>1 表示左高，bf<-1 表示右高；再看较高子节点的 bf 决定外侧还是内侧。
- LL 对失衡节点右旋，RR 左旋；LR 先对左孩子左旋再对节点右旋，RL 完全镜像。
- 插入时也可根据新 key 路径判断，但删除时必须查看子树 bf，因为高度下降不由某个插入 key 决定。
- 双旋本质是先把内侧折线转成外侧直线，再用一次单旋提升中间 key。

## 08-插入与删除回溯
Q: AVL 插入和删除的再平衡为何不同？
A:
- 插入按 BST 放入叶子，沿祖先回溯更新高度；第一次旋转后该局部子树通常恢复到插入前高度，因此更高祖先无需再旋转。
- 删除先做 BST 删除，再向根回溯；修复一个节点后子树高度仍可能下降，继续破坏更高祖先。
- 所以插入最多在一个失衡点做单/双旋，删除最坏可能在 O(log n) 个祖先处旋转。
- 实现必须把旋转后的新子树根重新接回父节点，否则局部正确却从整棵树断开。

## 09-AVL选型
Q: AVL 与普通 BST、红黑树相比适合什么场景？
A:
- 普通 BST 最简单但无法保证最坏延迟；若输入可控或一次构建后静态使用，可直接构建平衡 BST。
- AVL 更严格平衡，查询密集且更新较少时路径通常更短；代价是 height 字段与较积极的再平衡。
- 红黑树平衡更宽松、更新修复的旋转上界更友好，常用于通用有序映射。
- 若数据主要驻留外存，二叉树扇出过低，应使用 B/B+树；选树必须先看存储层级。
