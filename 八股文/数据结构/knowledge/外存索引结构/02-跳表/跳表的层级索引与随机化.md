# 跳表的层级索引与随机化

> 基线：跳表是在有序链表上建立稀疏快车道，用概率平衡换取实现简单和局部更新。

## 01-节点布局
Q: 跳表节点在内存中长什么样，层级不变量是什么？
A:
- 节点保存 key/value 和 `forward[0..level-1]` 指针数组；第 0 层包含全部节点并保持全序。
- 更高层是低层的有序子序列，头哨兵拥有最大层数；节点高度创建后通常不变。
- 有些实现每层还保存 span，用于 rank/select；双向范围遍历可给第 0 层增加 backward 指针。
- 与多棵链表不同，同一节点的多层指针共同构成塔，key/value 只存一次。

## 02-查询过程
Q: 跳表查询为什么从最高层开始向右、再向下？
A:
- 从当前最高层出发，只要下一节点 key 小于目标就向右；下一步会越过目标时下降一层。
- 高层一次跨过很多底层节点，下降后继续缩小区间；到第 0 层检查相等。
- 每层前进后不会回头，路径类似在随机平衡搜索树中下降。
- 返回前驱数组 update 还能被插入/删除复用，避免再次寻找每一层的修改位置。

## 03-随机层高
Q: 节点高度如何随机生成，为什么期望空间是 O(n)？
A:
- 从 level=1 开始，以概率 p 继续加一，直到失败或达到 maxLevel；高度至少 k 的概率是 `p^(k-1)`。
- 期望指针数为 `1+p+p²+...=1/(1-p)`，p=1/2 时约 2 个，所以总空间 O(n)。
- 最高层期望约 `log_(1/p) n`，搜索期望 O(log n)，但单次随机结构没有严格最坏平衡保证。
- 随机源、固定最大层和对抗输入会影响实际分布，应监控层高和最长路径。

## 04-插入
Q: 跳表插入怎样修改各层指针？
A:
- 搜索时记录目标在每层的前驱 `update[i]`，若第 0 层已存在 key 则按 map 语义更新 value。
- 为新 key 生成随机 level；若超过当前全局 level，高出的前驱设为头哨兵。
- 对每层执行 `new.forward[i]=update[i].forward[i]`，再令 `update[i].forward[i]=new`。
- 单线程中先让新节点指向后继再发布前驱链接可避免临时断链；并发版本还需原子与标记协议。

## 05-删除
Q: 跳表删除如何工作，为什么可能降低全局层数？
A:
- 同样搜索并保存每层前驱；确认第 0 层目标相等后，在目标存在的每层绕过它。
- 若删除后最高层头节点直接指向尾/空，逐层降低当前 level，避免查询从永久空层开始。
- 物理释放前要确保没有并发读者仍持有节点；GC 语言与手动内存语言处理不同。
- 带 span 的跳表需在所有受影响层更新跨度，不只是 forward 指针。

## 06-复杂度证明直觉
Q: 如何理解跳表期望查询 O(log n)？
A:
- 每个节点以概率 p 晋升，某层节点数期望是下一低层的 p 倍；层数随 n 对数增长。
- 反向看搜索路径，每下降一层前期望只横向经过约 1/p 个节点，因此总步数约 `(1/p)log_(1/p)n`。
- 这是对随机层高的期望，不是对输入 key 随机的要求；若层高随机独立，排序输入也可保持期望性能。
- 需要严格最坏 O(log n) 时，应选择确定性平衡树或专门的 deterministic skip list。

## 07-范围查询
Q: 跳表为什么适合有序范围查询和排名？
A:
- 用 O(log n) 期望时间定位下界，然后沿第 0 层顺序输出 k 个元素，总期望 O(log n+k)。
- 相邻结果直接通过 forward[0] 获取，无需树的栈或父指针；链式布局则可能有缓存缺陷。
- 每层保存跨越的底层元素数 span，可在下降时累计，支持按 rank 查元素或求某 key 排名。
- span 更新比普通跳表更复杂，重复 key 的排名语义也必须先定义。

## 08-跳表与平衡树
Q: 跳表与红黑树相比有哪些工程取舍？
A:
- 两者都支持有序查找和范围，跳表算法局部、代码相对直观，插删主要修改前驱指针。
- 红黑树给确定最坏 O(log n)；跳表通常只有期望保证且每节点指针数随机。
- 跳表第 0 层范围遍历简单，并发算法可将多层链接拆成局部 CAS；树旋转会同时改更多拓扑关系。
- 指针跳转导致缓存差，两者都可能被紧凑 B-tree 类内存布局击败；应按实现与 workload 测量。

## 09-误区
Q: 关于跳表，哪些说法不完整？
A:
- “查询就是 O(log n)”应加期望条件；极端层高分布可退化到 O(n)。
- “层数越高越快”错误；高层过密增加空间与横向比较，过稀又失去索引，p 存在权衡。
- “并发跳表天然无锁”错误；逻辑删除、物理摘链、节点回收与多层发布都需精密协议。
- “只用于 Redis”错误；它是通用有序索引结构，Redis 的具体 encoding、span 和并发模型应在 Redis 牌组学习。
