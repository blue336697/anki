# B 树、B+树与页式索引

> 基线：外存树的目标是用高扇出减少随机页访问；阶、最小度和页容量必须先约定再讨论。

## 01-页式节点
Q: 一个面向磁盘/SSD 的 B+树节点在页内通常长什么样？
A:
- 页头保存节点类型、key 数、空闲区边界、父/兄弟或校验信息；slot directory 指向页内变长 key/record。
- 内部页保存分隔 key 与子页号，叶页保存 key 与 value/记录定位，并常有左右兄弟链。
- 节点容量由页大小减去页头后，再除以 key、指针和 slot 开销，不是抽象的固定“m 阶”常数。
- 页号而非内存裸指针允许缓冲池换入换出；页内搜索可用二分、前缀压缩或 SIMD。

## 02-高扇出与高度
Q: B+树为什么比二叉平衡树更适合外存？
A:
- 一个内部页可容纳数百个 key/child，扇出 f 很大，高度约 `log_f N`；亿级记录也可能只有三四层。
- 一次节点访问对应一次页访问，减少高度就减少昂贵随机 IO；上层热点页还常驻缓冲池。
- 二叉树每节点只排除一半，却为少量 key 引入一次指针跳转/页访问，存储利用率极差。
- SSD 随机读虽比磁盘快，页粒度、写放大和缓存层次仍使高扇出重要。

## 03-B树与B+树
Q: B树和 B+树在数据位置、扇出和范围扫描上有什么本质差异？
A:
- B树内部与叶节点都可保存记录；B+树内部节点只作路由，完整记录或记录指针集中在叶层。
- 相同页大小下，B+树内部项更小、扇出更高；等值查询必须走到叶，但路径稳定且树更矮。
- B+树叶节点按 key 链接，定位范围起点后顺序扫叶即可；B树范围遍历需要跨层中序访问。
- 工程数据库常说 B-tree 但实际变体接近 B+tree，不能仅凭产品文档命名下结论。

## 04-搜索路径
Q: B+树等值和范围查询的完整路径是什么？
A:
- 从根页开始，在当前内部页找到满足分隔规则的 child；重复直到叶页，再在叶内查 key。
- 分隔 key 可能表示右孩子最小值或其他 fence key，等号走左/右必须与构建规则一致。
- 范围查询先按下界定位首叶和槽，然后沿叶 sibling 指针顺序读取，直到超过上界或达到 limit。
- 实际成本由树高页读、叶页数量、缓冲命中和回表组成，复杂度可写为 O(log_f N + K/pageEntries) 页访问。

## 05-插入与分裂
Q: B+树叶页满时如何分裂，父节点怎样更新？
A:
- 先把新记录按序放入临时或页内布局，再把条目分成左右页，修复叶链和日志/锁状态。
- 选取右页的最小 key 作为分隔 key 插入父页；该 key 在叶中仍保留，因为真实数据只在叶层。
- 父页若也满则递归分裂；根分裂会创建新根并让高度增加 1。
- 50/50 分裂实现简单但顺序写可能导致页长期半满；某些系统会做非对称分裂、填充因子或右侧优化。

## 06-删除与合并
Q: B+树删除后的借位、合并和根收缩如何工作？
A:
- 叶内删除后若仍满足最小占用，只需更新可能受影响的父分隔 key；低于阈值则尝试从兄弟借记录。
- 借位要把记录在兄弟间移动，并更新父中的边界 key；借不到则合并页、修复兄弟链并从父删除一个 child。
- 父可能继续下溢并向上合并；若根只剩一个 child，可让该 child 成为新根，高度减一。
- 实际数据库可能延迟合并以避免频繁结构修改和锁竞争，因此物理占用规则未必等同教科书立即修复。

## 07-并发结构修改
Q: 并发 B+树为什么需要 latch coupling 和 B-link Tree 思想？
A:
- 查询下降时要防止节点被并发分裂/合并导致指针失效；简单方案从父到子按序加 latch，再安全释放父。
- 过度持有根到叶路径会限制并发；crabbing 根据 child 是否“安全”尽早释放祖先。
- B-link Tree 给节点增加 high key 和右兄弟指针；若发现目标超出当前页范围，可向右修正，即使父分隔尚未更新。
- latch 保护内存页结构，事务锁保护逻辑记录，两者目的不同；还需 WAL 保证崩溃恢复。

## 08-页分裂影响
Q: B+树页分裂为什么会造成写放大和并发抖动？
A:
- 一次逻辑插入可能写新页、旧页、父页、兄弟链和日志，父满时继续级联。
- 分裂改变多个缓存页并需要结构锁，热点递增 key 虽集中在右端，也可能形成单页争用。
- 随机 key 使写分散和页碎片增多；过低填充因子浪费空间，过高则更频繁分裂。
- 评估索引写成本必须加入 secondary index、WAL、刷盘与复制，不只是 O(log N) 比较。

## 09-正确性与边界
Q: 关于 B+树，哪些常见表述需要纠正？
A:
- “每次查询都三次 IO”不是恒理；高度取决于页和 key，大量上层页可能缓存，叶后还可能回表。
- “B+树所有节点都有链表”通常错误；支持范围扫描的关键是叶层 sibling，内部页实现因系统而异。
- “删除必然立即合并”是教科书简化；工程实现可保留低利用页并由后台整理。
- “B+树只适合磁盘”过度绝对；内存数据库也可能因缓存局部性和范围能力使用变体，但应与并发树比较。
