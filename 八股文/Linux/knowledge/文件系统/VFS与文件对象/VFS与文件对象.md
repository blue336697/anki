# VFS与文件对象

## VFS卡
Q: Linux VFS 虚拟文件系统解决什么问题？
A:
- VFS 为不同文件系统提供统一抽象接口
- 应用通过 open/read/write 等统一系统调用访问文件
- 底层可以是 ext4、xfs、procfs、tmpfs、网络文件系统等
- VFS 屏蔽具体文件系统实现差异
- 面试表达：Linux 一切皆文件的统一体验，很大程度依赖 VFS 抽象

## 对象卡
Q: VFS 中 superblock、inode、dentry、file 分别表示什么？
A:
- superblock 描述一个已挂载文件系统
- inode 描述文件元数据和数据位置，不包含文件名
- dentry 表示目录项，把文件名和 inode 关联起来
- file 表示进程打开的文件实例，包含文件偏移和访问模式
- 多个 file 可以指向同一个 inode

## 打开文件卡
Q: 进程打开文件后，内核中大致有哪些数据结构关联？
A:
- 进程有文件描述符表
- 文件描述符指向打开文件对象 file
- file 指向 dentry 和 inode
- inode 关联具体文件系统操作和数据位置
- 这解释了为什么 fork 后父子进程可能共享文件偏移

## 正确性审查卡
Q: VFS 和文件对象有哪些常见误区？
A:
- “文件名存在 inode 里”：通常错误。文件名在目录项中
- “文件描述符就是文件”：不准确。fd 是进程内整数句柄
- “两个 fd 打开同一文件一定共享偏移”：不一定。dup/fork 共享，独立 open 通常不共享
- “procfs 是普通磁盘文件”：错误。它是内核暴露信息的虚拟文件系统
- “删除文件立即释放磁盘”：若仍有进程打开，空间可能等关闭后释放
