# 进程调度与上下文切换

## 调度卡
Q: Linux 进程调度要解决什么问题？
A:
- 调度器决定下一个运行哪个 task
- 目标是在公平性、吞吐、延迟和实时性之间取舍
- 普通进程主要由 CFS 等公平调度机制管理
- 实时进程使用更高优先级的实时调度策略
- 面试表达：调度不是简单轮流执行，而是根据策略选择可运行任务

## 上下文切换卡
Q: 上下文切换为什么有成本？
A:
- 需要保存当前任务寄存器、栈、程序计数器等状态
- 需要恢复下一个任务的执行上下文
- 可能导致 CPU cache、TLB 热数据失效
- 线程过多或频繁阻塞唤醒会增加切换开销
- 线上 CPU sys 高、cswch 高时要怀疑锁竞争、IO 阻塞或线程过多

## 睡眠唤醒卡
Q: 进程睡眠和唤醒在调度中如何理解？
A:
- 等待 IO、锁、定时器等条件时，进程会进入睡眠状态
- 条件满足后，内核把任务重新放回可运行队列
- 可中断睡眠能响应信号，不可中断睡眠通常等待内核关键资源
- 大量 D 状态进程常提示 IO 或内核资源等待
- 排障时要区分 CPU 忙和进程阻塞

## 正确性审查卡
Q: Linux 调度有哪些常见误区？
A:
- “线程越多吞吐越高”：错误。线程过多会增加切换和竞争
- “load average 高一定是 CPU 不够”：不一定，D 状态 IO 等待也会拉高负载
- “nice 值越高优先级越高”：错误。nice 越高通常越不优先
- “上下文切换只发生在线程之间”：进程、线程、中断返回等都可能发生
- “实时进程一定适合业务服务”：危险。配置不当会饿死普通任务
