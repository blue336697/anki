# 进程线程与fork

## 概念卡
Q: Linux 中进程、线程和 task_struct 如何理解？
A:
- Linux 内核用 `task_struct` 描述可调度实体
- 进程拥有独立地址空间、文件表、信号处理等资源
- 线程共享同一进程的大部分资源，例如地址空间和打开文件
- Linux 线程本质上也是 task，只是 clone 时共享了更多资源
- 面试表达：用户态区分进程线程，内核调度视角主要看 task

## fork卡
Q: fork 创建进程时为什么使用写时拷贝？
A:
- fork 会创建子进程并复制父进程的地址空间视图
- 真实物理页不会立刻复制，而是父子进程共享只读页
- 当任一方写入时触发缺页异常，再复制对应页
- 写时拷贝避免 fork 后立刻 exec 场景的大量无效复制
- 代价是页表仍需复制，且写入时会产生缺页和拷贝开销

## 生命周期卡
Q: 僵尸进程和孤儿进程有什么区别？
A:
- 子进程退出后，父进程未 wait 回收，子进程保留退出状态成为僵尸进程
- 僵尸进程不占用大量内存，但占用进程表项
- 父进程退出后，子进程变成孤儿进程
- 孤儿进程通常会被 init/systemd 接管并回收
- 线上看到僵尸进程要找父进程为什么不 wait

## 正确性审查卡
Q: Linux 进程线程有哪些常见误区？
A:
- “线程一定比进程轻很多”：不完整。线程共享资源多，但调度实体仍是 task
- “fork 会立刻复制全部内存”：错误。现代 Linux 使用写时拷贝
- “僵尸进程占满内存”：通常不是，主要占进程表项
- “kill 僵尸进程即可解决”：僵尸已退出，应处理父进程回收问题
- “进程和线程在内核里完全不同”：不准确。Linux 中都由 task_struct 表达
