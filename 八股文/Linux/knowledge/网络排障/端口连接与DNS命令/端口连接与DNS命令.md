# 端口连接与DNS命令

## 端口卡
Q: Linux 上如何排查端口占用和监听状态？
A:
- `ss -lntp` 查看 TCP 监听端口和进程
- `ss -antp` 查看连接状态
- `lsof -i :port` 可定位占用端口的进程
- `netstat` 老系统常见，但新系统更推荐 ss
- 排查时要区分 LISTEN、ESTABLISHED、TIME_WAIT、CLOSE_WAIT 等状态

## DNS卡
Q: Linux 上如何排查域名解析问题？
A:
- `nslookup` 或 `dig` 查询 DNS 解析结果
- 查看 `/etc/resolv.conf` 确认 DNS 服务器
- 用 `curl -v` 或 `ping` 区分解析失败和连接失败
- 注意应用可能有 DNS 缓存，JVM 也可能缓存解析结果
- 容器内还要检查容器 DNS 配置和集群 DNS

## 网络链路卡
Q: 线上服务连接失败时如何分层排查？
A:
- 先确认域名解析是否正确
- 再确认目标 IP 和端口是否可达
- 检查本机监听、防火墙、安全组和路由
- 查看服务日志和连接状态
- 最后再看网络丢包、延迟、DNS、负载均衡和上游限流

## 正确性审查卡
Q: Linux 网络排障有哪些常见误区？
A:
- “ping 通就代表服务可用”：错误。ping 只说明 ICMP 层面可达
- “端口没通一定是服务挂了”：不一定。可能防火墙、路由、安全组或 LB 问题
- “TIME_WAIT 都要清掉”：危险。它有协议正确性价值
- “DNS 解析结果永远实时”：错误。存在多级缓存
- “容器里和宿主机网络一样”：不一定。网络命名空间和 DNS 配置可能不同
