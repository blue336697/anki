# 页缓存与回写

## PageCache卡
Q: Linux 页缓存 Page Cache 有什么作用？
A:
- 页缓存缓存文件数据页，减少磁盘读写
- read 可能直接从页缓存返回
- write 通常先写入页缓存并标记脏页
- 后台 flusher 线程异步把脏页回写到磁盘
- 面试表达：很多文件 IO 性能来自页缓存，而不是磁盘真的很快

## fsync卡
Q: fsync、fdatasync 和普通 write 有什么区别？
A:
- 普通 write 返回时数据可能只在页缓存中
- fsync 要求文件数据和必要元数据持久化
- fdatasync 通常只要求数据和必要元数据持久化，减少部分元数据刷盘
- 数据库和日志系统常用 fsync 控制崩溃一致性
- 频繁 fsync 会显著影响写入延迟

## 回写卡
Q: 脏页回写会带来哪些线上影响？
A:
- 脏页积累过多会触发集中回写，造成 IO 抖动
- 应用写入可能被内核节流
- 大量回写会影响读 IO 延迟
- 容器环境中页缓存也会占用宿主机内存
- 排查时要看 dirty、writeback、iostat 和应用 fsync 模式

## 正确性审查卡
Q: 页缓存和回写有哪些常见误区？
A:
- “free 看到内存少就是内存泄漏”：不一定。Linux 会用空闲内存做 cache
- “write 成功表示数据已持久化”：错误。需要 fsync 或相关语义
- “drop_caches 是常规优化手段”：错误。它只是排障或测试工具
- “页缓存只影响读”：错误。写回和脏页也很关键
- “fsync 越多越安全且无代价”：错误。安全性提高但延迟成本高
