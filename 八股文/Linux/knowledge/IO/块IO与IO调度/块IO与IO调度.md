# 块IO与IO调度

## 块IO卡
Q: Linux 块 I/O 层解决什么问题？
A:
- 块 I/O 层把文件系统和块设备驱动连接起来
- 上层提交 bio 描述要读写的页和扇区
- 请求队列对 bio/request 进行合并、排序和调度
- 目标是减少随机 IO、提升吞吐并控制延迟
- 面试表达：应用一次 write 到真正落盘，中间经过 VFS、页缓存、文件系统和块层

## 调度卡
Q: I/O 调度器为什么重要？
A:
- 磁盘随机访问成本高，调度器可合并相邻请求
- 可调整请求顺序，减少寻道或优化队列
- 不同设备适合不同策略，SSD 和 HDD 关注点不同
- 高并发 IO 下调度影响吞吐和尾延迟
- 现代系统还要结合 blk-mq、多队列和 NVMe 特性

## DirectIO卡
Q: Buffered I/O 和 Direct I/O 有什么区别？
A:
- Buffered I/O 经过页缓存，读写可能命中内存
- Direct I/O 尽量绕过页缓存，减少双缓存
- 数据库常用 Direct I/O 自己管理缓存
- Buffered I/O 对普通文件访问简单高效
- Direct I/O 对对齐、批量和应用缓存管理要求更高

## 正确性审查卡
Q: Linux 块 IO 有哪些常见误区？
A:
- “write 返回就是落盘”：错误。可能只是写入页缓存
- “Direct I/O 一定更快”：不一定。绕过页缓存也失去缓存收益
- “SSD 不需要 IO 调度”：不完整。仍有队列、合并和延迟控制
- “IO 慢只看磁盘”：还要看文件系统、页缓存、队列和应用访问模式
- “顺序写一定没有抖动”：fsync、回写和设备缓存仍可能带来延迟
