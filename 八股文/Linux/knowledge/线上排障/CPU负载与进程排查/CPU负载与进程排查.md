# CPU负载与进程排查

## Load卡
Q: load average 高应该如何理解？
A:
- load average 表示一段时间内可运行和不可中断等待任务的平均数量
- 它不等同于 CPU 使用率
- CPU 密集任务会拉高 load
- D 状态 IO 等待任务也会拉高 load
- 判断是否异常要结合 CPU 核数、us/sy/wa、进程状态和业务流量

## CPU卡
Q: CPU 使用率高如何排查？
A:
- `top` 或 `htop` 找到高 CPU 进程
- `top -H -p pid` 查看进程内线程
- Java 服务可把线程 ID 转十六进制对照 `jstack`
- `perf top` 可看热点内核/用户函数
- 区分用户态 CPU、系统态 CPU、软中断和 IO wait

## 进程卡
Q: 进程状态 R、S、D、Z 分别表示什么？
A:
- R 表示运行中或可运行
- S 表示可中断睡眠，常见于等待事件
- D 表示不可中断睡眠，常见于等待 IO 或内核资源
- Z 表示僵尸进程，等待父进程回收
- 状态比单纯 CPU 数值更能解释系统卡在哪里

## 正确性审查卡
Q: CPU 和负载排查有哪些常见误区？
A:
- “load 高就是 CPU 打满”：错误。D 状态也会推高 load
- “CPU idle 高就一定没问题”：不一定。可能大量任务在 IO wait
- “kill -9 总能解决”：不一定。D 状态进程可能无法立即杀掉
- “只看进程不看线程”：多线程服务要定位到具体线程
- “sy 高无所谓”：系统态高可能说明网络、锁、系统调用或内核路径压力大
