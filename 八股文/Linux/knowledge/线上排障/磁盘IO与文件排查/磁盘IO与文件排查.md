# 磁盘IO与文件排查

## 磁盘卡
Q: Linux 上如何排查磁盘空间问题？
A:
- `df -h` 查看文件系统空间使用
- `du -sh *` 或 `du -xhd1` 定位目录占用
- `lsof | grep deleted` 查找已删除但仍被进程占用的文件
- inode 用尽时 `df -i` 会异常
- 日志、临时文件、core dump 和容器层是常见空间来源

## IO卡
Q: Linux 上如何排查磁盘 IO 瓶颈？
A:
- `iostat -x` 查看 util、await、r/s、w/s、队列等指标
- `iotop` 或 pidstat 定位进程级 IO
- 区分顺序 IO、随机 IO、读写比例和 fsync 压力
- 查看应用日志是否有慢查询、刷盘、checkpoint 或大文件操作
- 云盘环境还要看 IOPS、吞吐和延迟配额

## 删除卡
Q: 为什么删除大文件后磁盘空间没有释放？
A:
- 文件被删除后目录项消失，但如果进程仍打开该文件，inode 和数据块仍被占用
- 直到最后一个文件描述符关闭，空间才会释放
- 可用 `lsof | grep deleted` 找到占用进程
- 日志文件被删除但进程继续写入是常见原因
- 正确做法通常是让进程重新打开日志或重启相关服务

## 正确性审查卡
Q: 磁盘和 IO 排查有哪些常见误区？
A:
- “df 和 du 不一致就是命令错了”：不一定。可能有 deleted open file
- “磁盘 util 100% 就一定吞吐满”：不完整。也可能小 IO 延迟高
- “删除日志文件是安全释放空间”：危险。进程仍打开时不会释放
- “IO 慢只看磁盘”：还要看文件系统、页缓存、同步刷盘和应用模式
- “inode 不会用完”：小文件海量场景可能先耗尽 inode
