# 中断上半部与下半部

## 中断卡
Q: Linux 中断机制解决什么问题？
A:
- 外设通过中断通知 CPU 有事件需要处理
- 中断让 CPU 不必一直轮询设备状态
- 中断处理程序运行在中断上下文中，要求尽快完成
- 中断处理要避免长时间占用 CPU，影响系统响应
- 面试表达：中断是硬件事件进入内核处理流程的重要入口

## 上下半部卡
Q: 为什么中断处理要分上半部和下半部？
A:
- 上半部处理必须立即完成的工作，例如确认中断、读取关键状态
- 下半部处理可以延后的耗时工作
- 这样能缩短中断关闭或中断上下文占用时间
- 下半部机制包括软中断、tasklet、工作队列等
- 工作队列运行在进程上下文，可睡眠，适合更重的异步任务

## 软中断卡
Q: 软中断、tasklet、工作队列如何区分？
A:
- 软中断适合高频并发处理，例如网络收发
- tasklet 基于软中断，简化同类任务串行约束
- 工作队列把任务交给内核线程执行，可以睡眠
- 是否能睡眠、是否可并发、延迟要求是选择关键
- 现代内核中 tasklet 已逐渐不再是新代码首选

## 正确性审查卡
Q: 中断处理有哪些常见误区？
A:
- “中断里可以做任何事情”：错误。中断上下文限制很多
- “下半部就是另一个线程”：不准确。不同机制上下文不同
- “网络包都在应用线程处理”：错误。内核网络收包大量依赖中断和软中断
- “中断越多越好”：不一定。中断风暴会拖垮 CPU
- “工作队列一定实时”：不保证。它依赖内核线程调度
