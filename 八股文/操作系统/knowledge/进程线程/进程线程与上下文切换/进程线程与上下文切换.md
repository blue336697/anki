# 进程线程与上下文切换

## 进程线程卡
Q: 进程和线程的核心区别是什么？
A:
- 进程是资源分配和隔离单位，有独立地址空间
- 线程是 CPU 调度执行单位，同进程线程共享地址空间和文件等资源
- 线程切换通常比进程切换轻，但仍有寄存器、栈和调度成本
- 多线程共享内存方便协作，也带来数据竞争和同步问题
- 面试表达：进程强调隔离，线程强调共享和执行流

## 上下文切换卡
Q: 上下文切换为什么有成本？
A:
- 需要保存当前执行流的寄存器、程序计数器、栈等状态
- 需要恢复下一个执行流的状态
- 可能导致 CPU Cache 和 TLB 热数据失效
- 线程过多、锁竞争、频繁阻塞唤醒都会增加切换
- 后端服务线程池过大时，吞吐可能不升反降

## fork-exec卡
Q: Unix 中 fork 和 exec 为什么经常配合使用？
A:
- fork 复制当前进程，创建子进程
- 写时拷贝让 fork 不必立刻复制全部物理内存
- exec 用新程序替换当前进程映像
- shell 启动外部命令通常就是 fork 子进程后 exec
- 这种模型把进程创建和程序加载拆成两个简单原语

## 正确性审查卡
Q: 进程线程有哪些常见误区？
A:
- “线程没有隔离”：不完整。线程共享进程资源，但仍有独立栈和执行上下文
- “线程越多越快”：错误。过多会增加切换和竞争
- “fork 会立即复制全部内存”：现代系统通常使用写时拷贝
- “上下文切换只消耗 CPU 指令”：还会破坏缓存局部性
- “多进程一定比多线程慢”：不绝对。取决于隔离、通信和工作负载
