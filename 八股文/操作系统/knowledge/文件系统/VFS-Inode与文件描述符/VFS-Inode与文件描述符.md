# VFS-Inode与文件描述符

## VFS卡
Q: VFS 虚拟文件系统解决什么问题？
A:
- VFS 给不同文件系统提供统一抽象
- 应用通过 open/read/write 等统一接口访问文件
- 底层可以是磁盘文件系统、procfs、tmpfs、设备文件等
- VFS 屏蔽具体文件系统差异
- 面试表达：一切皆文件的统一接口背后是 VFS 抽象

## inode卡
Q: inode、dentry、file、文件描述符分别表示什么？
A:
- inode 表示文件元数据和数据位置，通常不保存文件名
- dentry 表示目录项，把名字和 inode 关联起来
- file 表示一次打开文件的内核对象，包含偏移和访问模式
- 文件描述符是进程文件表里的整数句柄
- 多个 fd 可能指向同一个 file 或同一个 inode

## xv6文件系统卡
Q: xv6 文件系统为什么适合理解真实文件系统？
A:
- xv6 保留 inode、目录、文件描述符、buffer cache 等核心概念
- 代码比 Linux 小很多，适合追踪 open/read/write 路径
- 它能展示系统调用如何进入文件系统层
- 也能理解目录项到 inode 再到磁盘块的映射
- 面试表达：xv6 是简化模型，但概念映射到 Unix/Linux 很有价值

## 正确性审查卡
Q: 文件系统有哪些常见误区？
A:
- “文件名存在 inode 里”：通常错误。文件名属于目录项
- “fd 就是文件本身”：错误。fd 是进程内句柄
- “删除文件立刻释放空间”：若仍被进程打开，空间可能暂不释放
- “所有文件都在磁盘上”：procfs、tmpfs、设备文件都不是普通磁盘文件
- “fork 后文件偏移一定独立”：父子进程可能共享打开文件对象和偏移
