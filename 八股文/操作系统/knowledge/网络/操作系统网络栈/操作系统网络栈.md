# 操作系统网络栈

## 收包卡
Q: 一个网络包到达主机后，操作系统大致如何处理？
A:
- 网卡接收数据并通过 DMA 放入内存缓冲
- 网卡中断或 NAPI 通知内核处理
- 内核网络栈解析二层、IP、TCP/UDP 等协议
- 数据进入 socket 接收缓冲区
- 应用通过 read/recv 从 socket 读取数据

## 发送卡
Q: 应用 send 数据后，操作系统大致做了什么？
A:
- 数据从用户缓冲区进入内核 socket 发送缓冲
- TCP 负责分段、拥塞控制、重传和流量控制
- IP 层路由选择，链路层封装帧
- 网卡通过 DMA 读取发送缓冲并发出
- send 返回不代表对端已经收到，只代表本机内核接收了发送请求或部分数据

## 瓶颈卡
Q: 操作系统网络栈常见性能瓶颈有哪些？
A:
- 软中断 CPU 高，收包处理不过来
- socket 缓冲区满，导致丢包或阻塞
- 连接数过多导致 fd、内存、调度压力
- 小包过多带来中断和协议栈开销
- 应用处理慢也会反压内核缓冲区

## 正确性审查卡
Q: OS 网络栈有哪些常见误区？
A:
- “send 成功表示对端收到”：错误。TCP 仍可能在本机缓冲或网络中
- “丢包一定发生在网络线路”：不一定。主机接收队列、socket buffer 也可能丢
- “网卡中断越多越好”：不一定。软中断过高会拖垮业务线程
- “应用只要 epoll 就不会有网络瓶颈”：错误。协议栈、缓冲、拷贝和业务处理都重要
- “TCP 可靠所以应用不用处理失败”：错误。连接断开、超时、半开都要处理
