# 设备驱动与中断处理

## 驱动卡
Q: 设备驱动在操作系统中扮演什么角色？
A:
- 驱动把硬件设备封装成内核可操作的接口
- 上层通过文件、网络、块设备等抽象访问设备
- 驱动负责寄存器读写、DMA、中断处理和设备状态管理
- 操作系统通过驱动屏蔽硬件差异
- 面试表达：驱动是 OS 与硬件之间的适配层

## 中断卡
Q: 中断处理为什么要尽快完成？
A:
- 中断上下文会打断当前执行流
- 长时间处理中断会影响系统响应和其他中断处理
- 上半部处理关键确认和状态读取
- 下半部处理可延后的耗时工作
- 网络收包、磁盘完成通知都大量依赖中断机制

## DMA卡
Q: DMA 对设备 IO 有什么价值？
A:
- DMA 允许设备直接和内存交换数据
- CPU 不必逐字节搬运数据
- CPU 负责设置缓冲区、长度、方向等描述信息
- 设备完成后通过中断通知 CPU
- DMA 提升吞吐，但要处理缓存一致性、内存映射和权限问题

## 正确性审查卡
Q: 设备驱动和中断有哪些常见误区？
A:
- “所有 IO 都由 CPU 亲自搬运”：错误。DMA 很常见
- “中断处理越完整越好”：错误。耗时工作应延后
- “驱动只是调用硬件 API”：不准确。它要处理并发、错误、缓冲和生命周期
- “设备文件就是普通文件”：不一定。很多设备文件背后是驱动操作
- “中断越多说明吞吐越高”：不一定。中断风暴会拖垮 CPU
