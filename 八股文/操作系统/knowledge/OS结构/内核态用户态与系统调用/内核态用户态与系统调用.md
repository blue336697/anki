# 内核态用户态与系统调用

## 隔离卡
Q: 操作系统为什么要区分用户态和内核态？
A:
- 用户态运行普通应用，权限受限
- 内核态运行操作系统核心代码，可访问硬件和关键资源
- 区分特权级能防止应用随意破坏内核和其他进程
- 应用通过系统调用受控地请求内核服务
- MIT 6.S081 的 xv6 也用这种隔离解释 Unix 风格 OS 结构

## 系统调用卡
Q: 系统调用从用户程序进入内核的大致路径是什么？
A:
- 用户程序调用 C 库封装函数，例如 read、write、fork
- 通过特殊指令触发 trap，CPU 切换到内核态
- 内核保存用户上下文，并根据系统调用号分派处理函数
- 内核校验参数，执行资源访问或调度逻辑
- 处理完成后恢复用户上下文返回用户态

## API卡
Q: API、库函数和系统调用有什么区别？
A:
- API 是暴露给程序员的接口约定
- C 库函数是用户态封装，可能调用系统调用，也可能完全在用户态完成
- 系统调用是真正进入内核的边界
- 例如 printf 通常先写用户态缓冲，最终可能调用 write
- 面试表达：不要把库函数和 syscall 混成一件事

## 正确性审查卡
Q: 用户态/内核态和系统调用有哪些常见误区？
A:
- “系统调用就是普通函数调用”：错误。它涉及特权级切换
- “进入内核态一定很慢到不能用”：不完整。成本高于函数调用，但系统设计会批量和缓存优化
- “内核可以信任用户指针”：错误。必须校验和安全拷贝
- “所有库函数都会进入内核”：错误。很多库函数只在用户态执行
- “xv6 太简单所以没用”：不对。它适合理解 OS 核心路径
