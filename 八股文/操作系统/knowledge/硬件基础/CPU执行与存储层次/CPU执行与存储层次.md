# CPU执行与存储层次

## 执行过程卡
Q: CPU 执行一条程序语句的大致过程是什么？
A:
- 程序先被编译成机器指令和数据
- CPU 通过程序计数器取指令，完成取指、译码、执行、写回
- 指令执行过程中会访问寄存器、Cache、内存和外设
- 指令本身不理解高级语言语义，只执行机器级操作
- 面试表达：高级代码最终会落到指令流和数据访问上，性能问题也常回到这两者

## 存储层次卡
Q: 为什么计算机需要寄存器、Cache、内存、磁盘这样的存储层次？
A:
- 越靠近 CPU 的存储越快但越贵、容量越小
- 寄存器最快，Cache 次之，内存更大但慢，磁盘容量最大但最慢
- 存储层次利用程序局部性，用小而快的缓存承接热点数据
- 操作系统和硬件共同管理这些层次，例如页缓存、TLB、CPU Cache
- 面试表达：很多性能优化本质是在提升局部性、减少跨层访问

## 局部性卡
Q: 时间局部性和空间局部性如何影响程序性能？
A:
- 时间局部性表示刚访问过的数据很可能再次被访问
- 空间局部性表示访问某地址后，附近地址也可能被访问
- 数组顺序扫描通常比链表随机访问更 cache 友好
- 循环顺序、数据布局、批处理都会影响 Cache 命中率
- 后端代码中的序列化、批量处理、列式存储也能体现局部性思想

## 正确性审查卡
Q: CPU 和存储层次有哪些常见误区？
A:
- “CPU 快所以内存访问无所谓”：错误。内存访问相对 CPU 非常慢
- “Cache 对程序员完全透明”：不完整。数据布局和访问模式会显著影响命中率
- “SSD 和内存差不多快”：错误。延迟量级仍差很多
- “优化只看算法复杂度”：不够。缓存局部性和常数成本也很关键
- “寄存器、Cache、内存都是操作系统直接管理”：不准确。CPU Cache 多由硬件管理
