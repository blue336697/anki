# 分层模型与端到端包路径

## 01-分层职责
Q: TCP/IP 分层各自解决什么问题？
A:
- 链路层负责同一链路上的帧交付和介质访问；网络层用 IP 完成跨网络逐跳转发。
- 传输层在端系统进程间提供复用、可靠字节流或数据报；应用层定义业务消息语义。
- 每层只承诺自己的服务并使用下层能力，分层让路由器、操作系统和应用可以独立演进。
- OSI 七层适合概念定位，工程排障通常用链路/IP/TCP/应用四五层模型。

## 02-封装解封
Q: 应用数据从发送进程到网卡时怎样被封装？
A:
- 应用写入 socket 后，传输层添加 TCP/UDP 头并按 MSS/拥塞窗口组织发送。
- IP 层选择路由、源地址并添加 IP 头；邻居子系统解析下一跳 MAC，链路层生成 Ethernet 帧。
- 网卡从 DMA ring 读取描述符和数据，计算部分校验/分段后发送；接收端按相反方向解封装。
- “一层加一个头”是逻辑模型，TSO/GSO/GRO 等卸载会让抓包看到与线上帧不同的分段时机。

## 03-交换与路由
Q: 二层交换机和三层路由器转发依据有什么区别？
A:
- 交换机通常按目的 MAC 查转发表，在广播域内转发帧；学习源 MAC 与入端口建立表项。
- 路由器按目的 IP 做最长前缀匹配，选择下一跳和出接口，并为每一跳重新封装链路层头。
- IP 源/目的通常端到端不变，MAC 源/目的每跳变化；NAT 等中间盒会显式改写 IP/端口。
- 路由器会递减 TTL/Hop Limit，避免环路永久转发。

## 04-端系统原则
Q: 为什么 TCP 可靠性主要放在端系统而不是每台路由器？
A:
- 中间网络只尽力而为转发，路由器可丢包、乱序、重路由，维护每条连接状态会降低可扩展性。
- 发送端序号、重传和拥塞控制，接收端确认与重组，最终才能判断完整端到端语义。
- 链路层重传可优化局部无线错误，却不能替代跨路径故障和接收进程状态。
- 端到端原则不是“网络完全无状态”，NAT、防火墙和负载均衡会引入状态与新的故障边界。

## 05-一次HTTP请求
Q: 浏览器访问一个新域名时，网络上依次可能发生什么？
A:
1. DNS 解析目标地址；检查路由与邻居缓存，必要时 ARP/NDP 获得下一跳链路地址。
2. TCP 三次握手或 QUIC 建连；HTTPS 再完成 TLS 身份认证与密钥协商。
3. 发送 HTTP 请求，分组经交换、路由、NAT/代理到服务端，响应沿可能不同路径返回。
4. 各层缓存和连接复用可跳过部分步骤，所以实际时序必须以抓包、DNS 和连接状态验证。

## 06-排障分层
Q: 端到端请求失败时如何按层快速缩小范围？
A:
- 先查本机地址、路由、邻居与 DNS；再确认目标 IP/端口能否建立连接和握手停在哪一步。
- TCP 已建立但应用超时，应检查 TLS、HTTP、代理队列和服务处理，而不是继续只 ping。
- ping 通不代表端口、路径 MTU、双向路由和应用健康；ping 不通也可能只是 ICMP 被过滤。
- 每层都要拿证据：ip/ss/dig、tcpdump、服务日志和指标形成同一时间线。
