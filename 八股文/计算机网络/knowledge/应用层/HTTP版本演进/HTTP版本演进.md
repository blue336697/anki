Q: HTTP/1.0 和 HTTP/1.1 的主要区别是什么？
A:
- HTTP/1.0 默认短连接，每个请求常新建 TCP 连接
- HTTP/1.1 默认持久连接，可复用 TCP 连接处理多个请求
- HTTP/1.1 增加 Host 头，支持虚拟主机
- HTTP/1.1 支持 chunked 传输、更多缓存控制和范围请求
- 但 HTTP/1.1 同一连接上仍存在队头阻塞问题

## HTTP/2 卡
Q: HTTP/2 解决了 HTTP/1.1 哪些问题？
A:
- 二进制分帧让协议解析更高效
- 多路复用允许一个 TCP 连接上并发多个请求/响应
- HPACK 头部压缩减少重复 header 开销
- 支持流优先级和服务器推送
- 面试边界：HTTP/2 解决应用层队头阻塞，但仍受 TCP 层队头阻塞影响

## HTTP/3 卡
Q: HTTP/3 为什么基于 QUIC/UDP？它解决了什么问题？
A:
- HTTP/3 基于 QUIC，而 QUIC 运行在 UDP 之上
- QUIC 在传输层实现多路复用，避免 TCP 丢包导致所有流一起阻塞
- QUIC 集成 TLS 1.3，减少握手时延
- QUIC 使用连接 ID，网络切换时更容易保持连接
- 面试表达：HTTP/3 的关键不是"UDP 更快"，而是 QUIC 在用户态重新设计可靠传输和多路复用

## 队头阻塞卡
Q: HTTP 队头阻塞在不同版本中分别指什么？
A:
- HTTP/1.1 管线化中，前一个响应没回来会阻塞后续响应处理，这是应用层队头阻塞
- HTTP/2 多路复用解决了应用层队头阻塞
- 但 HTTP/2 仍在一个 TCP 连接上，TCP 丢包会阻塞该连接上所有流的数据交付
- HTTP/3/QUIC 把多路复用放到传输层用户态，单个流丢包不必阻塞其他流
- 面试亮点：要区分 HTTP 层队头阻塞和 TCP 层队头阻塞

## 工程实践卡
Q: 后端服务升级 HTTP/2/HTTP/3 时要考虑什么？
A:
- 客户端、网关、CDN、负载均衡和服务框架是否支持
- TLS 证书、ALPN 协商和协议降级策略是否正确
- 长连接、多路复用会改变连接数、并发流、限流和超时配置
- HTTP/3 依赖 UDP，可能受企业网络、防火墙和运营商策略影响
- 需要用真实指标验证延迟、错误率、CPU 和带宽变化

## 正确性审查卡
Q: HTTP 版本演进有哪些常见误区？
A:
- "HTTP/2 就不需要 TCP"：错误。HTTP/2 通常仍基于 TCP
- "HTTP/3 是不可靠的"：错误。QUIC 基于 UDP 但自己实现可靠传输
- "多路复用等于没有任何阻塞"：不准确。HTTP/2 仍有 TCP 层队头阻塞
- "服务器推送是 HTTP/2 最大收益"：不一定。实践中推送使用谨慎，很多收益来自多路复用和头压缩
- "升级协议一定提升性能"：不一定。要看网络环境、实现、配置和业务请求形态
