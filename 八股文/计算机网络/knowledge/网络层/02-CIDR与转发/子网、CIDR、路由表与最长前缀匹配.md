# 子网、CIDR、路由表与最长前缀匹配

## 01-前缀语义
Q: CIDR 前缀 `/p` 怎样划分网络与主机部分？
A:
- IPv4 前 p 位是网络前缀，剩余位标识该前缀内地址；掩码是 p 个 1 后接 0。
- 判断同网段使用 `(address & mask)==network`，不是比较十进制字符串前几段。
- 传统 IPv4 子网常保留全 0 网络地址和全 1 广播地址，但点到点/特殊前缀有例外。
- CIDR 取代 classful 固定 A/B/C 类，可任意前缀聚合并减少路由表。

## 02-主机选路
Q: 主机发送目的 IP 时如何决定直连还是交给网关？
A:
- 查本机 routing policy/table，选择匹配目的的最具体路由；connected route 指向本地链路。
- 直连路由解析目标 IP 的邻居地址；经网关路由解析 next-hop 网关 MAC。
- 若无更具体路由，使用 default route；完全无路由则本地返回 network unreachable。
- 多网卡、源地址策略和容器 namespace 会产生多张表，不能只看一条默认路由。

## 03-最长前缀
Q: 路由器为什么使用 Longest Prefix Match？
A:
- 一个目的可同时匹配默认 `/0`、聚合前缀和更具体子网；最长前缀代表最精确规则。
- 例如 `/24` 优先于 `/16`，metric 通常只在同前缀长度或协议策略中比较。
- 控制平面通过 OSPF/BGP/静态路由产生 RIB，路由器选优后下发适合高速查找的 FIB。
- LPM 可用 trie/TCAM 等实现，数据面不在每包运行完整路由协议。

## 04-下一跳递归
Q: 路由条目指定 next-hop 后为什么还需要递归解析？
A:
- FIB 知道“去目标先找网关 G”，但还需找到到 G 的出接口/直连路由，最终获得链路层邻居。
- 若 next-hop 本身不可达，路由即使存在也无法转发；控制面可撤销或标记 unresolved。
- ECMP 可为同前缀保留多个等价下一跳，通常按 flow hash 选择以避免单连接乱序。
- 修改 hash seed/成员会造成部分流迁移，不等同逐包轮询。

## 05-路由聚合
Q: 路由聚合为什么减少表项，又会带来什么风险？
A:
- 多个连续子前缀可由共同更短前缀宣告，减少控制更新、FIB 容量和查找压力。
- 聚合会隐藏内部拓扑；若聚合者宣告但某子网实际不可达，流量可能被吸入黑洞。
- 常配置 discard/null route 覆盖聚合范围，并由更具体路由优先承接真实子网。
- BGP 更具体前缀会因 LPM 胜过聚合，既用于流量工程也可能被错误/劫持滥用。

## 06-排障
Q: “目标 IP 能 ping，域名服务不通”的路由排障应看什么？
A:
- 分别确认域名解析出的每个 A/AAAA 地址、源地址选择和对应 route get，IPv4/IPv6 路径可能不同。
- 检查回程路由、策略路由、NAT 和安全组；单向可达会表现握手 SYN 重传。
- traceroute 只显示愿意返回 ICMP 的跳点，星号不必然是断点；应结合终点抓包。
- 路由表“有条目”不等于邻居、ACL、MTU 和服务端口都正常。
