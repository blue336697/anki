# 背景

公司全面推行全栈工程师的概念，正好有次完整需求试试手，从需求分析、前后端以及测试工作全部交给AI来做，最终结果也是不出意外的出意外了

# 事情经过

上线当晚

- 预发复现了一个前端问题，类似于后端的空指针，会导致登录进去菜单导航栏全部空白
- 让AI修复在开发分支，本地正常后合并到预发分支，预发验证也没问题
- 关键点：问AI是否修复逻辑都在已经提交并且推送了，且两个分支都已经修改了吗，AI答没问题
- 后续测试全部完成后推生产，无论使用的新旧测试账号都没有前面说的BUG了

第二天

- 领导打电话说：客户空白页怎么回事
- 到公司后第一件事先恢复现场，复现看到控制台的报错，心里凉了半截
- 然后看了修改痕迹，发现预发分支上有，但是开发分支上没有，而上线流程实际上跟预发分支没关系
- 随后迅速修复推生产了一版本

# 原因

直接原因

AI引用两个变量名都引用错了，导致的类似后端空指针的效果

核心原因
全栈开发规范不规范所造成的必然，现在AI能力虽然看着很厉害，但实际上上手用并且吃过几次亏以后就会发现里什么都不操心全交给他做还有一段距离

- 首先AI改动的这个文件，是一个权限分发ts，是一个很早就不修改且稳定的东西，但是这次需求需要一些权限的改动，AI直接从根文件改，而且改的都是写死逻辑，很让人怀疑
- 其次应用的变量名都能错

# 反思

现在前后端都比较倡导使用openspec来管理项目开发，随着研究的深入，发现一些环节还是需要有经验的人去把关

1. 线下全栈流程：
    1. 需求评审
    2. 哪些需求适合全栈
    3. openspec 生成设计方案
    4. 前后端评审设计方案
    5. AI Coding
    6. 仓库提 PR 时前后端 review
    7. 前后端测试
2. 线上全栈流程：人换为模型，claude 去 review codex
3. 前后端同学自行组 buddy，互相学习、评审
4. 探索 BAT 全栈流程
