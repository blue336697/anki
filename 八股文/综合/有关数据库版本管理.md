# Flyway

## 常见接口

### Callback

在 Flyway（一个常用的数据库版本管理和迁移工具）中，Callback 接口的作用是**在数据库迁移生命周期的各个阶段插入自定义逻辑**。也就是说，你可以通过实现 Callback 接口，在 Flyway 执行迁移操作（如迁移前、迁移后、校验、清理等）时自动触发你自己的代码。

**1. 主要作用**

---

- 允许开发者在 Flyway 迁移流程的**特定事件点**（如迁移开始、迁移结束、迁移失败等）执行自定义操作。
- 常用于**日志记录、通知、数据校验、环境准备、清理等场景**。

**2. 常见事件**

Flyway 支持的事件包括但不限于：

- beforeMigrate（迁移前）
- afterMigrate（迁移后）
- beforeEachMigrate（每条迁移前）
- afterEachMigrate（每条迁移后）
- beforeClean、afterClean
- beforeValidate、afterValidate
- beforeUndo、afterUndo
- beforeBaseline、afterBaseline
- beforeRepair、afterRepair
- beforeInfo、afterInfo
- beforeEachUndo、afterEachUndo
- beforeEachValidate、afterEachValidate

**3. 使用方式**

你可以通过实现 org.flywaydb.core.api.callback.Callback 接口，重写对应的事件方法，然后将实现类配置到 Flyway 中。

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class DistributedLockCallback implements Callback {

    private final RedissonClient redissonClient;
    private final FlywayDBProperties flywayDBProperties;
    private static final String LOCK_KEY = "Sturnus:flyway:migration:lock:%s";
    private static final Integer LOCK_RETRY_COUNT = 10;
    private static final Integer LOCK_RETRY_INTERVAL = 10;
    private static final String LOCK_VALUE = "locked";
    private static final long LOCK_TIMEOUT = 300; // 5分钟超时
    private RLock lock = null;

    @Override
    public boolean supports(Event event, Context context) {
        return event == Event.BEFORE_MIGRATE || event == Event.AFTER_MIGRATE;
    }

    @Override
    public boolean canHandleInTransaction(Event event, Context context) {
        return false;
    }

    @Override
    public void handle(Event event, Context context) {
        if (event == Event.BEFORE_MIGRATE) {
            this.lock = this.acquireLock();
        } else if (event == Event.AFTER_MIGRATE) {
            this.releaseLock();
        }
    }

    private RLock acquireLockWithRetry() {
        int retryCount = 0;
        Exception lastException = null;
        long startTime = System.currentTimeMillis();
        while (retryCount < LOCK_RETRY_COUNT) {
            try {
                log.info("acquireLockWithRetry Flyway {} times try", retryCount + 1);
                RLock rLock = this.acquireLock();
                long duration = System.currentTimeMillis() - startTime;
                log.info("acquireLock cost: {} ms", duration);
                if (Objects.nonNull(rLock)) {
                    return rLock;
                }
            } catch (Exception e) {
                lastException = e;
                retryCount++;
                if (retryCount < LOCK_RETRY_COUNT) {
                    long waitTime = LOCK_RETRY_INTERVAL * 1000;
                    log.warn("acquireLock failed {} times wait {} seconds, exception: {}", retryCount,
                        LOCK_RETRY_INTERVAL, e.getMessage());
                    try {
                        Thread.sleep(waitTime);
                    } catch (InterruptedException ie) {
                        Thread.currentThread().interrupt();
                        throw new FlywayException("retry interrupt", ie);
                    }
                }
            }
        }
        long totalDuration = System.currentTimeMillis() - startTime;
        String errorMsg = String.format("Flyway acquireLock failed, try %d times，cost: %d ms，DB: %s", retryCount,
            totalDuration, this.flywayDBProperties.getDb());
        log.error(errorMsg);
        throw new FlywayException(errorMsg, lastException);
    }

    @SneakyThrows
    private RLock acquireLock() {
        String lockKey = String.format(LOCK_KEY, this.flywayDBProperties.getDb());
        RLock lock = this.redissonClient.getLock(lockKey);
        boolean acquired = lock.tryLock(30, 300, TimeUnit.SECONDS);
        return Boolean.TRUE.equals(acquired) ? lock : null;
    }

    private void releaseLock() {
        try {
            if (this.lock != null && this.lock.isHeldByCurrentThread() && this.lock.isLocked()) {
                this.lock.unlock();
                log.info("releaseLock success");
            } else {
                log.warn("releaseLock not exist");
            }
        } catch (Exception e) {
            log.error("releaseLock error", e);
        } finally {
            this.lock = null;
        }
    }

    @Override
    public String getCallbackName() {
        return "distributedLockCallback";
    }
}
```

---

**总结**

- Callback 接口用于在 Flyway 迁移生命周期的各个阶段插入自定义逻辑。
- 适合做日志、通知、校验、环境准备等自动化操作。
- 通过实现并注册 Callback，可以让 Flyway 迁移过程更加灵活和可控。

## 配置

### 项目配置

application.yml增加flyway配置

```yaml
spring:
  flyway:
    enabled: true
    baseline-on-migrate: true
    baseline-version: 0
    clean-disabled: true
    mixed: true
```

---

flyway参数详解：

| enabled | 是否启用flyway | true |
| --- | --- | --- |
| baseline-on-migrate | 是否在非空数据库上自动基线 | false |
| baseline-version | 基线版本号 | 1 |
| validate-on-migrate | 迁移前是否校验 | true |
| clean-disabled | 禁用 clean 命令 | false |
| validate-migration-naming | 校验迁移命名 | true |
| mixed | 是否允许混合 SQL/Java | false |

### POM
