### **多线程与多线程同步**

#### **1、lock-free和cas loop**

lock-free：这个词的含义是指一个代码属性，不是说完全不用锁，而是使用一定的手段，让其运行的程序不会因为抢到锁的线程中途无法释放锁时等待的线程无限期等待的设计理念，简单来说就是程序永远在执行

cas-loop：

在并发编程中，CAS（Compare-And-Swap）是一种用于实现无锁算法的原子操作。CAS 操作通过比较和交换来确保对共享变量的安全更新。CAS 循环通常用于实现自旋锁或无锁数据结构。

以下是一个简单的 CAS 循环示例，使用 Java 的 `AtomicInteger` 类来实现：

**示例代码**

```java
import java.util.concurrent.atomic.AtomicInteger;
//运行代码，你会看到类似以下的输出：
 
//Updated value to: 1
//Updated value to: 2
//Updated value to: 3
//...
//Updated value to: 10
//Final value: 10
public class CASLoopExample {
    public static void main(String[] args) {
        AtomicInteger atomicInteger = new AtomicInteger(0);
 
        // 目标值
        int targetValue = 10;
 
        // CAS 循环
        while (true) {
            int currentValue = atomicInteger.get();
            int newValue = currentValue + 1;
 
            // 尝试使用 CAS 更新值
            if (atomicInteger.compareAndSet(currentValue, newValue)) {
                System.out.println("Updated value to: " + newValue);
                if (newValue >= targetValue) {
                    break;
                }
            } else {
                // CAS 失败，继续循环
                System.out.println("CAS failed, retrying...");
            }
        }
 
        System.out.println("Final value: " + atomicInteger.get());
    }
}
```

---

通过这种方式，CAS 循环可以确保对共享变量的安全更新，并在并发环境中避免竞争条件。

#### **2、Fetch-and-add算法**

这两者的结合可以实现Fetch-and-add(FAA)算法，这个算法具体来说

Fetch-and-add (FAA) 算法是一种用于实现原子操作的算法，通常用于并发编程中。它通过硬件支持的原子操作来实现对共享变量的安全更新，避免了竞争条件。FAA 操作在执行时会获取变量的当前值，并将其增加一个指定的值，然后返回原始值。

**工作原理**

FAA 操作通常由硬件指令支持，例如在 x86 架构中，`LOCK XADD` 指令可以实现 FAA 操作。FAA 操作的步骤如下：

1. **获取当前值**：读取共享变量的当前值。
2. **增加指定值**：将共享变量增加一个指定的值。
3. **返回原始值**：返回共享变量的原始值。

**伪代码示例**

以下是一个简单的伪代码示例，展示了 FAA 操作的基本原理：

```java

function fetch_and_add(variable, increment):
    old_value = variable
    variable = variable + increment
    return old_value
```

---

**应用场景**

FAA 算法在多线程编程中非常有用，特别是在以下场景中：

1. **计数器**：实现线程安全的计数器。
2. **锁的实现**：用于实现自旋锁等同步机制。
3. **并发数据结构**：如无锁队列、无锁栈等。

**Java 示例**

在 Java 中，可以使用 `AtomicInteger` 类来实现 FAA 操作。以下是一个示例：

```java
import java.util.concurrent.atomic.AtomicInteger;
 
public class FetchAndAddExample {
    public static void main(String[] args) {
        AtomicInteger atomicInteger = new AtomicInteger(0);
 
        // 执行 FAA 操作
        int oldValue = atomicInteger.getAndAdd(5);
 
        System.out.println("Old Value: " + oldValue); // 输出: Old Value: 0
        System.out.println("New Value: " + atomicInteger.get()); // 输出: New Value: 5
    }
}
```

在这个示例中，`getAndAdd` 方法实现了 FAA 操作，它获取 `atomicInteger` 的当前值，将其增加 5，然后返回原始值。

**总结**

Fetch-and-add (FAA) 算法是一种用于实现原子操作的算法，通过硬件支持的原子指令来确保对共享变量的安全更新。它在并发编程中非常有用，广泛应用于计数器、锁的实现和并发数据结构等场景。

#### **3、程序序、内存序、乱序执行**

程序序：这里就是指代码的书写顺序（某些语言在编译层面也会指令重排序）

内存序：这里内存序对于单核cpu来说肯定等同于程序序，但是如果是多核cpu就要考虑内存屏障来完成共享资源的读取语义了，有些

乱序执行：在早期的cpu中采用的一般是有序执行，而现代cpu越来越多的采用乱序执行，原因是这样效率会更高；注意乱序执行是结果而不是原因，导致乱序执行的因素有两种：

- 在编译阶段的指令重排序
- 在CPU执行阶段的乱序执行，CPU 的超标量流水线、以及预测执行、Cache-Miss 等都有可能导致指令乱序执行

> 执行顺序如下：
> 
> - 指令获取，从代码节内存区域加载指令到 I-Cache
> - 译码
> - 分发指令到指令队列
> - 指令在指令队列中等待，一旦操作数就绪，指令就离开指令队列，那怕它之前的指令未被执行（乱序）；而对于有序来说会会在操作数有效的前提下并且操作数对应的指令执行完后，下一个指令才会执行
> - 指令被派往功能单元并被执行
> - 执行结果放入队列（Store Buffer），而不是直接写入 Cache；对于有序来说这一步和下一步合并为直接放入内存或者寄存器
> - **只有更早请求执行的指令结果写入 cache 后，指令执行结果才写入 Cache，通过对指令结果排序写入 cache，使得执行看起来是有序的**

#### **4、Store Buffer（存储缓存）和 Invalidate Queue（失效队列）**

**改前** 

```java
int a = 0; // 被CPU1 Cache
int b = 0; // 被CPU0 Cache
 
// CPU0执行
void x() {
    a = 1;
    b = 2;
}
 
// CPU1执行
void y() {
    while (b == 0);
    assert(a == 1);
}
```

两者都是增加CPU时间的利用率，但是都会带来同步问题；

- 存储缓存：每个core都会自己的缓存，可以理解为一个缓存写动作的队列，当修改的变量在cache中没有，就需要等待将这个变量从内存缓存到cache，这个等待时间不能浪费故有了store buffer，当没有命中cache时就先把这个操作放到buffer中，core就认为完成这个操作并且等到加载到cache后在做对应的处理，当缓存中有自己需要的值，则直接用或修改，当修改时会向别的核心广播；随后就带来一个问题即cache和buffer的数据不同步（单核多核都会）

> 写屏障：这个就保证了多核心下别的核心读到最新的值，即赋值a的变量一定发生在赋值b，不能让别的核心读取a的变量时还是旧值。如果没有写屏障就会发生，a变量在当前core没有时等待cache加载放入buffer中，转而去赋值在自己核心的b，这时如果别的核心在用变量a判断什么就会发生问题了。屏障就会在修改a的store buffer打标记，修改b时会检查store中是否还存在标记，存在则不会修改
> 
- 失效对列：同理如果核心修改了某个值，则需要将这个变量的旧值在其他核心给失效，就需要发送失效消息，发送之后需要等待其他核心返回失效ACK，所有回复之后才能修改，即也在浪费CPU时间，这时引入这个队列，将修改动作先放进去，并立即返回ACK

> 读屏障：解决如果队列中的修改动作被延迟处理了，读取某值的时候正好cache中存在并且是旧值，所以就有问题了，这个与写屏障同理，如果队列中存在打了标记的消息，会等待队列为空时再处理
> 

**改后**

```java
a = 1;
wmb();
b = 2;
 
while(b != 2) {};
rmb();
assert(a == 1);
```

#### **5、伪共享（false sharing）**

伪共享指的是多个线程去频繁读取同一个cache line的某些个变量，导致cpu cache（缓存一致性）频繁失效，性能下降的现象；在现代计算机中一个缓存行大概是64字节，位于缓存行中的数据哪怕只有一位改变也需要重新加载，在现代CPU的多核背景下，每个核修改共享数据都会发送广播让其其他核心同步修改，接收到消息的核心会把自己的cache标记为失效，并重新加载；当然对于同一缓存行，会在多个核心中设置为共享，当线程想要修改时必须获取缓存行的独占锁

> 对于下面代码f与fFast的区别实际上就是后者规避了伪共享的问题
> 
> - 因为 shm 被线程 1 和线程 2 这两个线程并发访问，所以 shm 的内存数据会以 Cache Line 粒度，被同时加载到 2 个 Core 的 Cache，因为被多核共享，所以该 Cache Line 被标注为 Shared 状态。
> - 假设线程 1 在 offset 为 64 的位置写入了一个 8 字节的数据（sizeof(long)），要修改一个状态为 Shared 的 Cache Line，Core1 会发送核间通信消息到 Core2，去拿到该 Cache Line 的独占权，在这之后，Core1 才能修改 Local Cache
> - 线程 1 执行完 shm_offset.fetch_add(sizeof(long)) 后，shm_offset 会增加到 72。
> - 这时候 Core2 上运行的线程 2 也会执行 shm_offset.fetch_add(sizeof(long))，它返回 72 并将 shm_offset 增加到 80。
> - 线程 2 接下来要修改 shm[72] 的内存位置，因为 shm[64] 和 shm[72] 在一个 Cache Line，而这个 Cache Line 又被置为 Invalidate，所以，它需要从内存里重新加载这一个 Cache Line，而在这之前，Core1 上的线程 1 需要把 Cache Line 冲刷到内存，这样线程 2 才能加载最新的数据。

**伪共享例子** 

```java
public class SharedMemoryExample {
    private static final int SHM_SIZE = 16 * 1024 * 1024; // 16M
    private static final ByteBuffer shm = ByteBuffer.allocate(SHM_SIZE);
    private static final AtomicInteger shmOffset = new AtomicInteger(0);
 
    //670ms
    public static void f() {
        while (true) {
            int off = shmOffset.getAndAdd(Long.BYTES);
            if (off >= SHM_SIZE) break;
            //慢在赋值这样，而不是因为fFast的步长变大从而线程竞争变少
            shm.putLong(off, off); // 赋值
        }
    }
 
    //99ms
    public static void fFast() {
        while (true) {
            final int INNER_LOOP = 16;
            int off = shmOffset.getAndAdd(Long.BYTES * INNER_LOOP);
            for (int j = 0; j < INNER_LOOP; ++j) {
                if (off >= SHM_SIZE) return;
                shm.putLong(off, j);
                off += Long.BYTES;
            }
        }
    }
 
    private static final AtomicInteger step = new AtomicInteger(0);
    private static final int THREAD_NUM = 2;
 
    public static void workThread() {
        final int LOOP_N = 10;
        for (int n = 1; n <= LOOP_N; ++n) {
            fFast();
            step.incrementAndGet();
            while (step.get() < n * THREAD_NUM) {}
            shmOffset.set(0);
        }
    }
 
    public static void main(String[] args) {
        long start = System.currentTimeMillis();
        Thread[] threads = new Thread[THREAD_NUM];
        for (int i = 0; i < THREAD_NUM; ++i) {
            threads[i] = new Thread(SharedMemoryExample::workThread);
            threads[i].start();
        }
        for (int i = 0; i < THREAD_NUM; ++i) {
            try {
                threads[i].join();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        long end = System.currentTimeMillis();
        System.out.println((end - start));
    }
}
```

解决方案：

大致的思路就是空间换时间，不要让多个变量落到一个缓存行中

- 使用填充（Padding）：充是通过在变量之间插入一些无用的数据，使得这些变量位于不同的缓存行中，从而避免伪共享的问题。
- `@Contended` 注解是 JDK 8 引入的一个注解，用于避免伪共享。需要注意的是，使用该注解需要在 JVM 启动时添加参数 `XX:-RestrictContended`。
- 将变量放入不同的数组元素中，因为数组元素通常会被分配到不同的缓存行中。
