# anki 模式

## 提交约定

基于当前提交历史，消息风格为简短英文描述。推荐后续采用以下格式：

- `add: <主题>` — 新增算法主题或题目
- `fix: <描述>` — 修正题解或代码错误
- `docs: <描述>` — 文档和配图更新

## 代码架构

```
/
├── README.md              # 仓库概述与目录导航
├── AGENTS.md              # Codex 指导文件
├── 算法/                   # 算法笔记根目录
│   └── <主题>/             # 主题目录（中文命名，如 动态规划）
│       ├── problems/       # 每题一个 md，供 build_from_mds.py 构建
│       ├── build_from_mds.py
│       └── image*.png      # 配图（image.png, image 1.png...）
├── 八股文/
│   └── <技术栈>/            # Java、Redis、MySQL、Linux 等
│       ├── *.md            # 原始长文笔记
│       ├── knowledge/      # 每个原文下拆出的知识点 md
│       └── build_*.py      # 技术栈或样板牌组构建脚本
└── 牌组/
    ├── 算法/               # 算法 APKG 输出
    └── 八股文/<技术栈>/     # 八股文 APKG 输出
```

## 工作流

### 新增算法主题

1. 在 `算法/` 下创建中文主题目录（如 `算法/回溯/`）
2. 创建笔记 `.md` 文件，按 H2 标题分题
3. 将配图放入同目录，命名为 `image.png`、`image N.png`
4. 更新 README.md 目录索引
5. `git add` 整个主题目录并提交

### 修改已有题解

1. 直接编辑对应 `.md` 文件中的代码块或文字
2. 如需替换配图，保持原文件名不变（或新增 `image N.png` 并更新引用）
3. 注意 markdown 图片引用中空格需转义为 `%20`

### 制作八股文牌组

1. 保留原始长文 `.md`，不要直接改造成卡片专用格式
2. 当处理整个目录/一级大类时，先做“5 年经验面试知识地图”，不要只扫描现有 md：列出该方向应覆盖的完整主题、当前已有内容、缺口和优先级
3. 缺口分级：`P0` = 5 年后端面试必备，缺失会明显露怯；`P1` = 深挖加分项；`P2` = 低频或专项扩展
4. 在 `八股文/<技术栈>/knowledge/<大类>/<知识点>/` 下拆知识点，每个知识点一个 `.md`；原文没有但 P0/P1 必备的知识点要新建文件夹补齐
5. 一个知识点通常由 4-6 张卡组成：概念、机制、边界、工程实践/对比追问、正确性审查，必要时加图示卡
6. 正确性审查是必做步骤：对版本差异、过时说法、实现细节和面试表述做显式修正
7. 先复用原文已有清晰配图；没有可用图且结构/流程/复杂对比难靠文字复习时，再用 `drawio-skill` 生成图
8. 输出 APKG 到 `牌组/八股文/<技术栈>/`，不要放在 `牌组/` 根目录

### 八股文验收标准

完成一个八股文目录前必须给出覆盖评估：

- 知识地图是否覆盖该方向 5 年经验常见深挖点
- 每个 P0 知识点是否至少有概念、机制、边界/失败模式、工程实践或追问、正确性审查
- 是否补齐了原文没有但面试必问的大类
- 是否能支撑面试官围绕该大类连续追问 10 分钟
- 剩余风险是什么，哪些 P1/P2 可以后续补

## 笔记格式规范

算法题每道题遵循：题干 → 配图 → 解法代码

- 题干和讲解使用中文
- 代码块标注为 Java
- 短配图放置在学习卡片关键步骤处

八股文知识点遵循：

- 每张卡只问一个明确问题，答案控制在面试能说出口的 3-6 个要点
- 优先写因果链、适用边界和常见误区，不复制原文长段落
- 对 JDK、MySQL、Redis、Spring、Kafka、Linux、Go 等版本敏感内容，要区分经典模型和现代版本行为
- 图只服务结构型、流程型和复杂对比型知识点；纯定义、纯列表、纯结论不额外配图
- 图片文件名尽量使用 ASCII，便于 Anki 媒体打包
