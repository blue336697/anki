pdfplumber — 表格结构理解引擎[](%E6%80%BB%E7%BB%93%2035b444514a3180e49aacd069787744b0.md)

**所有 30+ 个 Parser 全部依赖此包**。它解析 PDF 内部的字符和线段指令，提供三个层次的能力：

| **API** | **能力** | **原理** | **适用场景** |
| --- | --- | --- | --- |
| `page.find_tables()` | 检测表格位置（返回边界框列表） | 检测 PDF 中水平和垂直线段交叉形成的矩形区域 | 有边框 PDF 的表格定位 |
| `page.extract_tables()` | 按表格线提取数据（返回二维字符串数组） | 将 `find_tables()` 检测到的每个单元格内的文字提取并拼成行列结构 | 有行/列分割线的 PDF，如工行、建行、中行 |
| `page.extract_words()` | 提取所有词条 + 精确坐标 `{x0, x1, top, bottom, text}` | 按字符间距和阅读顺序将单字符聚合成”词”，保留页面坐标 | **无边框 PDF**，如招行——用表头关键词的 x 坐标作为列边界 |

两个工具函数： - `pdfplumber.utils.extract_text()` — 按阅读顺序提取纯文本，银行识别时提取首页文字做 `eval()` 匹配 - `pdfplumber.utils.extract_words()` — 带字体过滤参数的词条提取，工行 v2 用于按 `size=7.0` 筛选字符

**核心原理**：pdfplumber 的工作方式是”理解 PDF 的绘制指令”。PDF 中每个字符是一个 `(字体, 字号, x, y, 文本)` 元组，每条线是一个 `(x0, y0, x1, y1)` 元组。pdfplumber 将这些底层指令解析后，按 y 坐标聚合成行，按 x 坐标和线段判断列边界，最终输出结构化数据。

**两种策略的本质区别**：

`有边框 PDF（结构驱动）:
  find_tables() 检测线条交叉 → 确定单元格边界 → extract_tables() 填文字
  代表: ICBCParser, BOCParser, CCBParser, CEBParser...

无边框 PDF（坐标驱动）:
  extract_words() 获取每个词的坐标 → 表头关键词 x 坐标 = 列边界 → 数据词按 x0 落入哪个区间就归入哪列
  代表: CMBParserV2, 部分农商行 Parser`

fitz (PyMuPDF) — 底层 PDF 操控[](%E6%80%BB%E7%BB%93%2035b444514a3180e49aacd069787744b0.md)

**当 pdfplumber 不够用时的降级武器**。PyMuPDF 是 C 库 MuPDF 的 Python 绑定，操作 PDF 底层对象（页面、线、文本块），可以”写”PDF 而不仅仅是”读”。

| **用途** | **代码位置** | **具体操作** |
| --- | --- | --- |
| **重建 PDF（工行水印过滤）** | `icbc_parser.py:495-605` | `fitz.open()` 读原始 PDF → `fitz.open()` 建空白新 PDF → `new_page.insert_text(Point, text, fontsize=size)` 只把 7pt 字符写回 → 保存，相当于在物理层面重建了一个干净 PDF |
| **PDF 拆分** | `smart_pdf_parse_service.py:252-291` | `fitz.open(source)` → `split_doc.insert_pdf(source, from_page, to_page)` 按页数范围切分 → 保存为带 head/body/tail 标签的分片文件 |
| **无边框 PDF 补画表格线** | `abc/border_drawer.py`, `cgb/border_drawer.py`, `citic/border_drawer.py`, `gzbank/gzbank_v1.py`, `tjbank/tjbank_v1.py` | 先用 `extract_words()` 找列边界 → 用 `fitz.Point(x, y)` + `page.draw_line(p1, p2)` 在原 PDF 上补画竖线分隔线 → 保存后交给 pdfplumber `extract_tables()` 正常提取 |
| **获取字体元数据** | `icbc_parser.py:554`, `bocom_v2_1.py:345` | `page.extract_words(extra_attrs=["fontname", "size"])` 拿到每个字符的精确字号和字体名——这是工行”7pt = 真实数据”判断和部分银行字号分类的前提 |

**fitz 与 pdfplumber 的关系**：

`fitz 做前处理（补线/重建/拆分） → pdfplumber 做后续的表格提取

具体来说：
  - fitz.open() 打开 PDF，操作页面对象
  - fitz.Point / fitz.Rect / page.draw_line() 画线
  - page.insert_text() 写入文本
  - 保存后用 pdfplumber.open() 重新打开提取`

**典型组合流程**（以广发银行 cgb 为例）：

`fitz.open(原始PDF) + pdfplumber.open(原始PDF)
  → extract_words() 找出每列的 x 边界
  → fitz.draw_line() 在列边界位置画竖线
  → 保存画线后的 PDF
  → pdfplumber.open(画线PDF) → extract_tables() 正常提取`

5. 有没有真的因为理解偏差导致项目方案、排期或者交付结果出现问题，怎么纠正的
    1. 产品需求如果一开始不闭环，作为研发已经明显感受到风险，需求又不能停止，必须往前推，这时怎么推送，有没有写风险说明、拉评审、有样本数据说服、设计兼容方案
    2. 上线后问题怎么量化？
    3. 个人复盘是什么， 风险有没有前置

### 设计一个从AI建议到正式上线的完整流程

1、AI输出格式约束
2、自动校验：预发校验
3、样本回放：历史真实样本（正负）、线上未命中的样本、边界样本、误伤样本、黄金样本集
4、人工审核：自然语言可解释结论，
5、上线灰度：新旧链路同存怎么对比，
6、上线监控：怎么监控新旧链路上新命中的标签（命中表：命中数量、命中占比，新旧链路增减幅度），怎么判断合理还是误伤，询问客户响应太慢怎么办
7、一键回滚
